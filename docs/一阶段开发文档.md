### 2026-09-28 合成媒体复测与修复

本次新增 `scripts/generate-media.mjs`，生成两段可明显区分的 30fps/48kHz 视频、人声 WAV 和音乐 WAV，脚本同时产生 3.5 秒的 EDL。以其运行 `build` 后，在 `.run-data/phase1-acceptance/delivery-final/` 得到含源视频副本、OTIO、xmeml、三条 48kHz 双声道 WAV、SRT、EDL 和 manifest 的交付包；预览片为 `.run-data/phase1-acceptance/preview-final.mp4`。预览片经 FFprobe 计数 105 帧、30fps、3.5 秒，切点前后抽帧显示画面由色条切换为测试图案。XML 解析得到 2 个视频 clipitem 与 3 个音轨；OTIO JSON 有 2 个视频 Clip 和 3 个 Audio Track，所有媒体 URI 都解析到交付包内现存文件。人声 WAV 在声轨前后为静音、区间内有声；音乐在人声区间有 ducking。`npm test` 当前 11/11，通过真实媒体生成、缺失源拒绝、TTS 时长不符拒绝、帧/采样位置、媒体引用和音频能量回归。`npm run check`、`git diff --check` 通过。

### 框架接口与结构开放说明
七端口执行顺序与传递机制可继续复用；“完全满足所有真实适配器需求、无需增加结构”尚缺真实媒体证据，不能据此关闭接口设计。当前未实现占位模板 `adapters/pending.mjs` 仍保留。

## 1. 目标与边界

输入一份多轨 `edl.json` 和它引用的媒体，命令行产出可交给剪辑人员的目录：可编辑时间线（优先 `timeline.otio`、`edit.xml`）、分轨音频、字幕和 `delivery-manifest.json`。人工在 Premiere/Resolve 导入，核对切点、轨道、帧率、同步与素材可链接性。CLI 只负责文件交接，**不修改 Go 控制面的 SQLite 状态，不经 MCP 遥控剪辑软件，不将预览片当可编辑工程**。

最初交付的是执行骨架；后续占位适配器未形成真实媒体产物，本次已补 FFprobe 探测、帧/采样边界、带片段的 xmeml/OTIO、分轨 WAV 与音量 ducking。Premiere XML 导入与轨道结构已验收，精度校对按本页约定延后。使用 `pending.mjs` 时 `build` 仍必须明确失败，不能生成冒充成功的文件。

## 2. 现有代码与运行方式

| 路径 | 作用 |
| --- | --- |
| `workers/node/timeline-cli/src/edl.mjs` | 解析和基础结构校验；**不**探测媒体或判定帧精度。 |
| `workers/node/timeline-cli/src/contracts.d.ts` | 七个适配器端口及交付产物的类型契约。 |
| `workers/node/timeline-cli/src/pipeline.mjs` | 顺序执行、同步门禁、临时目录和发布 manifest。 |
| `workers/node/timeline-cli/src/cli.mjs` | `validate` / `build` 命令入口。 |
| `workers/node/timeline-cli/adapters/pending.mjs` | 明确报未实现的适配器模板；复制后逐项替换。 |
| `workers/node/timeline-cli/fixtures/minimal.edl.json` | 与原项目文档一致的最小结构样例；不包含真实视频。 |

在 `workers/node/timeline-cli` 目录运行（Node ≥22，无需安装依赖）：

```bash
node src/cli.mjs validate --edl fixtures/minimal.edl.json
node src/cli.mjs build --edl path/to/edl.json --output path/to/new-delivery --adapters path/to/real-adapters.mjs
npm test
npm run check
```

`validate` 只证明 JSON 基础结构有效，**不证明媒体存在、时间精确或可导入**。`build` 需要适配器模块导出 `createAdapters()`；当前 `pending.mjs` 会明确失败。输出目录必须尚不存在，成功后自动复制规范化的 `edl.json` 并生成 manifest。manifest 的 `ready_for_import_validation` 仅表示软件生成环节结束，仍需人工导入验收。失败时清理临时目录，不覆盖已有交付。适配器只能把产物写入传入的 `stagingDir`，并返回相对于它的路径。

## 3. 输入与接口约定

输入沿用项目文档 §8 的 `timeline`、`video`、`game_audio`、`voice`、`subtitle`、`music` 六段；时间值目前用秒表示。结构校验要求正帧率、正整数采样率、至少一段视频、有效入出区间和必要 ID/路径。未来若要支持 `30000/1001` 等分数帧率，应先明确并版本化输入契约，再更新校验、类型和 fixture；不能在内部用 `29.97` 浮点值累积帧位。

`createAdapters()` 返回七个具有 `run(context)` 方法的对象，按以下顺序调用：

1. `cuts`：解析剪辑顺序、源入出点、时间线起点和重叠/空隙策略；输出显式切点计划。约定源时间与目标时间的单位，保留原始 EDL 引用以供追溯。
2. `timebase`：探测源帧率、时间基、VFR/CFR 和音频采样率，选择精确有理数表示及转换策略；输出带帧号/采样号的规范时间。此处定义舍入规则，禁止逐片段浮点累计。
3. `tracks`：组装视频、游戏音、人声、音乐、字幕轨和轨道顺序；输出与具体导出库解耦的时间线中间表示。不能擅自把分轨混成单声道交付。
4. `sync`：校验切点帧对齐、轨道长度、源媒体范围、音画偏移、字幕与真实 TTS 时长；返回 `{ok, issues}`。`ok !== true` 时流水线停止，后续端口不得调用。
5. `formats`：从已校验的中间表示导出 `timeline.otio` 和 `edit.xml`（需要时再增 FCPXML），返回实际已写文件的 `{kind, path}` 列表。可评估 `@chatoctopus/timeline`，但须用真实样片证明格式兼容；不得假定库名等于已验证导入。
6. `audio`：导出游戏音、人声、音乐等可独立精修的分轨音频；记录轨名、采样率、声道和实际时长。每项都返回 `{kind, path}`，文件须真实存在。
7. `subtitles`：生成 SRT（可扩展 ASS），依据已确认的真实语音时长落点。每项都返回 `{kind, path}`，文件须真实存在。

`formats` / `audio` / `subtitles` 的产物都在 `stagingDir` 内；manifest 由框架写。导出适配器不得自报同步已通过，必须消费 `sync` 的检验结果。所有来源媒体路径应相对 `edl.json` 所在目录解析；交付包内使用可迁移的相对引用或明确包含媒体副本及校验值。路径穿越、软链接越界、重复名称以及输出目录覆盖均不得通过。

## 4. 建议的补全顺序与每步验收

| 顺序 | 任务 | 最小验收 |
| --- | --- | --- |
| 1 | 建立一段有画面、原声、TTS、字幕、BGM 的短样片及预期帧表 | 媒体来源、帧率、采样率、期望入出点和轨道位置可人工核对；fixture 不含隐私或大文件入 Git。 |
| 2 | 完成 `cuts`、`timebase`、`tracks` | 单元测试覆盖非整数帧率、VFR 输入策略、边界舍入、空隙/重叠、轨道顺序；中间表示可序列化审查。 |
| 3 | 完成 `sync` | 故意错位、越界、TTS 时长不符时拒绝发布；正确样片通过。 |
| 4 | 完成 OTIO/XML 与分轨音频/SRT 导出 | 产物存在、路径可解析、再读回得到相同片段数/顺序/切点；记录每种格式不能表达的特性。 |
| 5 | 人工导入 Premiere 和/或 Resolve | 软件内可编辑，视频切点、各轨、字幕和音画同步符合预期；保存导入结果和差异记录。此项不能由自动测试代替。 |

开发时优先实现**一条样片的端到端路径**，再扩展复杂素材。具体帧率、变速、转场和 ducking 等规则应在真实样片与目标软件中确定，并以 fixture + 回归测试固定；发现格式能力缺口时在 manifest 标明限制或拒绝交付，不能静默丢轨。

## 5. 交付门禁与集成边界

- 自动门禁：`npm test`、`npm run check`、EDL 结构校验、端口顺序、失败不发布、路径安全；适配器补全后增加文件读回、音频探测及帧/采样误差测试。
- 人工门禁：Premiere XML 导入及轨道结构已验证；精确切点、音画、ducking、字幕与 Resolve 按用户决定延后校对。manifest 的 `ready_for_import_validation` 仍不代表这些项目已验收。
- 与 Go 控制面集成应在 CLI 独立验收后开展：Go 只提交任务、记录产物路径及状态；不在 Go handler 复制时间线业务规则。失败与重试必须保留原 EDL 和日志，禁止将半成品标记为成功。
- 仓库原本忽略 `docs/`；本次仅为 `docs/一阶段开发文档.md` 加入例外，使这份实现交接文档在 Git 工作树中可见。其他设计文档仍按原规则忽略；后续需要由维护者自行决定是否提交本文。
