## 1. 需要带齐的条件

候选代码必须包含当前未提交的 MP4 实现与修复，并对照 [源码索引](后续模块交接/v1/source-baseline.json) 核验。索引本身不能代替源码交付；旧 `.run-data` 的媒体/截图可能已按限额清理，以现存文件与新索引为准。

用户此前指定原录屏：`E:\Data\Videos\Rec\2026-06-07 04-10-16.mkv`。本次只核对文件存在与大小 140505420 字节，没有转码或外发。历史探测约 98.545 秒、60 fps、五条音轨，作为准备参考；执行者重新探测并试听，不照搬旧音轨选择。原文件只读保留。

开跑条件：实际视觉模型、实际解说模型、可用环境变量凭证、固定 configured profile revision/hash、针对该预设的素材外发许可、可实际发声的中文 SAPI 声音、FFmpeg/ffprobe/中文字幕字体，以及操作者可用的 Premiere。现有服务商协议适配器已经存在，只有实际不兼容时才安排适配修复。

未知或未配置项写入 blocked 清单；不能用 builtin 模板、mock 返回或测试音替代正式内容/声音。无人可进行判断时，自动执行结果保留，人工状态 pending。

## 2. 目录与索引

验收会话统一放入 `.run-data/real-business-acceptance/<session_id>/`，包括 source-index.json、build-index.json、profile-binding.json、source-probe.json、evidence-index.json、results.json 和人工文字报告。运行输出是可清理的测试产物，源码、固定样本、脚本及文字/JSON 结果保留。

采用 [acceptance-run.template.json](后续模块交接/v1/acceptance-run.template.json)。至少记录：候选 HEAD + 工作区索引哈希；实际启动构建和 WebUI 产物哈希；源录屏与所选轨/区间；profile revision/hash；asset/run/导出 revision/manifest；preview ID/input/preset/MP4 hash；实际软件版本；每个检查的来源、操作者、时点和证据。

源码索引序列化 UTF-8，按相对路径排序，记录精确文件字节 SHA-256。索引文件自身 SHA-256 用作候选指纹；不要把最终 JSON 的 key 重排误当同一个文件字节。目录外证据先复制到会话的受控证据路径并计算哈希，或仅登记已受控业务文件引用；不接收任意浏览器传入的绝对路径。

## 3. 实际执行顺序

| 步骤 | 操作 | 判定与记录 |
|---|---|---|
| A01 | 固定候选、构建、依赖、模型/声音和 profile，保存明确许可 | 缺项必须可定位；配置与 Worker 指纹一致，无凭证泄漏 |
| A02 | 从已有启动脚本启动独立服务会话 | 记录 URL、PID+路径+启动时间和日志；不占用或停止用户其他会话 |
| A03 | 受控登记原录屏，探测并试听各音轨，选择短片/候选 | 保存轨道索引、源时间和选择修订；不默认混合五条音轨 |
| A04 | prepared-preflight 后启动 configured 工作流，真实识别/排序 | 检查抽帧证据与游戏画面一致，标签和排序可追溯；实际模型版本有记录 |
| A05 | 场景退回/修改/确认，生成解说，编辑后批准 | 中文事实忠实，不凭空解释画面；改稿使旧批准失效，重新批准固定草稿 |
| A06 | 实际 TTS、字幕、混音、导出 | 试听中文声音、字幕起止、游戏声同步、音乐压低与恢复；超长语音不可静默截断 |
| A07 | 通过真实 WebUI 创建 MP4，播放/seek/下载 | 绑定当前导出 revision，画面切点/黑场/字幕和三轨一致；记录精确异常时间 |
| A08 | 下载该 run 的 ZIP，导入 Premiere，单独导入 SRT | 记录软件版本、轨道、FPS、切点、实际播放及可编辑性 |
| A09 | 移动测试交付包并重新链接媒体 | 副本新位置可继续播放与编辑；原包仍保留，正式业务包不移动 |
| A10 | 改稿或改选段重跑；在隔离资产做取消/重试 | 旧批准/交付/预览保持版本身份；当前节目源无旧 MP4 残留；运输重试不重复创建 |
| A11 | 宽窄窗、键盘、SSE 断开重连后快照 | 状态不丢、按钮可达、合法播放不被普通刷新中断 |
| A12 | 停止本次会话，重启后访问历史结果 | 自有媒体子进程退出，数据与 JSON/文字证据可恢复；统计占用 |

先用可重复短选段贯通，再验证完整代表样本。每次扩大范围先计算输入副本、WAV、输出、缓存和截图预算；无法在 500 MiB 内安全完成的测试标 blocked，不能偷偷移到不统计的目录。

## 4. 现有接口复用

实际启动示例使用现有入口，所有文件路径必须替换为已准备好的实际文件：

```powershell
pwsh -NoProfile -File 'E:\AI\Video Auto Cut\scripts\Start-LocalPipeline.ps1' `
  -ProfileFile '<实际profile文件的绝对路径>' `
  -IngestRootsFile '<受控录屏根配置文件的绝对路径>' `
  -Port 8806
```

该脚本要求新会话 profile revision 为 1；不要修改现有业务 profile 历史去满足示例。端口占用时另选空闲端口。外部模型权限使用现有 profile consent 流程；启动脚本不会代替人批准素材外发。

交付/预览使用现有 `/api/workflows/{run}/delivery.zip`、`POST/GET /api/workflows/{run}/previews`、`GET /api/previews/{id}` 和受控 files 路由。人工记录沿用 `GET/POST /api/workflows/{run}/acceptance`，POST 包含 `expected_version`、六个既有 check_item 之一、passed/failed 和 note；冲突先重读，不盲重试旧版本。

现有六个键：content_fidelity、evidence_trace、browser、premiere、cuts_fps、subtitle_audio_duck。未检查的项目不 POST；在旁路证据文件中保留 pending/blocked。自动浏览器或 FFmpeg 通过不能自动写入人工 passed。MP4 判断证据单独绑定 preview/input/preset/output 哈希，避免同一导出修订下不同预览尝试混用结论。

## 5. 缺陷闭环
