# 服务商通用接入（2026-10-02）

本次增加 OpenAI、Anthropic、Google Gemini 三种原生 API 格式，接入实际识别/解说 Worker，并提供模型发现、模型选择和连接测试。保留原有自定义内容接口；没有新增模型下载、自动批准或真实录屏外发。实际服务商链接与 API key 尚待用户提供，真实服务商兼容性和内容效果仍待验。

## 使用入口

在“处理预设与运行准备”中选择“已配置模型”，分别为画面识别和中文解说设置 API 格式、基础地址、模型 ID 与运行凭证环境变量名。两种任务可以使用不同的格式、端点和模型。

点击“发现模型”读取列表后选择模型，也可以手动填写未列出的模型 ID。“测试连接”发起实际生成请求；画面识别使用固定合成 PNG，解说使用固定文字，可能产生少量费用。成功表示鉴权、所选请求格式与生成响应可用，不等于模型内容准确。

测试 key 在密码框中填写，仅存在于当前页面内存和当前请求，不写入预设、数据库审计、浏览器存储或查询缓存。留空时使用控制面启动环境中的凭证变量。改变协议格式、地址或凭证变量会清除测试 key；配置或模型改变后旧测试结果失效，在途请求取消，迟到结果不会覆盖当前状态。

正式 Worker 继续从启动环境读取凭证。保存预设记录变量名，不保存 key；浏览器中的临时测试 key 不会自动安装到 Worker。启动新部署前设置所选变量，使用实际 profile 文件启动 `scripts/Start-LocalPipeline.ps1`。现有 Worker 配置固定原版，新预设需要匹配配置的 Worker；检查运行条件会拒绝错配。真实媒体外发仍需要具体预设版本及指纹的许可。

## 协议与配置

Provider 增加可选 `api_format`：`openai`、`anthropic`、`gemini`。省略该字段仍表示原有 `/vision`、`/narration` 自定义契约；Go JSON omitempty 保持旧预设的规范字节和指纹算法不变，新字段纳入新预设指纹。数据库无需迁移。

| 格式 | 默认基础地址 | 生成接口 | 模型列表 | 鉴权 |
|---|---|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `/chat/completions` | `/models` | Bearer |
| Anthropic | `https://api.anthropic.com/v1` | `/messages` | `/models` | x-api-key，anthropic-version |
| Gemini | `https://generativelanguage.googleapis.com/v1beta` | `/models/{model}:generateContent` | `/models` | x-goog-api-key |

服务商兼容地址可以替换默认值。自定义路径前缀原样保留，例如 `https://gateway.example/api/v1`；仅域名根地址自动补 `/v1` 或 Gemini `/v1beta`。OpenAI/Anthropic 也接受以生成接口结尾的地址并移除该后缀。Gemini 接受模型列表的 `models/` 前缀，发送前标准化 ID；本功能面向 Gemini API key 接口，不包含 Vertex AI OAuth。

识别请求包含校验过哈希的实际取样 JPEG；OpenAI 使用 image_url/data URL，Anthropic 使用 base64 image source，Gemini 使用 inlineData。解说请求采用已审查的场景标签和时间窗。模型文本转换为原有 scenes/narrations 契约，仍验证片段身份、证据、排序、时间窗和文本长度；模型不能授予批准。截断、拒绝、安全阻断、空输出或无效结构均失败，不能静默回退 builtin。

OpenAI 默认使用 `max_completion_tokens`。只有 HTTP 400 明确指向该参数被拒绝时，才在原请求预算内尝试一次 `max_tokens`；两次保持相同上限，不重复已成功的生成。Anthropic 使用 max_tokens，Gemini 使用 maxOutputTokens。

- `configs/providers/profile.anthropic.example.json`
- `configs/providers/profile.gemini.example.json`

## 诊断接口及边界

POST `/api/providers/models` 和 POST `/api/providers/test` 接收 `{provider, api_key?}`，由现有人类同源/loopback JSON 入口保护，不开放为 Agent MCP 工具。诊断可在未保存预设时使用，但不会保存预设、绑定任务或授予媒体外发许可。

响应包含 `ok/code/message/latency_ms`；发现模型另有 `models[{id,name}]` 和可选 truncated。服务商错误通过诊断结果呈现，字段结构错误仍使用现有 HTTP 错误信封；凭证及服务商原始错误文本不回传。鉴权失败、404、限流/额度、超时、重定向、非 JSON、空/截断输出分别提示。

每次 HTTP 请求最多 12 秒，整个诊断最多 30 秒，响应最多 1 MiB；不跟随重定向。模型列表最多 10 页、500 个模型，重复游标失败，达到上限明确标为部分结果。Anthropic 使用 after_id，Gemini 使用 pageToken；Gemini 列表排除仅支持 embedding 的模型。不从名称猜测其他模型是否支持图片，使用连接测试验证。返回的模型 ID/显示名有长度限制、去重，并避免回传当前凭证。

Worker HTTP 超时默认 30 秒，拒绝重定向，仍采用现有图片/响应预算。连接测试和模型发现不是运行准备的自动动作，打开页面、加载/保存预设、普通预检都不会自动调用收费模型。

人工验收修复：真实 Step Plan 多图识别首次在 30 秒读取期限处超时。Worker 增加 `provider_timeout_seconds`（有限数字 1–300 秒，默认仍为 30），固定预设映射保留该本地运输参数；帧取样预算仍由预设控制，互不替代。`Start-LocalPipeline.ps1 -ProviderTimeoutSeconds 120` 可设置正式 Worker 的等待期限。本轮验收采用 120 秒，保留同版媒体、预设指纹和既有外发许可；需要重启 Worker 后才生效。修复回归：preparation/provider 共 10 项及 worker/content 共 39 项通过，真实失败阶段重试结果另记在人工验收记录中。
