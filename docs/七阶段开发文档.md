## 1. 目标与阶段范围

F7-01/F7-02 的补充契约见 [执行隔离与断点恢复修复方案](七阶段执行隔离与断点恢复修复方案.md)。停止交接、启动重连、同/跨执行接管、提交状态查询和 UI 契约已修复，T19 恢复型合成 E2E 与规定报告已交付；工程问题关闭。执行协议 2 / vac-ingester/3，控制面与 ingester 需一起更新，旧普通任务兼容。

把项目入口从“操作者预先准备 EDL 和受控媒体包”推进到“直接登记本机游戏录屏，生成可审查的初始 EDL，再进入既有内容加工链路”。

本阶段必须实现：

1. 本地录屏导入：受控根目录内的文件登记、后台复制与完整哈希、独立输入快照；原文件保留。
2. 媒体探测：容器、视频流、时长、分辨率、帧率/时间基准、音频流及采样率；多音轨展示和明确选择。
3. 长录屏候选分段：有预算的局部场景变化分析、确定性候选切点、长度控制、源时间追溯；不把画面变化等同于游戏关卡或高光识别。
4. 初始 EDL 审查：选择片段、修改边界、确认音轨/输出帧率，再生成可用的标准化媒体与 EDL。
5. 接入既有流程：使用第六阶段固定预设启动识别、排序、解说、审查、语音、字幕、混音和交付。
6. 长任务运行：真实进度、取消、租约回收、失败重试、可验证断点、重启恢复和不可变来源。

本阶段不实现模型安装、自动下载、通用时间线编辑器、Premiere 实时遥控、跨资产批处理、安装器或发行升级。第七阶段也不承诺完全自动判定游戏内容和最优剪辑节奏；内容判断由既有视觉/解说适配器与审查流程承担。

验收时机后推不取消产品里的分段选择、场景确认和旁白批准。工程脚本可以对合成 fixture 执行这些操作，不得给真实内容批量代填通过。

## 3. 架构与状态所有权

```text
WebUI / 本地导入脚本
    │ 选择已配置根目录和相对文件；人类决定治理范围
    ▼
Go service + SQLite（唯一状态所有者）
    │ 创建 source / ingest run / 固定策略与任务绑定
    ▼
现有任务队列：media_probe → segment → 分段审查 → media_prepare
    │              新本地 ingester 角色，经鉴权 MCP 执行
    ▼
delivery_root 下的不可变原始快照、分段结果、选中短片和初始 EDL
    │ Go 校验并原子登记准备完成
    ▼
第六阶段 prepared-preflight / prepared-workflows
    ▼
既有识别 → 审查 → 排序/解说 → 审查 → 语音/字幕/混音/导出
```

第一版限定控制面与 ingester 同机；不通过 MCP 把大视频传给远程执行器。REST/MCP handler 只解码、鉴权、调用 service 和写响应，不做长时间复制、扫描或转码。FFmpeg 参数由受控策略生成，通过参数数组执行；不接收 shell、任意滤镜脚本或输出绝对路径。

建议新增 `control-plane/internal/ingest` 契约、`service/ingest*.go`、`store/ingest.go`、`api/ingest.go`、Python `vac_worker/ingest/`，以及 WebUI 导入/分段面板。文件名允许按仓库组织调整，业务边界不变。本轮不创建这些代码文件。

### 3.1 导入阶段状态

ingest run 状态为 `queued / processing / awaiting_review / ready / failed / cancelled`；`stage` 为 `probe / segment / segment_review / prepare / ready`。任务本身继续使用现有 Task 状态，run 状态由 service 根据任务与审查结果推进。

- 登记原始文件后建立原始输入资产；`input_kind=raw_recording`，此时没有可运行 EDL。
- media_probe 同时完成受控复制、哈希与探测；结果成功后停止在 `awaiting_review/probe`，由人选择视频流、游戏音轨和处理范围。
- 人提交固定分析计划后创建 segment 任务，成功后停在 `awaiting_review/segment_review`。
- 确认片段选择后创建 media_prepare；包验证与登记成功才进入 `ready`，资产 `input_kind` 改为 `edl_package`，保留 source/ingest 来源。
- ready 仅表示输入准备成功，不表示内容审查、导出或人工验收通过；不得自动启动外部模型。
- 新计划或重新准备生成新 run/revision，不改写已被内容流程消费的输入包。每个资产只允许一个活动导入 run；有活动内容流程时拒绝覆盖资产输入。

人类选择和审批走 REST。ingester 不能修改可见性、锁定、角色、片段确认或模型许可。取消、锁定、隐藏及角色撤回对领取、检查点和最终登记都立即生效；过时产物只能隔离留存，不能推进新状态。

## 4. 本地文件入口与来源

### 4.1 允许的目录

控制面启动配置新增 `ingest_roots`：稳定 root_id 到管理员明确配置的绝对目录。WebUI 只提交 root_id 和相对文件名，不浏览任意磁盘、不接受 UNC/URL/任意绝对路径。返回 UI 的目录列表只含 ID 与展示名称，不包含真实绝对根目录。

ingester 启动配置有同一 root_id 映射；能力报告与任务绑定根目录配置指纹，映射不一致时不能领取。服务端先解析和校验路径，Worker 打开时再检查归属、文件类型及来源标记。拒绝目录、越界、符号链接/junction 逃逸、设备路径及正在变化的输入。

提供 `scripts/Import-Recording.ps1 -Path <本机绝对路径>` 作为便捷入口：仅把路径转换成已配置根目录的相对路径并调用人类接口，不能绕过根目录限制；日志不打印凭证。浏览器第一版使用“根目录 + 相对文件名”，不伪装成能取得本机完整路径的文件选择器。浏览器大文件上传不在首版范围。

人登记后默认资产不可见；“允许本地导入处理”是明确的人类治理动作，只允许 ingester。准备完成后再由人允许 recognizer/narrator/exporter，并选择模型预设。不能暗中把新录屏暴露给所有角色或配置模型外发。

### 4.2 原始快照与大文件复制

原始文件始终保留。media_probe 流式复制到本次受控暂存目录，同时计算 SHA-256；不会把整文件读入内存。复制前后校验长度/文件标记，来源变化时失败；不会把仍在录制的文件登记为稳定快照。

导入文件、探测 JSON、receipt 写完再发布为不可变源目录；状态登记和审计在业务事务中完成。数据库不在长复制期间持有写事务。失败或未登记输出留在本次恢复目录，自动扫描只处理本系统记录的 owned 路径，不清理用户录屏或历史交付。

保留 source_id、原始长度、SHA-256、源引用摘要、导入版本、探测方法版本、复制字节进度和受控快照引用。源路径不能被传给视觉或解说服务；已有内容 Worker 只读取选中短片。

复制支持分块检查点；恢复时核对来源标记与已完成块哈希，先校验暂存文件再续写。原文件变化或块校验失败必须重新导入或失败提示。全文件 SHA-256 在完成时由字节流计算；分块哈希列表不能冒充全文件哈希。

原始快照与候选数据不进入每一个内容修订或最终 ZIP。最终包包含必要的选中媒体、初始 EDL、source-map 和去敏来源摘要；不能让一段小时级录屏在多个任务中重复复制几十份。

## 5. 媒体探测、音轨与时间基准

探测结果至少记录：容器、时长和大小；每个流的绝对 stream index/type/codec/disposition；视频尺寸、旋转、time_base、avg_frame_rate/r_frame_rate、起始 PTS；音频采样率、声道、语言/标题和起始 PTS。缺字段标为 unknown，不能以帧率字段不相等直接断言 VFR。

第一版支持可解码的 MKV/MP4/MOV；至少自动验证 H.264 + AAC/PCM 组合。扩展名不作为有效性证明。损坏、无视频或不支持的输入明确失败；HDR/特殊色彩及多视频流不自动忽略，要求选流并记录能力限制。

处理计划由人明确选择一个视频流、一个游戏音频流或显式无音频。多音频时显示列表；不默认混合全部音轨，不把第一个流假定为游戏音。无音频允许 `game_audio=[]`，不生成假声轨；实际字幕和新旁白仍由后续链路生成。

内部时间使用整数 tick/us 和有理数帧率，记录源 PTS 与归一化原点。选择视频流的首个有效呈现时间作为源时间零点，各音轨都按同一原点映射；保留相对偏移，不能分别把音频/视频首帧都强制清零。

首版输出 CFR 30 或 60 fps、48 kHz 游戏音，目标由计划固定。源 30000/1001、60000/1001 与 VFR 的原始时间基准保留在来源映射里；转换按实际 PTS 取帧，不能使用 `帧号/名义帧率` 推断所有源时间。CFR 转换记录重复/丢帧和起止误差。其他目标帧率待共享时间基准与 Premiere 自动测量通过后再扩展。

准备短片必须精确落到选定时间边界；不能仅 keyframe stream-copy 后宣称任意切点精确。音视频使用共同变换；对真实存在的静音偏移可显式填充/裁剪并记录，不能用无声结果替代应有语音或忽略不同流起始偏移。

自动校验每段解码成功、实测帧数/时长/音频样本与计划一致，视频边界误差不超过一个目标帧；样本级音频误差与帧量化误差分别报告。超过容差不得发布 ready 包。

## 6. 候选切点与片段审查

### 6.1 算法首版

使用有版本的本地场景变化检测器，低分辨率分析画面，按块扫描并保留块边界重叠；计算候选分数、源时间、方法版本与检测配置。算法不调用外部模型。

候选切点加上处理区间首尾，去重和排序后形成不重叠、无空洞的候选片段。合并过短片段；过长片段按确定性规则分割并标注 `duration_limit`。无场景变化时依靠长度控制仍产生合法候选；淡入淡出/闪光/菜单切换只是切点证据，不能自动写成语义关卡结论。

候选结果覆盖请求的分析区间，但只被选中的片段进入输出时间线。候选表支持选择/排除、修改边界、相邻合并/拆分；第一版输出按源顺序拼接，后续 sort 负责语义排序。排序和入出点改变必须产生新计划版本。

审查界面展示源时间、长度、方法/分数、受限数量缩略图及明确的处理范围；准备完成后可以预览/试听标准化短片。不要求浏览器原生播放所有 MKV，也不伪装无法播放的原文件为成功预览。

### 6.2 预算与降级

媒体策略独立于第六阶段内容 Profile，保存 schema/version、参数和 SHA-256，固定在 ingest run。建议首版运行默认上限如下；实现者调整时同步示例、校验与故障测试，不能静默取消上限。

| 项目 | 首版建议 |
|---|---|
| 单源大小/时长 | 64 GiB / 6 小时，可配置更小；超限拒绝并提示 |
| 选定分析区间 | 源范围内，支持短区间起步；未指定为完整源范围 |
| 分析块/重叠 | 60 秒 / 1 秒；重叠结果不重复计入切点 |
| 分析尺寸 | 最长边不超过 640；不缓存全量解码帧 |
| 单块期限/总扫描期限 | 120 秒 / 2 小时，分别有取消和超时 |
| 候选数/缩略图预算 | 2048 / 128，分页显示；超限明确阻断或生成新参数计划重跑 |
| 已选片段/输出长度 | 最多 48 段 / 默认最多 15 分钟；超过要求修改选择 |
| 元数据/manifest | 检测数据 JSON ≤16 MiB；标准 delivery manifest 仍 ≤1 MiB、≤512 文件 |
| 存储 | 启动前估算原始快照、选中短片、暂存和保留修订；执行期间持续检查剩余空间和本次输出配额 |

检测阈值、最短/最长片段和选定范围在结构化策略中显式记录。达到期限、候选数或空间上限时不返回截断的“完整成功”；部分扫描只允许保存 checkpoint，UI 显示已完成范围和剩余项。

第六阶段 `sampling.max_frames` 不被自动提高。新入口为每个已选片段至少安排一张视觉证据，再在剩余预算内确定性分配额外帧，每段仍最多 5 张。选择数大于全任务帧数时阻断启动，并提示减少片段或显式发布更大预算的预设。新路径的配额策略须记录版本，旧输入保持原有采样行为。时间/总字节预算继续全任务共享，不得拆成多个请求绕过。

## 7. 初始 EDL、媒体包与来源契约

media_prepare 只转码已选片段。每段 MP4 为独立、可解码的 CFR 短片，包含所选游戏音频（若有）；全片起点为 0，片段输出时长按整数帧定义。避免把整个原始长视频再次装入短片包。

包至少包含：

```text
edl.json                         # 兼容现有必需的五个轨道数组
delivery-manifest.json          # schema_version=1，受控相对路径
media/segment_001.mp4 ...        # 仅已选标准化片段
source-map.json                 # 每段源时间/PTS → 输出帧/样本映射
ingest-provenance.json          # 去敏 source/run/计划/方法/媒体指纹
worker-receipt.json             # 任务、领取执行标识、策略和输入身份
```

EDL 示例（30 fps、两个 4 秒片段）：

```json
{
  "timeline": {"fps": 30, "sample_rate": 48000},
  "video": [
    {"src": "media/segment_001.mp4", "in": 0, "out": 4, "timeline_in": 0},
    {"src": "media/segment_002.mp4", "in": 0, "out": 4, "timeline_in": 4}
  ],
  "game_audio": [
    {"src": "media/segment_001.mp4", "in": 0, "out": 4, "timeline_in": 0},
    {"src": "media/segment_002.mp4", "in": 0, "out": 4, "timeline_in": 4}
  ],
  "voice": [], "subtitle": [], "music": []
}
```

source-map 使用稳定 segment_id、source_id/hash、原视频/音轨 stream index、原始 time_base/PTS、源时间范围、输出 fps、输出帧数/音频样本数、转换误差和标准化媒体 SHA。EDL 可以增加向后兼容的 `ingest` 去敏元数据，不能替换旧字段或让旧 Worker 必须解释新原始路径。

source-map 与 provenance 必须经过固定修订、排序、语音/字幕/混音及 Node 导出传递到最终 ZIP。排序改变 timeline_in 后按 segment_id 更新输出映射，仍保留原录屏源范围；不能根据数组序号猜来源。模型请求只使用必要的片段证据/内容，不携带原始根目录与录屏路径。

## 8. 存储、任务与恢复契约

迁移使用实现时下一可用编号；当前已有 0001–0008，若无其他新增可使用 `0009_media_ingest.sql`。不要改旧迁移，不以硬编码历史测试回避新表。

| 表/扩展 | 关键字段与约束 |
|---|---|
| recording_sources | source_id、asset_id、root_id/受限源引用、源标记、snapshot_ref、sha256、大小、探测版本；源快照发布后不可变 |
| ingest_runs | run_id、asset_id/source_id、state/stage、version、当前计划修订、当前任务、错误摘要；每资产最多一个活动 run |
| ingest_plan_revisions | run_id/revision、schema、canonical_json、sha256、actor；包含流选择、范围、检测预算、片段选择和目标参数，修订只追加 |
| ingest_task_bindings | task_id、run/plan/input 指纹、当前 execution_id；每次重新领取刷新执行标识 |
| ingest_checkpoints | task/输入/策略、sequence、执行标识、已完成块/片段、受控文件及哈希；只引用可验证成果 |
| ingest_worker_capabilities | 已鉴权 Agent、根目录配置摘要、工具/操作能力、服务器 observed/expires；不与模型 profile 指纹混用 |
| Asset 可选字段 | input_kind、ingest_run_id；旧资产缺省为 edl_package，不影响历史接口 |

media_probe / segment / media_prepare 的 AgentRole 均为新本地 `ingester`，通过现有 claim/progress/heartbeat/fail 与 queue 处理。新类型不能出现在普通任意任务表单并绕过导入计划；创建它们须有合法 ingest task binding。

每次领取生成 execution_id；`get_task_input` 返回当前身份，检查点及提交必须匹配。不能仅使用 agent_id/task_id 判断同一执行器重领后的结果是否新鲜。重新领取会失效旧执行标识，即使 Agent ID 相同，旧子进程的迟到结果也不能提交。

结果登记采用“先发布本次 owned 目录，再事务登记结果/任务/下一阶段/审计/幂等”。发布后断线可根据 receipt 恢复登记；内容相同重复请求返回相同结果，不同内容复用键冲突。登记前重新核验租约、治理、执行标识、run/计划版本和受控文件。大视频全量复制/哈希在执行步骤完成，handler 不反复同步读取整段录屏。

检查点仅在块/片段文件写完并核验后登记；中断的最后一块废弃或重做。初版不要求恢复 FFmpeg 内部编码状态，但必须能跳过验证通过的已完成分析块与已完成短片；禁止把“重跑整个长文件”描述为断点恢复。

进度分别显示复制字节、扫描源时间/总范围、已完成片段/总段数、当前步骤与排队状态。无依据时不展示预计剩余时间；有分母时进度不倒退，100% 只在实际成功登记后显示。取消/超时要结束本次子进程树并等待退出，保留可验证检查点，不按通用进程名结束软件。

## 9. REST / MCP / SSE 开发契约

以下为开发接口契约，实际实现和验收状态另见实施报告与验收记录。沿用 loopback、同源、现有 JSON 错误与人类 actor 规则。请求拒绝未知字段，分页和请求体有界；不得用 HTTP 200 和空列表占位冒充功能完成。

| 方法与路径 | 请求/响应要点 |
|---|---|
| GET `/api/ingest-roots` | 返回已配置目录的 ID/名称；无绝对路径 |
| POST `/api/recordings` | `{asset_id, root_id, relative_path, idempotency_key}`；快速登记 source/原始资产，不复制视频；返回 source 与 source_version |
| POST `/api/assets/{id}/ingest-runs` | `{source_id, expected_source_version, idempotency_key}`；已有 ingester 治理许可才排 media_probe；202 + run/task |
| GET `/api/assets/{id}/ingest-runs` | run 历史，limit 1–50 / offset；旧 run 只读 |
| GET `/api/ingest-runs/{run}` | run、plan/source 身份、步骤任务、进度和去敏探测结果 |
| GET `/api/ingest-runs/{run}/segments` | 有界候选分页；stable segment_id、源范围、分数、方法与缩略图 key |
| POST `/api/ingest-runs/{run}/analysis-plans` | `{expected_version, video_stream_index, game_audio_stream_index|null, source_range_us, segmentation, idempotency_key}`；固定新版计划并排 segment |
| POST `/api/ingest-runs/{run}/selection-revisions` | `{expected_version, base_plan_revision, selected_segments, output, idempotency_key}`；验证范围/重叠/预算，保存新的不可变选择修订，不转码 |
| POST `/api/ingest-runs/{run}/prepare` | `{expected_version, plan_revision, profile_id, profile_revision, idempotency_key}`；校验所选片段与内容预设预算，绑定该版并排 media_prepare，不调用模型 |
| POST `/api/ingest-runs/{run}/cancel` | `{expected_version, reason}`；事务取消并失效在途提交 |
| POST `/api/ingest-runs/{run}/retry` | `{expected_version, stage, idempotency_key}`；仅合法失败步骤，复用验证过的输入/计划及 checkpoint |
| GET `/api/ingest-runs/{run}/files/{key}` | 只读已登记缩略图/探测摘要；key 不是路径，不能下载任意原始目录 |

source_version 由服务端对合法源引用/登记标记计算；不是客户端自报文件哈希。片段时间使用整数 us，源范围为 `[start_us,end_us)`；selected_segments 中的边界变更也必须在已探测源范围内，输出目标固定 `{fps:30|60,sample_rate:48000}`。prepare 绑定内容 Profile 只是用于预算/来源一致性，后续仍需显式 prepared-preflight/start；最终启动必须选同版，否则要求重新核对预算并产生新准备修订。

MCP 变更：

- `get_task_input` 对新类型返回 `input_kind=media_ingest`、task/run/source/plan/execution_id、受控引用与预算，不返回伪 EDL；旧任务 JSON 保持兼容。仅当前租约持有者可读；外部源引用只允许 ingester。
- `heartbeat` 新增可选 `ingest_capability`；工具/根目录配置摘要由 ingester 报告，身份角色固定、有效期 90 秒。原 `capability` 与模型预设含义保持。
- 新工具 `save_ingest_checkpoint`：受控 checkpoint 引用、execution_id/sequence/输入指纹；只做当前租约下的有限登记。
- 新工具 `submit_ingest_result`：task_id、execution_id、package_dir、输入/计划身份；仅合法 ingester 导入任务。类型对应的产物契约在 service 校验；media_prepare 最终复用 EDL 包验证。
- MCP 不新增目录浏览、任意本地命令、治理修改、片段批准或外发许可工具。

SSE 新增 `ingest.changed`；只通知 UI 重新拉 REST 快照。重连刷新 source/run/plan/segment/asset/task，不依赖事件历史重放。错误消息去敏，包含可操作原因（选流、预算、源变化、空间不足、时间戳异常），不原样透传程序 stderr。

## 10. WebUI 与本地运行交接

导入入口展示已配置根目录、相对文件、资产名、允许本地 ingester 操作的明确治理动作。运行面板显示步骤/进度/失败原因、取消和合法重试；探测结果提供流选择与源范围，分段审查支持候选分页和选段边界表单。

prepare 完成后展示实际片段预览/试听、目标帧率、音轨及来源，入口导向现有预设运行面板；只有 ready EDL 能启动内容 workflow。空候选、无音轨、媒体不可播放、能力过期、旧版冲突和恢复中的状态均有实际提示，控件不能溢出窄窗。

## 11. 开发拆分与交付门槛

下表保留 A–H 交付门槛；当前主链路已有实现，但 E 存在已复现缺陷，H 仍需补证，详细状态见独立验收记录。建议依赖顺序 A → B → C/D → E/F → G → H；不能以“接口已经搭好”替代完整实现。

| 任务 | 范围 | 必须交付的证据 |
|---|---|---|
| A 契约/存储/治理 | 输入类型、媒体策略、source/run/plan/task/checkpoint、下一迁移、路径和角色规则 | 迁移兼容、事务失败回滚、版本/幂等并发、root 逃逸与原始资产不能启动内容任务 |
| B 入场复制与探测 | media_probe、源快照、哈希、多流元数据、流/范围计划 | 大文件流式处理、来源变化拒绝、损坏/无音轨/多音轨 fixtures、取消无原文件损伤 |

## 12. 自动验收与最终人工验收

### 12.1 必须自动覆盖

1. 输入控制：相对路径、中文/空格/长路径、重复导入、同键不同请求、目录/URL/设备路径拒绝、junction/符号链接逃逸、导入途中源变化。
2. 媒体探测：30/60 fps、分数源帧率、真实 VFR、非零首 PTS；无音轨、两个具有不同标记音的音轨、损坏和无视频文件。VFR fixture 用非均匀实际 PTS 生成并断言，不能仅修改元数据。
3. 分段：已知场景变化、无变化、闪光、短段合并、长段拆分、跨分析块边界、指定源区间；切点唯一、覆盖完整、顺序确定。测试测量已知切点，不把文件存在当检测正确。
4. 准备：只生成选中的片段；每段帧数、音轨选择、长度/采样数、源时间映射、没有选择的范围不进入 EDL；有声音时解码不为空。
5. 同步：用具有已知源 PTS 的闪帧/标记音录屏，在标准化短片与最终分轨音频中定位事件，量化偏差；超过一个目标帧失败。分别覆盖音频晚起、不同视频/音频起点与 VFR，不用无声音频证明同步。
6. 恢复：模拟复制/扫描/转码中断、 lease 回收、同 Agent 重领、锁定/隐藏、取消、磁盘不足、检查点篡改和发布后登记断线；已完成块可复用，旧结果拒绝。
7. 预算：候选/帧/字节/时间/文件数量/空间上限实际生效；超限明确阻断，不自动提高 Profile 限额。长素材不累积全量帧，记录峰值内存、时间和写入字节，无依据不写性能达标。
8. 真实链路：合成 MKV 从本地源导入 → 探测选轨 → 分段选择 → 标准化 EDL → 第六阶段固定预设 → 本地 mock 实收图片 → 场景/草稿 fixture 确认 → 实际中文 SAPI → Node XML/ZIP；验证 source-map/provenance、选段顺序、帧率、音频标记以及修改后新 run 重跑。
9. 浏览器：导入/治理、进度、选流/范围、候选分页/边界编辑、版本冲突、取消/重试、预览试听、旧来源/新包不混淆、SSE 重连与 375/520/900/1280 宽度。
10. 旧链路：Go 全包/vet、Python 全套、两个 Node 全套、WebUI 类型/构建/已有测试；第五、第六阶段端到端 fixture 保持兼容，旧任务无新增字段也可执行。

新增 `workers/python/scripts/verify_phase7_ingest.py` 及 fixture 生成器，输出隔离 `.run-data/phase7-e2e-<id>/report.json`、运行日志、输入/计划/映射/包摘要和最终 ZIP。报告固定区分 `engineering`、`content_provider=mock`、`human_acceptance=pending`；全流程自动成功也不填写人工通过。
