## 通用调用约定

1. **同源访问**：生产页面由 Go 的 `web_root` 托管；使用相对 `/api/...` URL。当前会话端口 8806 是运行配置，不应写死到业务组件。开发使用 `webui/vite.config.ts` 的代理，默认后端 8787，可用 `VAC_API_TARGET` 指定实际端口。Go 校验 loopback Host 和浏览器 Origin；不要直接跨端口访问绕过既有代理。
2. **请求格式**：JSON POST/PATCH 使用 `Content-Type: application/json`。请求体上限 1 MiB；未知字段、非对象 JSON、重复尾随 JSON 都会拒绝。不要把 GET 返回对象原样作为写请求提交。
3. **响应格式**：成功通常直接返回对象或裸数组，没有统一 `{data:...}` 外壳。201 表示创建；202 表示排队/受理，不代表处理完成。文件和 SSE 不能调用 `response.json()`。
4. **认证与 key**：当前网页 REST 是本机控制面，没有登录/token 流程。供应商 API key 是外部服务凭证，不是本地 REST 登录凭证；Worker 的 MCP token 也不交给浏览器。当前治理/审查审计 actor 通常为固定 `human:webui`，不能据此推断具体操作者身份。
5. **并发版本**：`expected_version` 是对应 run 的整数版本；`expected_revision` 是预设保存版本；`expected_asset_version` 是预检返回的字符串指纹；`expected_source_version` 是登记源版本。四者不可互换。409 后刷新快照，让用户基于新状态重试，不强行修改版本覆盖。
6. **幂等键**：对同一逻辑操作的网络重试应复用同一个 `idempotency_key`；新的操作使用新键。现有部分封装内部调用 `crypto.randomUUID()`，重新调用封装即新操作，接手者若实现自动重试需特别处理。
7. **路径**：路径参数逐段 `encodeURIComponent`。文件键是受控标识，不是绝对路径；录屏输入是 `root_id + relative_path`，交付导入是 `delivery_root` 内相对目录。不要让浏览器读取任意服务器本机路径。
8. **时间单位**：录屏与选段 `_us` 字段是整数微秒；解说 start/end、证据 timestamp 的含义是秒；时间线帧率仅 30/60 fps，准备音频采样率 48000。显示与回写必须保留微秒，使用 `clockToUs/usToClock` 等价的无损转换。
9. **取消请求与取消任务**：AbortController 只终止诊断等 HTTP 请求；停止导入/内容流程必须调用对应 cancel/revoke 接口，不能用关闭页面替代。

### 错误与业务未通过

普通错误结构：

```json
{"error":{"code":"conflict","message":"可展示给用户的原因"}}
```

| HTTP / code | 前端处理 |
|---|---|
| 400 `invalid_argument` | 修正参数；不要无条件重试 |
| 403 `forbidden` | 展示治理/来源限制，刷新资产或运行条件 |
| 404 `not_found` | 对象或路由不存在；不得把所有其他错误当不存在 |
| 405 `method_not_allowed` | 方法错误，可读取 Allow |
| 409 `conflict` / `invalid_state` | 版本或阶段不允许，刷新权威快照 |
| 409 `resource_busy` / `stale_execution` | 资源占用或执行代次已变化；保留排空/恢复提示 |
| 409 `lease_expired` / `lease_held` | 展示任务租约状态，重新读取，不由浏览器抢占 |
| 413 `payload_too_large` / 415 `unsupported_media_type` | 调整请求体或 Content-Type |
| 500 `internal_error` | 保留当前界面数据并显示失败；服务端日志包含详细原因 |
| SSE 503 `no_event_source` | 连接不可用，允许 REST 刷新和重连 |

以下两类 **HTTP 200 仍可能未通过**：

- 服务商诊断检查 `ProviderDiagnostic.ok` 和 `code`，常见 code：`passed`、`missing_credentials`、`authentication_failed`、`endpoint_or_model_not_found`、`rate_limited`、`timeout`、`connection_error`、`redirect_refused`、`provider_error`、`response_too_large`、`invalid_response`。保留 message 和 latency_ms；未知 code 也要显示。
- 运行预检检查 `PreparationReport.can_start` 和 `checks[].status`。`blocked`/`not_checked` 不能显示为完成；不要仅按 HTTP 成功启用启动按钮。

### 资产与治理

#### API-01 · GET `/api/assets`

- **页面功能**：App / AssetManager：资产列表和选择。

- **成功响应**：200 Asset[]。

- **页面功能**：App / AssetManager / IngestPanel：可见、锁定、批准、允许导入。

以下列出重构页面需要的字段，完整结构以 Go JSON 标签和上述 TypeScript 类型为准。TypeScript 是客户端消费子集，并非所有后端字段的完整定义。示例 ID、模型名均为占位值。

| 数据对象 | 关键字段及用途 |
|---|---|
| `Asset` | `asset_id`；`status`；`agent_visible/human_approved/locked`；`allowed_agents:string[]`；`artifacts:Record<string,string>`；`created_at/updated_at`；可选 `input_kind:raw_recording或edl_package`、`ingest_run_id`。artifacts 值不是下载 URL |

| `execution` | `execution_id/generation/status/wait_reason/connection/checkpoints_done/recovery_from/cleanup/control_version` 等；前端部分可选字段，不包含进程 ID 或密钥 |
| `Task` | `task_id/asset_id/type/agent_role/status/progress/updated_at`；可选 `agent_id/message/lease_expires_at/claimed_at/artifacts/depends_on/attempts`。progress 为0..1，不是百分数 |

### 处理预设与诊断对象

```ts
type ProcessingProvider = {
  adapter: 'builtin' | 'vision' | 'narration';
  endpoint?: string;
  model?: string;
  token_env?: string; // 凭证环境变量名，不是 key 值
  api_format?: 'openai' | 'anthropic' | 'gemini';
};
type ProcessingProfile = {
  schema_version: 1;
  profile_id: string;
  revision: number;
  name: string;
  content_mode: 'builtin' | 'configured';
  vision: ProcessingProvider;
  narration: ProcessingProvider;
  sampling: { max_frames: number; max_bytes: number; timeout_seconds: number };
  tts_voice: string;
  export_target: 'premiere';
};
type ProviderDiagnostic = {
  ok: boolean; code: string; message: string; latency_ms: number;
  models?: { id: string; name: string }[];
  truncated?: boolean;
};
```

- 当前通用服务商界面使用三种原生格式；`api_format` 为空是已有 custom 适配兼容语义，不应把空值当成“自动检测”。诊断接口要求明确三种格式之一。
- `endpoint` 是基础地址，必须保留服务商要求的路径前缀。浏览器不自行拼 `/chat/completions`、`/messages` 等供应商协议后缀，交给本地 Go/Worker 适配层。
- configured 模式：vision.adapter=`vision`，narration.adapter=`narration`；builtin 模式二者只能是 `{adapter:"builtin"}`，不能残留 endpoint/model/token_env/api_format。
- profile_id：`[A-Za-z0-9_-]{1,64}`；name 最长100字符；max_frames=1..48，max_bytes=1..48 MiB，timeout_seconds=1..120；tts_voice 非空；本阶段 export_target 固定 premiere。
- 临时 `api_key` 只发诊断请求；未填写时控制面尝试读取 provider.token_env。它不保存到预设、localStorage、查询缓存或审计；正式 Worker 仍需自己的启动环境凭证。测试成功不等于 Worker 已具备凭证。
- 参数或临时 key 变化应使旧测试结果失效；保留手动模型输入。AbortController + 请求代次校验防止旧结果覆盖新配置；卸载时取消请求。清除测试 key 应同时清除相关诊断状态。
- 发现模型只能证明模型目录可读取，不能证明所有模型都支持图像。画面识别测试使用合成图片，中文解说测试使用文字；二者都不是 TTS 试听接口。

`PreparationReport` 主要字段：`schema_version/profile_id/profile_revision/profile_sha256/status/can_start/checks[]/expected_asset_version?`。checks 含 `{code,status,message}`，status 为 passed/blocked/not_checked。固定预设检查至少涉及下列项目，前端应按数组渲染，不写死项目数：

| code | 展示用途 |
|---|---|
| `asset_governance` | 可见且未锁定 |
| `role_recognizer/role_narrator/role_exporter` | 对应角色已允许 |
| `active_workflow` | 没有冲突活动内容流程 |
| `input_ready` / `ingest_ready` | 原始录屏已准备为可用包 |
| `ingest_profile` | 与准备短片时绑定的预设版本一致 |
| `active_ingest` | 仍有活动导入时阻断 |
| `controlled_edl` | 受控 EDL 校验 |
| `worker_recognizer/worker_narrator/worker_exporter` | 新鲜 Worker、相同预设指纹、工具与凭证就绪；narrator 还要匹配声音 |
| `external_authorization` | 当前预设版本的外发许可 |

## 典型请求与完整操作顺序

### 录屏到选段

```mermaid
flowchart LR
  A[读取根目录] --> B[登记录像]
  B --> C[设置资产治理]
  C --> D[开始导入并读取探测结果]
  D --> E[提交分析计划]
  E --> F[候选选段与拆分合并]
  F --> G[保存完整选择版本]
  G --> H[绑定已保存预设并准备短片]
  H --> I[等待 ready 并进入内容预检]
```

AnalysisRequest 示例：

```json
{
  "expected_version": 3,
  "video_stream_index": 0,
  "game_audio_stream_index": 1,
  "source_range_us": [0, 60000000],
  "segmentation": {
    "method": "scene_change",
    "threshold": 0.3,
    "min_segment_us": 2000000,
    "max_segment_us": 120000000
  },
  "idempotency_key": "analysis-operation-uuid"
}
```

game_audio_stream_index=null 表示不选游戏音轨。当前表单范围为0..probe.duration_us；threshold=0.05..0.95；最短片段至少0.5秒，最长至少为最短的2倍、且不超过30分钟。

SelectionRequest 示例：

```json
{
  "expected_version": 5,
  "base_plan_revision": 1,
  "selected_segments": [
    {"segment_id":"seg_0001","start_us":500000,"end_us":1500001},
    {"segment_id":"manual_example","start_us":1500001,"end_us":4000000}
  ],
  "output": {"fps":30,"sample_rate":48000},
  "idempotency_key": "selection-operation-uuid"
}
```

selected_segments 为完整列表，按源起点升序、不重叠、每段至少能生成一帧，遵守 policy 上限；segment_id 唯一并符合 `[A-Za-z0-9_-]{1,64}`。拆分/合并没有独立 HTTP 接口，在浏览器修改这个列表后统一保存。派生 ID 不必出现在自动候选列表中，但要保持可见可编辑。当前合并仅允许首尾相接；不要把间隙自动纳入。

prepare 请求使用保存结果的 run.version 和 selection_revision：

```json
{
  "expected_version":6,
  "plan_revision":2,
  "profile_id":"my_profile",
  "profile_revision":1,
  "idempotency_key":"prepare-operation-uuid"
}
```

修改选择/输出帧率后必须先保存，未保存时禁用“生成”；变更分析版本时不能继承旧候选的勾选。后端 start/analysis/prepare/retry 还接受可选 `resource_policy`：`reject_if_busy`（默认）或 `replace_after_stop`；现有前端未发送，若新增替换入口，应明确表达“停止旧执行并等待清理”，不能绕过排空。

### 预设到交付

1. 保存预设或读取明确的历史版本；需外部模型时授予该版本外发许可。
2. POST prepared-preflight，显示全部 checks。只有 can_start=true 且没有未保存配置时才能继续。
3. 将 report.expected_asset_version 原样传给 prepared-workflows；成功后读取 run/review，并订阅事件。
4. recognize 完成后逐场景确认或退回；全部 confirmed 才推进 sort、narrate。
5. 逐句改稿并保存新修订；逐句批准。全部批准才推进 tts → subtitle → mix → export。
6. ready_for_acceptance 后预览/试听，下载该 run 的 ZIP，按当前修订记录验收。

场景编辑请求：

```json
{"expected_version":10,"base_revision_id":"rev_example","scene_id":"scn_example","label":"修正后的场景说明","sequence_rank":0}
```

解说编辑请求（时间为秒）：

```json
{"expected_version":11,"base_revision_id":"rev_example2","narration_id":"nar_example","text":"修正后的解说。","start":0.1,"end":3.2,"source_scene_id":"scn_example"}
```

当前 editWorkflow 封装使用通用 Record，因此重构时最好为“场景编辑”和“解说编辑”分别定义请求类型。后端兼容 revision_id 作为 base_revision_id 的回退；不要同时传不一致的两个修订。sequence_rank 为0..场景数-1；草稿文本最长160字符，结束晚于开始并满足所属视频/场景时间窗。

六类验收 `check_item`：`content_fidelity`（内容忠实度）、`evidence_trace`（证据追溯）、`browser`（浏览器）、`premiere`（Premiere 导入）、`cuts_fps`（切点/帧率）、`subtitle_audio_duck`（字幕/声音/压低）。用户完成哪项就记录哪项；存在 ZIP 或任务 succeeded 不等于所有验收通过。

## 状态与按钮启用规则

| 对象 | 关键状态/阶段 | 页面行为 |
|---|---|---|
| 导入运行 | state=`queued/processing/awaiting_review/ready/failed/cancelled`；stage=`probe/segment/segment_review/prepare/ready` | `awaiting_review` 是等待用户，非异常；failed 才显示失败步骤重试；ready 才显示短片已生成 |
| 内容流程 | status=`created/running/awaiting_review/failed/cancelled/ready_for_acceptance` | 失败重试、取消、验收入口随真实状态启用 |
| 场景审查 | awaiting_review + scene_review | 允许确认/退回；当前界面还允许 acceptance 阶段编辑场景以生成新修订 |
| 草稿审查 | awaiting_review + draft_review | 批准尚未批准的当前版本；draft_review/acceptance 可编辑；取消流程后不允许撤销操作 |
| 任务 | queued/claimed/running/succeeded/failed/cancelled | queued 不显示已经执行；未知状态展示原值。前端类型中的 paused 是预留，后端无暂停/恢复 REST |
| 执行恢复 | waiting_resource/waiting_drain/draining/stop_requested | 显示等待旧执行退出；保留取消和恢复反馈 |
| 执行恢复 | suspended_connection / recovering / cleanup_blocked | 显示断线、恢复或清理受阻；不能只看 Task.progress |

按钮禁用只是交互辅助，所有请求仍需处理后端拒绝。当前“启动新流程”和“启动此版本流程”语义不同，重构为一个主按钮时推荐固定预设流程，同时保留工程回归入口的真实标识。

## SSE、缓存与刷新

`GET /api/events` 使用命名事件，不能只监听 EventSource.onmessage：

| 事件 | 当前前端失效/重新读取的查询 |
|---|---|
| asset_created / asset_updated | assets、audit |
| task_created / task_updated | 当前 task、audit、ingest/run |
| ingest.changed | ingest、assets |
| capability.changed | ingest、assets、workflows、processing-profiles、prepared、workflow、review、acceptance |
| workflow.changed / review.changed / acceptance.changed / profile.changed | workflows、processing-profiles、prepared、workflow、review、acceptance |

事件帧形如 `event: workflow.changed` + `data: {...}`，data 是该业务事件负载，不是统一任务对象。服务端心跳是注释 `: ping`，不是业务事件。没有 event ID 重放保障，禁止只靠 Last-Event-ID 恢复。

每次连接成功（首次或重连）都刷新 REST 快照；断线期间保留旧数据并提示连接状态。当前退避基数1秒、上限30秒、最多8次；手动“立即重连”清零预算，主动断开取消定时器。事件只提示数据变化，REST 仍是展示状态的来源。

写入成功以及版本冲突后，应按模块刷新：

- 导入：`ingest`、`assets`、`audit`；候选缓存键包含 run_id、analysis_revision、offset。
- 预设：`processing-profiles`、`prepared`、`workflows`、`assets`、`audit`。
- 内容审查：`workflows`、`workflow`、`review`、`acceptance`、`assets`、`audit`。
- 交付：资产与文件列表；文件列表以资产 ID 区分，不能把上一资产媒体留作当前结果。

当前导入活动运行约5秒轮询（等待人工除外），任务观察约15秒，已请求的预检约15秒；若重构共享查询，避免同一个任务在父组件和子组件各轮询一次。

## 本地功能、兼容探测与缺失接口

| 页面内容 | 真实实现与重构边界 |
|---|---|
| 手动补充导入、批量 JSON 草稿 | `localStorage['vac.asset-drafts.v1']`，不写 Go。不能包装成已入库；真正登记录像走 recordings，导入交付包走 deliveries/import |
| 资产媒体类别、部分时长/分辨率 | artifacts 键名推断或本地草稿字段，不是 Asset 的统一后端分类字段 |
| 审计时间/类型/actor/关键字筛选与统计 | 仅已读取 limit 范围，界面需显示“已加载 N 条 / 命中 M 条”；不能称为全库搜索 |
| `/api/v1/audit/logs` | fetchAuditLogs 先探测的兼容候选，当前后端未注册；只有404/not_found 才回退 `/api/audit`，不能在500等故障时回退掩盖错误 |
| 关联任务列表 | 从有限审计 task.create 推导 task_id，再 GET 单任务；可能不完整，应保留范围及读取失败提示 |
| 单任务取消/重试/暂停/恢复 | 无对应 REST；已有的是导入 run 和内容 workflow 的 cancel/retry。不要把它们当成单任务接口 |
| 任意文件上传、任意路径浏览、通用资产新增/删除 | 无对应 REST；受控录屏登记和交付导入会产生/更新资产，但不存在 POST/DELETE `/api/assets` |
| 拆分、合并、拖动边界 | 浏览器先编辑选择列表，再 POST selection-revisions；无独立 split/merge 接口 |
| 试听音量 | HTMLAudioElement.volume，仅本次浏览器试听，不改变导出混音 |
| 下载验收摘要 | 浏览器组装 JSON Blob，内容取已有 run/profile_binding/acceptance；无专门 summary 下载接口 |
| 打开 Premiere / 配置 Worker 环境 / 设置服务端录屏根目录 | 当前不由网页 REST 直接执行；不能通过界面按钮虚构已执行效果 |
| `/mcp` | Worker/Agent 通道，不属于 WebUI REST 清单；浏览器不应直接持有或使用其 token |
