## 接入约束与最短流程

人工入口首先调用 `skillApi.unlockHumanSession(token)`。宿主需配置至少 32 字符随机 `VAC_HUMAN_ACCESS_TOKEN`；它与模型 API Key、MCP Agent token 独立。后端签发一小时 HttpOnly/SameSite=Strict 会话，SDK 还支持内存请求头；不写 localStorage、项目、日志或 Agent 配置。现有 `api.request` 已带 `credentials:include` 和可选人工头，但尚无页面调用解锁/锁定。

新项目与 run 的读取/写入、步骤/修订/节点、日志、原 `/api/audit` 及 Skill 管理写入需要人工会话。Skill 说明只读与 MCP 身份验证分别沿用其边界。MCP 的 10 个新增工具服务外部 Agent，详见 Skill 交接，不能把人工定稿/日志/撤销动作交给 Agent，也不把 MCP 计为待实现的前端 HTTP。

调用顺序：解锁 → 项目创建/读取 → 素材导入或关联 → 保存可见集并人工确认 → 选流程/Skill/模式创建 run → execute 或 MCP 运行 → 展示计划并人工定稿 → 执行/检查 → 读取 workbench 播放及交付。局部调整时调用 edits → 等待新计划 → 人工确认 → 继续执行；历史恢复后也须重新确认。

`GET .../workbench` 的 `segments` 同时给出 `timeline_start/end` 与 `source_start/end`。`segment_index` 从 0 开始；`at_seconds` 使用成片时间；区间需对齐完整片段边界，溶解重叠时间点可选中两段。不要在前端自行把成片时间当源时间。`createSkillEdit` 已封装版本/成片绑定，`skillPreviewSource` 已优先使用短时只读 `preview_url`，两者均未被页面使用。

播放器使用 workbench 返回的 `preview_url`，支持 Range/HEAD；票据精确绑定路径，一小时有效，退出或凭证轮换立即失效。不要持久化或传给 Agent。收到版本冲突先重读快照；请求超时先查询 run/步骤，不盲目重复付费调用。历史预览不能直接授权新修改，正式导出还需当前定稿与内容摘要一致。

旧新手引导和侧栏宽度保存在 localStorage；自动启动选择不再记忆。新项目/默认 Skill 等配置由 Go 持久化，凭证、preview_url 和人工批准不得写本地持久缓存。切项目、会话退出、版本变化须处理在途请求和播放器。保持页面挂载也要保留隐藏页/焦点/模态框快捷键守卫。
