# Skill 管理与双流程改造方案
## 2026-10-19 用户澄清与设计落点

本次只调整架构设计与旧文档；大改之后新建分支实施。完整设计见 [Skill 双流程架构设计](Skill双流程架构设计.md)，本文件保留原需求来源，以下切片不表示已开工。

- VAC 支持两种 Agent 方式：外部 Agent 经 MCP 取得对应 Skill 和受控项目上下文后自行推理、调用 VAC 工具；内置 Agent 使用用户配置的 API Key/Provider 运行同一 Skill。外部模式无需额外配置 VAC 推理模型 Key，转录/TTS 等 VAC 工具的服务凭证另计。
- Agent 负责理解 SKILL.md；Harness 负责上下文、权限、工具调度、预算、审计和产物，不将 Markdown 直接解释成固定步骤程序。
- 流程 A/B（轻量/画面主导）、Agent 执行方式（MCP/API）、创作方式（手写/Agent 生成）是独立维度。
- 原生 video-use、Skill 管理及项目隔离仍为目标。现有 F1 可见集是全局范围，需迁移项目 scope；现有 FFmpeg 能力要统一复用。具体接口草案及 S0–S6 依赖以新设计为准。
- §10 是原方案的历史交接示例，不是本轮代码实现、安装、模型外发或合并授权。

## 1. 目标一句话

让 VAC 从「固定内置管线」升级为 **可管理 Skill 的 Harness**：脚本工作台能指定 Skill 干活；原生内置 `video-use` 与 **ffmpeg 直导出**；产品明确支持 **两条流程**——口播/可转写素材走轻量 Skill 直出成片，游戏录屏等不可靠转写素材走「抽帧 → 多模态大意 → 按脚本编排 → ffmpeg 或 Premiere」。

本方案不推翻 F1 可见集 / F2 脚本工作台已定口径（人工授权、定稿、Agent 不直接读盘），而是在其上增加 Skill 层与第二交付路径。

## 2. 非目标（本轮方案边界）

- 不在本文完成代码、不推远程、不合并 `main`。
- 不删除现有 recognize→narrate→export 旧链；旧链可降级为「兼容 Skill / 兼容工作流」，由迁移计划决定何时收敛。

- 不强制替换强调色 / 视觉规范；UI 新增分页仍遵守 `ui-style-spec.md`。

## 3. 产品双流程（必须写进 README / 引导弹窗）

### 3.1 流程 A：轻量直出（口播、教程、访谈等）

适用：素材以人声为主，转录有意义；用户要的是「尽快出可发布 MP4」，可接受较少人工精修。

步骤：

1. **创建项目** → 得到项目目录（见 §5）。
2. **导入素材**到项目文件夹（入库）；按需确认 Agent 可见集（F1 门禁仍有效；轻量流程可提供「一键对本项目全部素材可见」但必须留痕）。
3. 进入 **脚本工作台**，选择原生 Skill **`video-use`**（或用户安装的兼容 Skill）。
4. 用户用自然语言写目标（可附简短脚本/大纲）；工作台把「项目素材视图 + 用户指令 + Skill 清单」交给 Harness。
5. Skill 按自身契约执行（去口癖/空白、剪点、字幕、叠层、自检等，以内置 `video-use` 能力为准）。
6. **ffmpeg（或 Skill 内封装的渲染）直接导出** `final.mp4`（及可选中间件）；站内预览；可选再导出 Premiere 包（非必须）。

验收口径（给 Codex）：

- 空项目 → 导入 ≥1 口播样片 → 选 `video-use` → 一次成功跑出可播放 MP4。
- 全程不要求用户手写 EDL；不要求 Premiere。
- 失败时有可读错误（缺 API key、转录失败、渲染失败），且不污染其它项目目录。

### 3.2 流程 B：复杂画面 / 游戏录屏（不可靠转写）

适用：游戏画面、纯画面演示、BGM 盖过人声、或「转成文字稿不能代表画面信息」的素材。

步骤：

1. 创建项目并导入素材；确认 Agent 可见集。
2. **关键画面抽帧**（控制面任务，Worker/ffmpeg 执行）：
   - 检测「画面内容剧烈变化」的帧（场景/镜头切点、大面积运动突变等）。
   - **连续剧烈变化**区间采用抽稀策略：默认 **三抽一**（可配置：N 抽 1、按时间上限、按总帧预算）。
   - 输出：关键帧图片集 + 时间戳清单 + 抽帧策略元数据（写入项目，可供复跑）。
3. **多模态识别**：把抽帧结果交给多模态模型（走现有 Provider 预设：OpenAI / Anthropic / Gemini 等），生成一份结构化的 **「视频内容大意」**（见 §6.2）。
4. 用户在脚本工作台 **书写或导入脚本**（沿用 F2 语法与定稿门禁）；Agent **基于「大意 + 用户脚本」编排画面**（选段、顺序、字幕意图、可选 TTS 挂接）。
5. 交付二选一或并行：
   - **ffmpeg 直导出**成片（站内预览 / delivery）；
   - **Premiere 支持的序列**（既有 xmeml / OTIO / 交付 ZIP 能力对齐或明确替换策略，见既有交付文档）。

验收口径：

- 无有效人声的游戏样片：流程 A 不得被默认强行转录堵死；流程 B 在无 ASR 时仍能产出「大意」并完成编排草案。
- 抽帧策略可配置且写入审计；超预算停在决策卡，不静默砍素材。
- 定稿与可见集门禁与 F1/F2 一致：Agent / `system:auto-review` 不能代点确认。

### 3.3 流程选择 UX

- 新建项目时可选默认流程模板：`lightweight`（A） / `visual_heavy`（B） / `custom`。
- 脚本工作台顶部显示当前绑定 Skill + 流程提示；允许中途切换，但切换须提示「将使未定稿草稿过期 / 需重跑抽帧」等后果。
- 自动模式（若保留）：全局授权页须逐项列出将调用的 Skill、可见集、脚本定稿范围（延续 G1 口径 A）。

## 4. Skill 体系

### 4.1 定义

**Skill** = 一段可版本化的 Agent 能力包，至少包含：

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定 ID，如 `video-use`、`vac-script-syntax` |
| `name` / `description` | 展示名与用途 |
| `version` | semver 或锁定 git ref |
| `source` | `builtin` / `local_path` / `git` / `registry`（首版可只做 builtin + local_path） |
| `entry` | `SKILL.md` 或等价清单路径 |
| `runtime` | 声明：`instructions_only`（仅注入提示） / `harness`（由 VAC Harness 按步骤调度） / `external_cli`（可选） |
| `inputs` | 声明需要的输入：素材视图、脚本修订、大意文档、用户指令… |
| `outputs` | 声明产物：`mp4`、`edl.json`、`content_summary`、`premiere_package`… |
| `permissions` | 网络、指定 Provider、写项目子目录、调用 ffmpeg 等；默认最小权限 |
| `compatible_flows` | `["A"]` / `["B"]` / `["A","B"]` |

仓库内建议目录（给 Codex 落地时用，可微调但需单一事实来源）：

```text
skills/
  video-use/           # 原生内置（从 upstream 纳入并 VAC 适配）
    SKILL.md
    ...
  vac-script-syntax/   # 已有或演进
  vac-visual-summary/  # 流程 B：抽帧+大意（可后置拆分）
  README.md            # Skill 作者与权限模型说明
```

控制面需有 **Skill 注册表**（DB 或配置 + DB 覆盖）：安装、启用/禁用、默认 Skill、项目级覆盖。

### 4.2 设置 › 插件 / Skill 管理分页（UI）

在现有「设置」工作区增加分页（名称建议：**Skill** 或 **插件 / Skill**；不要新开顶层五大页签以外的第六大区，除非和零改布局）。

分页能力：

1. **列表**：已安装 Skill（builtin 标记「原生」）、版本、启用状态、兼容流程、上次校验结果。
2. **启用 / 禁用**（项目默认 + 全局默认分层：全局默认，项目可覆盖）。
3. **安装**：
   - 目标：原生随包附带 `video-use`，不可卸载，可禁用；当前尚未纳入。
   - 从本地目录导入（选文件夹，校验 `SKILL.md`）。
   - （可选二期）从 git URL 拉取锁定版本。
4. **详情**：读 `SKILL.md` 摘要、权限声明、输入输出契约、依赖（ffmpeg、转录服务商等）。
5. **校验**：一键检查依赖（ffmpeg 是否在 PATH / 捆绑路径；所需 API key 是否在预设里配置）。
6. **设为脚本工作台默认 Skill**（按流程 A/B 可各设一个默认）。

权限与安全：

- Skill **不能**获得任意磁盘读权；只能通过控制面提供的 **项目素材视图 / 可见集视图** 访问媒体（延续 Agent 不直接读盘）。
- Skill 写出物只能落在 **当前项目目录约定子路径**（如 `renders/`、`summaries/`、`skill-runs/<run_id>/`）。
- 需要外发模型时，走既有 Provider 预设 + 外发授权，不另开旁路。

### 4.3 Harness：其它模块如何调用 Skill

**Harness** = 控制面内的 Skill 运行治理与工具调度层（Go service）。外部 Agent 通过 MCP 读取 Skill；内置 Agent 通过配置的 API Key/Provider 读取同一 Skill。Agent 解释说明并选择工具，Go 统一约束项目上下文、权限、预算和产物。

调用序列（逻辑）：

```text
UI / Auto / MCP
  → POST /api/skill-runs  { skill_id, project_id, script_revision?, visible_set_sha, params }
  → Harness 校验：Skill 启用、权限、可见集确认、（若需）脚本定稿或显式「允许未定稿试跑」
  → 物化输入包到 skill-runs/<id>/input/（清单 + 允许的媒体引用，不是裸盘路径泄露）
  → 按 Skill.runtime 执行：
       instructions_only → 注入系统提示，走现有 Agent 生成入口
       harness → 外部 MCP Agent 或内置 API Agent 理解 Skill，调用受控工具（转录/抽帧/渲染…）
  → 收集 outputs，登记为 run 产物；SSE 通知
  → 失败重试策略由 Skill 声明 + 全局预算共同约束
```

脚本工作台集成点：

- 工作台工具条：**「运行 Skill」** 下拉（仅启用且兼容当前流程的 Skill）。
- 生成旁白 / 编排画面时：可选「使用 Skill：xxx」；默认值来自项目设置。
- 特殊语法与 Skill 的关系：
  - F2 语法仍由 `vac-script-syntax`（或等价）解释；
  - `video-use` 更偏「整段自然语言目标 → 成片」，可不要求用户写满 `{@视频}` 块；若混用，须在方案实现时定义优先级（建议：**显式语法块优先，其余交给 Skill**）。

自动模式：

- 授权页列出将调用的 `skill_id@version`。
- Skill 跑出的「需人工确认」步骤映射到现有决策卡，不发明第二套授权体系。

MCP：

- 增加只读 `skills.list` / `skills.get`；写入 `skill_runs.create` 受与 HTTP 相同的权限过滤。

### 4.4 原生纳入 `video-use`

动作要求：

1. 将 upstream `video-use` **vendoring / 子树纳入** `skills/video-use/`（保留来源与 LICENSE；记录 upstream commit）。
2. 写 **VAC 适配层**：
   - 输入改为读「项目可见素材清单」，不扫任意用户目录；
   - 进度文件（如 `project.md`）落到项目 `skill-runs/` 或 `skills-state/video-use/`；
   - 转录依赖（如 ElevenLabs）改为：**可选 Provider**；缺失时流程 A 明确报错，并提示改走流程 B 或配置 key；
   - 渲染出口优先走 **VAC 原生 ffmpeg 模块**（§5），避免多套 ffmpeg 封装漂移；
   - 自检「最多重做 N 次」接入 Harness 预算与审计。
3. 标记 `builtin=true`，`compatible_flows=["A"]`（若后续证明对 B 有子步骤可复用，再扩）。
4. 文档：在 Skill 详情与用户引导中写清「口播友好 / 游戏录屏勿默认」。

借鉴点（来自 QA 对比结论，纳入实现待办）：

- **转录文本打包给 LLM，关键处才取帧** → 可复用到 VAC 内容审查 / 流程 A。
- **渲染后按切点自检** → 对齐 auto-run 自评分，优先切点级检查。

## 5. 项目目录与原生 ffmpeg

### 5.1 项目 = 文件夹

创建项目时在约定根下生成（示例，Codex 可按现有 ingest 根对齐）：

```text
<projects_root>/<project_id>/
  project.json          # id、名称、默认流程、默认 skill、创建时间
  media/                # 导入素材（或 symlink / 登记后的托管副本）
  visible/              # 可选：可见集快照说明（事实仍以 DB 为准）
  scripts/              # 脚本修订导出（可选镜像）
  summaries/            # 流程 B「视频内容大意」
  keyframes/            # 抽帧图片与清单
  skill-runs/<run_id>/  # 单次 Skill 输入输出与日志
  renders/              # ffmpeg / Skill 导出的 mp4、代理文件
  delivery/             # 交付打包（zip、xmeml、otio…）
  audit/                # 可选：人类可读审计摘录
```

「把素材导入到项目文件夹」须同时 **登记到控制面资产表**，不能只落文件不入库（否则可见集与权限失效）。

### 5.2 原生 ffmpeg

要求：

- 控制面或专用 Worker **官方支持 ffmpeg** 作为一等能力（检测版本、编解码器、硬件加速可选）。
- 统一封装：切点拼接、音频淡入淡出、烧字幕、缩放、代理生成、导出版本（如 720p delivery）。
- 脚本工作台 / Skill / 旧 export 任务 **共用同一 ffmpeg 服务接口**，禁止各 Skill 私藏互不兼容的命令拼装（允许 Skill 传「意图参数」，由 VAC 翻译成命令）。
- 直导出成功即登记 `renders/` + delivery variant；站内预览走现有预览管道。

接口草案（名称可调）：

- `POST /api/projects/{id}/exports/ffmpeg` `{ edl_or_timeline_ref, profile, burn_subtitles, ... }`
- `GET /api/system/ffmpeg` → 版本与能力探测

## 6. 流程 B 关键设计

### 6.1 剧烈变化抽帧

实现建议（给 Codex，可替换算法但需可测）：

1. 解码低分辨率代理（降低成本）。
2. 帧差 / 直方图差异 / 感知哈希距离超过阈值 → 标记为「剧烈变化点」。
3. 对连续超过阈值的时间窗：按 **三抽一**（默认）或 `interval_ms` / `max_frames_per_window` 抽稀。
4. 全局硬顶：`max_keyframes_per_asset`、`max_total_keyframes_per_run`；超限 → 停决策卡或降采样策略升级提示。
5. 产出 `keyframes/manifest.json`：`[{ asset_id, pts, path, score, strategy }]`。

### 6.2 「视频内容大意」文档

建议结构（Markdown + 可选 JSON sidecar）：

```markdown
# 视频内容大意
- 资产：...
- 抽帧策略：三抽一 / 阈值…
- 模型：provider/model/version
- 生成时间：...

## 时间线摘要
| 时间 | 画面要点 | 置信度 | 关键帧 |
| --- | --- | --- | --- |
| 00:01.2 | ... | high | kf_012.jpg |

## 整体叙事大意
（多段自然语言）

## 可供编排的节拍
- Beat 1: ...
```

Agent 编排时 **只读大意 + 用户脚本 + 可见集**，需要复核某时刻再按需取帧（学习 video-use 的省 token 思路）。

### 6.3 编排 → 导出

- 编排结果仍应落到可审计中枢（现有 `edl.json` 或脚本 delivery 等价物），再：
  - `ffmpeg` 直出；或
  - `xmeml` / `OTIO` / 既有 Premiere 包。
- 与 F2「特殊语法预渲染画面与字幕」的关系：流程 B 的编排输出应能回写成工作台可预览形态；细节由 Codex 在实现时对照 `script-workbench-syntax.md` 对齐，**不得绕过定稿门禁直接进交付**。

## 7. 与现有模块的关系（防重做 / 防打架）

| 现有 | 本方案 |
| --- | --- |
| F1 可见集 | 保留；Skill 只吃已确认可见集 |
| F2 脚本工作台 | 增加「指定 Skill」；语法 Skill 与 video-use 分流 |
| 自动模式 | 授权页增加 Skill 身份；预算覆盖 Skill 重试 |
| Provider 预设 | Skill 外发必须走预设；新增「转录类」能力标签（可选） |
| 旧 content workflow | 兼容期内可包装为 `vac-legacy-pipeline` Skill，或保持双入口至 F3 挂接完成 |
| TTS 专页 | 不变；脚本段只保留是否配音与挂接 |
| ui-style-spec | 新分页遵守 |

分支建议（给 Codex，和零可改）：

- 用户已明确大改在后续新分支实施；本轮不创建分支，具体名称和起点在实施时确定；
- **勿动 `main`**；合入 `agent/main` / `agent/develop` 前交 Gate；
- 大改分切片：① Skill 注册 + 设置分页 → ② Harness + 工作台入口 → ③ ffmpeg 统一 → ④ 内置 video-use 适配 → ⑤ 流程 B 抽帧与大意 → ⑥ 双流程引导与文档。
