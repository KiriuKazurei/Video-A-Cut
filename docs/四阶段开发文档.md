## 本轮补上的契约

- **取样预算。** `SamplingLimits` 的总帧数、总字节和总时长都有有限默认值。`recognize` 为一次任务创建一个 `SamplingBudgetTracker`，同一计数器和截止时间覆盖每个片段的 FFmpeg 与 FFprobe。超限时删除本次写出的帧，并且不发布交付清单。
- **视觉输入。** `ClipEvidence.evidence_root` 由 Worker 的暂存目录设置。适配器只在这个根目录内解析相对路径，核对 SHA-256 后再放入 `image_base64`。缺文件、哈希不符或路径越界会在发出请求前失败。请求体不带绝对路径，也不带证据根目录。
- **证据贯穿。** `recognize` 把帧和 `samples/evidence-manifest.json` 写入交付包，清单含模型名与 `sampling-v1` 配置。之后每个 `package` 都复制并重算哈希；场景引用必须落在这份清单里。导出 CLI 在源包带有该清单时同样复制并校验，伪造引用不会发布。
- **解说审批。** 任务 EDL 里的 `tts_auto_approve_policy` 和 `approvals` 不能放行 TTS。操作员只在 Worker 配置里用严格布尔值 `tts_auto_approve` 打开自动化策略。人工批准走 `POST /api/assets/{id}/narration-reviews`，服务按文本、起止时间和来源计算草稿哈希并写入审计；`DELETE /api/assets/{id}/narration-reviews/{hash}` 撤销。Worker 只从 `get_asset` 读到的 `narration_approvals` 做比对，MCP 没有审批写入工具。模型返回的 `needs_review=false` 不会变成免审。
- **还没做完的验收。** `scripts/verify_phase4_integration.py` 只跑合成媒体和 builtin。`scripts/verify_phase4_e2e.py` 在缺少操作员给出的端点和录屏时直接退出，不上传素材，也不代替 Premiere 人工判断。

## 目标与非目标

- 从录屏的有限抽帧与媒体元数据建立关卡/片段证据，识别结果需附来源片段、取样时间、方法和置信度；不把 ffprobe 元数据标签冒充视觉识别。
- 生成与识别证据对应的中文解说草稿，限制其落点、时长和字数；人能在 TTS 前审查，不能把模型猜测当作已确认事实。
- 保持 Go service/store 为任务与资产的唯一事实来源。模型访问只发生在 Python Worker 的内容适配层；MCP 仍不提供治理权限，也不直接读取任意磁盘文件。
- 不在本阶段实现 Premiere 实时遥控、剪辑器内编辑器或未经配置的云端上传。没有可用模型时任务应显式失败，保留 `builtin` 作为可标识的回归与演示模式。

## 当前已接入的骨架

`workers/python/vac_worker/content.py` 定义 `ContentProvider` 协议、`ClipEvidence`、`SceneDecision`、`NarrationDecision` 与输出校验。`recognize` 在读取媒体时长后调用 provider，`sort` 随片段重排识别索引，`narrate` 接收识别结果并调用 provider；返回数据先经过数量、索引、文本、置信度和时间窗校验，再进入 EDL/交付包。已提交的 `BuiltinContentProvider` 只产生 `method=metadata_only` 标签与“第 N 段”模板，不声称完成 AI 内容理解。

Worker 配置新增 `content_provider`，默认 `builtin`。选择未安装的 provider 在配置加载时直接失败，不能静默退回模板。`StageContext.content_provider` 允许测试或后续适配器注入；MCP 领取、租约、进度、原子发布和 `submit_delivery` 未改变。`tests/test_content.py` 覆盖自定义 provider 穿过识别/排序/解说的链路、非法结果拒绝与失败时不发布 manifest。

`ClipEvidence` 在时长和入出点之外带有取样帧和 Worker 指定的 `evidence_root`。视觉适配器只在这个根目录内读取帧，核对哈希后才把图像字节发给已授权的端点。没有配置外部服务时仍使用可识别的 `builtin`，不能把模板结果说成模型识别。

## 任务顺序与交付契约

1. **有界取样。** 在 Worker 私有暂存目录内按片段时长采样少量代表帧；每帧记录媒体源相对路径、源时间戳、图像尺寸与哈希。限制单片帧数、总像素/字节、处理时间和并发；超限、解码失败或越界均使任务失败。原始素材和抽帧保持在交付根受控范围，不把绝对路径写入模型提示词。用静态画面、切场、黑场和多音轨真实录屏作 fixture。
2. **识别适配器。** 明确选择本地模型或经用户配置的外部服务；配置须写明端点、凭证环境变量、超时、发送哪些帧。外部发送默认关闭。适配器只返回每个输入片段一条 `SceneDecision`，含可解释标签、方法、置信度和证据帧引用；不能自行修改 EDL、资产治理或任务状态。结果校验通过后再发布包，并记录模型/配置版本与取样哈希，以便复现。
3. **排序语义。** 现有 `sort` 只按时间线位置稳定重排，不能声称按关卡顺序排序。若识别结果提供顺序线索，先定义可审查的 `sequence_rank` 与冲突规则，再由排序阶段使用；重复名、低置信度或证据冲突需进入人工复核，不允许任意猜顺序。视频与对应游戏音频必须同移，帧/采样边界继续由一阶段 CLI 校验。
4. **解说草稿。** provider 基于已确认的场景标签与证据写一段可编辑中文草稿；不得编造未见到的事件。输出必须落在本片段时间窗、长度有上限，字幕文本不可含换行/控制字符。将草稿、来源场景、模型版本和待复核标志保存在 EDL 的可兼容扩展字段；TTS 前的人工审查或明确自动化策略须有记录。TTS 仍先合成，再按真实声长回填字幕及 ducking；超时语音直接失败。
5. **交付与回归。** 用用户指定的真实录屏和额外带明确场景锚点的样本，跑 `recognize → sort → narrate → tts → subtitle → mix → export`。检查 MCP/REST 资产隔离、任务失败/重试、EDL 证据可追溯、时间线切点/轨道/音画、SRT、混音和 Premiere 导入。人工判断标签及解说是否忠于画面，并记录错误样本与修复前后差异。

## 输出边界与失败规则

当前 `SceneDecision` 一片一条，`clip_index` 必须与输入片段一一对应；`label` 和 `method` 必须非空、可打印且有长度上限，置信度若提供则须为有限的 0–1 数值。`NarrationDecision` 最多每片一条，文本非空、可打印且不超过 160 字符；时间戳必须为有限数并落在所属视频片段内。零条解说、重复索引、越界时间或无效置信度直接失败，不产生成功 manifest。后续如果要支持一片多句，先升级契约、测试和字幕/TTS 映射，不能绕过校验。

识别质量没有通用“自动通过”阈值。置信度只作为复核提示，不能替代人工判断；如果模型输出与帧证据矛盾，应保留错误并让任务进入失败或人工复核流程。模型凭证仅从环境变量读取，日志不能打印 token、完整请求体或原始媒体内容。未配置外部服务、网络断开、超时、速率限制和解析失败均不得退回 `metadata_only` 后提交成功。

## 验收门槛

- 骨架门槛（已通过）：Python Worker 15 项测试；自定义 provider 的识别和解说结果进入 EDL；非法索引/文本/时间窗拒绝；未知 provider 在启动时拒绝；三阶段默认 `builtin` 流水线不回退。
- 内容门槛（待开发）：抽帧元数据与哈希可重现；实际识别适配器在明确配置的模型上运行；有证据的排序和解说草稿经过人审；模型失败不发布伪成功产物。
- 交付门槛（待开发）：真实媒体端到端、Premiere 人工内容校对、任务审计及所有已有时间线/音频回归通过。自动测试、浏览器可见验证与人工内容验收分别记录。
