更新：2026-09-29。依据《项目开发文档》§6.2、§9–11、§14，以及当前 Go 控制面代码。本文是后续 Agent 的实施契约；界面和服务端行为以代码与运行验收为准。

## 阶段边界与当前进度

一阶段修订版 XML 已在 Premiere 导入；V1 两段视频、A1/A2/A3 三段音频、3.5 秒序列及画面符合合成样片预期。用户同意将疑似 ducking 偏移、精确音画同步、字幕与 Resolve 验证延至后续内容开发接近完成时。**这是一项延期校对决定，不是音画精度验收通过。** 详情见《一阶段开发文档》。

本项目的“二阶段”按现有实施计划定义为 **REST + SSE + 人类 WebUI**，不是剪辑软件实时 MCP 遥控。Go 控制面已有治理、任务、审计、SSE、受控交付文件接口与同源静态托管；WebUI 已接资产治理、任务观察、交付预览/试听/下载。自动化、HTTP 联调和用户真实浏览器操作均已验收通过；细节见《二阶段验收记录》。

## 架构与数据所有权

```text
浏览器 WebUI
  ├─ REST 查询/治理/任务提交 ─┐
  └─ EventSource 订阅变化 ───┤
                              ▼
Go api（协议、校验、JSON/SSE）→ service（唯一业务规则）→ store/queue/events
                              │
                              └─ MCP 仅在后续阶段调用同一 service，不拥有状态
```

浏览器只缓存服务器快照，不在客户端重实现资产可见性、锁定、审批或任务状态机。PATCH 只发送允许的治理字段，成功后用服务端返回的完整 Asset 更新缓存。创建任务仅发送 `task_id`、`asset_id`、`type`、`agent_role`；状态、进度和审计归 Go 管。界面不得把 `artifacts` 中的本机路径当作可直接下载 URL。

WebUI 与 Go API 采用同源部署。开发时 Vite 将 `/api` 代理到默认 `127.0.0.1:8787`，浏览器访问 `127.0.0.1:5173`；也可用 `VAC_API_TARGET` 指向独立测试端口。构建后配置 Go 的 `web_root` 可从同一端口提供静态 WebUI。Go 当前只接受本机 Host/同源浏览器请求，开发代理发往 Go 时需避免把 Vite 页面 Origin 原样转发到后端。不得为方便开发而放宽 Go 的本机来源校验。

## 已有 HTTP 契约

| 接口 | 响应 | UI 用途 |
| --- | --- | --- |
| `GET /api/assets` | `Asset[]` | 列表及初始快照 |
| `GET /api/assets/{id}` | `Asset` | 详情及治理结果核对 |
| `PATCH /api/assets/{id}` | `Asset` | `agent_visible`、`locked`、`human_approved`、`allowed_agents` |
| `POST /api/tasks` | `Task`（201） | 提交一项任务 |
| `GET /api/tasks/{id}` | `Task` | 按 ID 跟踪任务；当前**没有**任务列表接口 |
| `GET /api/events` | SSE | `asset_created/updated`、`task_created/updated` |
| `GET /api/audit?limit=N` | `AuditLog[]` | 审计列表 |
| `POST /api/deliveries/import` | `Asset`（201） | 从 `delivery_root` 下相对目录导入 CLI 清单和文件登记 |
| `GET /api/assets/{id}/files` | `DeliveryFile[]` | 无绝对路径的文件元数据 |
| `GET /api/assets/{id}/files/{key}` | 媒体或附件 | 仅可读已登记键；媒体支持 HTTP Range |
| `GET /api/assets/{id}/delivery.zip` | ZIP | 按清单原相对路径下载完整交付包 |

错误体是 `{ "error": { "code": string, "message": string } }`。UI 应展示可读 message，同时保留 code 供以后行为分支，不能按 message 文本判断错误。时间字段是 RFC3339 JSON 字符串。资产、审计列表返回数组，不包裹 `data` 字段。

SSE 没有历史回放：`EventSource` 的 `open` 每次触发（含自动重连）都刷新资产、当前正在跟踪的任务和审计快照；收到相应事件时也使对应 Query 失效。事件仅作“有变化”通知，不能当作新的唯一状态来源。断线时显示状态，不清空已有快照。

## WebUI 骨架与实施顺序

本次骨架包含 Vite/React/TypeScript 入口、统一 API client、Go 模型类型、QueryClient、SSE 订阅与简洁的资产/任务/审计操作台。初始页面须有加载、空、错误、断线状态；按钮可用键盘操作，有可见焦点，状态用文本表达。界面以治理和观测为主，不实现时间线编辑器。

以下保留最初实施顺序；其中浏览器流程、交付接口和界面已按最终验收节完成或记录边界：

1. 与运行中的 Go 进程做浏览器端实际连通性检查，确认 Vite 代理、本机来源校验、SSE 重连及 JSON 错误显示；修复真实不匹配。
2. 扩展资产详情、治理表单和任务跟踪；若需要全局任务面板，先在 Go service/store/api 增加分页列表接口及测试，再接 UI。
3. 为预览、试听、导出制定受控文件交付 API 与权限。现有 `artifacts` 是路径元数据，不能直接交给浏览器读取文件系统。
4. 增加浏览器层的键盘、窄窗、长文本、网络断线与错误状态验收。不要以静态页面截图代替真实 API 流程。
5. 在内容开发接近完成时，回到一阶段待校对项，使用带同步锚点的素材量化 ducking 和音画误差，再决定是否修复。

交付文件接口已按上述契约接线：`delivery_root` 必须是已存在的绝对目录，未配置时交付功能关闭；导入只接受该根目录内的 CLI `delivery-manifest.json`，所有声明文件在登记前验证，读取时再验证路径。WebUI 不接收任意文件路径，非媒体文件强制作为附件下载。ZIP 保留原包内相对路径，避免 XML/清单引用失效。配置与运行示例见 `webui/README.md`。

## 验收与未完成项

自动化与 HTTP 检查：WebUI 类型检查与构建、Go `test ./...` 与 `vet ./...`、`git diff --check`；独立库已完成真实 CLI 包导入（201）、10 文件登记、媒体 Range（206）、ZIP（200）且清单 9 个引用全部存在；同源静态页面、治理 PATCH、任务 POST/GET、审计和 SSE 初始连接均通过 HTTP 联调。用户随后在真实浏览器确认媒体播放/下载、资产治理、任务跟踪、SSE 断开/重连和窄窗显示全部正常。键盘细节与故障注入错误态未单独报告，作为后续非阻断回归项。

`ui-ux-pro-max` 技能的搜索脚本在本机安装中不存在，本次界面遵循其 `SKILL.md` 与 `references/quick-reference.md` 的静态规则：清晰标签、可见焦点、状态不只靠颜色、空/错/断线可辨识、窄窗无横向溢出。此为设计约束，不替代浏览器验收。
