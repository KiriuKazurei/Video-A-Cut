### DrawAI 的素材实际如何分发

- 建项目时由代码生成纸纹、颗粒、网格三张 SVG，以及 whoosh、impact 两段 WAV。五项基础媒体可离线生成。
- 动效文档列出可检索的 9 张纹理、102 个 FLAC 单音/打击采样。先 `motion_assets library` 搜索，再用 `use` 按 ID 拷入当前项目，记录哈希、来源、许可。导入后还需要显式绑定画面或加入音轨。
- 发布文档按整个扩展包统计 46 个字体文件与 116 项素材，约 145 MB 下载、约 201 MB 解压。发布包与 npm 插件分开，下载后校验并缓存；这组总数与可检索子库、工程生成项是不同口径。体积与清单来自上游文档，本轮未解包复算。
- Freesound 是另行联网检索的音效源。DrawAI 的 MIT 插件代码、Shotcraft Apache-2.0 卡片、OFL 字体、CC0 采样和许可不明确的纹理各自处理。DrawAI 的声明指出 8 张纹理没有逐项明确来源和许可。 [素材操作](https://github.com/fourzkw/dsh-drawai/blob/master/docs/motion-video.md#素材) · [发布机制](https://github.com/fourzkw/dsh-drawai/blob/master/docs/release.md#发布素材包npm-包不再带字体与素材库) · [第三方声明](https://github.com/fourzkw/dsh-drawai/blob/master/LICENSE)

## VAC 首版流程

首版场景建议选 **20–30 秒产品功能演示**。用用户已有的截图或录屏，支持纯代码场景作为空工程入口。已有配音时用真实词级时间驱动画面和字幕，未提供配音时按用户需求走现有 TTS 或无旁白路线。以 **可编辑 AVP 和已核对的 MP4** 为同一任务的两个终点。

1. **读取要求和素材。** 从现有脚本工作台发起，内置 Agent 和外部 MCP 使用同一份任务与工具约束。确定受众、卖点、画幅、时长、旁白及用户指定的镜头。读当前资源、时间线、`draw.capabilities`，根据实际能力挑引擎和卡片。
2. **先排镜头再制作。** 每镜记录稳定 ID、意图、序列帧区间、镜头卡 ID/版本、素材绑定、主要动作与音频锚点。初始镜长由卡片建议，最终受总时长、媒体长度和旁白时轴约束。优先按叙事功能和输入类型筛卡，再按画幅、引擎和风格排序。分镜作为既有任务上下文或脚本绑定的结构化记录，落地剪辑只由现有时间线解释。
3. **先看代表镜头。** 先做一张定调帧，再做 2–4 秒带切换或声音的短样片。用现有绘制帧预览和节目监视器呈现，保留与当前修订对应的样片。Agent 默认自行推进；用户明确要求先审样时，在现有交互里停在样片供反馈。
4. **按镜落轨。** 真素材、旁白、音乐、字幕沿用现有轨道。参数化动效以绘制构图保存，通过 `draw.import` 的源码模式进代码轨，保留后续编辑能力。修改指定镜头时用实例 ID、修订和既有局部再生成机制，只重做目标范围。
5. **全片预览与交付。** 检查首尾、切点、文字最密处和旁白落点，播放确认节奏与音画。提交现有结构化 `run.finish` 路径。交付记录区分技术检查、模型自评和人工观感，关联工程修订、成片哈希及使用的素材版本。

示例分镜可用「标题钩子 → 产品主界面 → 局部放大标注 → 前后对比 → CTA」。首批样片选「主界面 → 局部标注」，同时暴露图像清晰度、字幕安全区和声音节奏问题。

| 条目 | 首批建议 | 数据与使用方式 |
|---|---|---|
| 镜头卡 | 8 张。品牌开场、截图揭示、录屏聚焦、局部标注、步骤列举、数据/数字强调、前后对比、CTA。 | 每张有用途、禁用条件、画幅、所需输入、时长区间、参数 schema、实际可运行的 VAC 构图实现、短预览和自检。卡片是可执行模板，Agent 选择后填写参数，预览也由同一实现生成。 |
| 风格预设 | 2 套。清晰产品演示、深色技术说明。 | 主题 token 覆盖颜色、字体栈、留白、字幕、转场节奏。与镜头卡可组合。先使用当前运行时已可用字体，缺少字体时明确展示替代结果。 |

- **同一目录，两种入口。** 在现有资源工作区增加「内置」筛选或分组，复用预览和导入；在现有 Skill 注册表为 Agent 增加按类型检索、按 ID 读取和按 ID 导入的受控能力。检索只返回轻量索引，选中后取配方、预览或导入媒体。工具名称待实施时确定。
- **当前工程持有引用。** VAC 0.4.1 有 `resources.list/read` 和工程导入服务，MCP 还没有通用素材导入工具。建议新增的入口只接受已发布条目 ID 与版本，服务端解析可信目录和哈希，复用当前工程导入链路，返回普通资源 ID。使用项目可持久化的相对媒体路径，以内容摘要去重。版本升级后旧工程仍指向既有版本，未保存工程沿用既有保存流程。资源入库与放到时间线继续是两项明确操作。
- **限制首版依赖。** 卡片实现使用 `draw.capabilities` 实际支持的 VAC 引擎和模块。沿用 AVP、序列、轨组、修订校验、预算与取消。扩展包下载、外部媒体检索、全站采集、整片多 Agent 分派放在基础闭环验证后评估。
- **按文件处理许可。** 首版优先自制。第三方条目只有核清来源、再分发条件和署名要求后才进入安装包；无法核验的纹理留作调研参考。需要署名时从素材目录生成对应清单。 [VAC 功能边界](../功能文档.md) · [VAC 接口](../接口文档.md) · [现有操作 Skill](../../skills/vac-video-edit/SKILL.md)

## 实施顺序与验收

用户在调研后将第一阶段改为迁入固定版本的全部 Shotcraft 镜头卡与源码。实际集成的上游提交为 `1266a3ec4831289c4d893d42dd5102723658039a`，目录有 124 张卡和 150 个变体。移植保留作者署名、原始配方及源码，安装包资源表包含 Apache-2.0 全文与改编声明。 [归属与改编说明](../../control-plane/internal/shotcraft/ATTRIBUTION.md)

### 脚本到运行代码

示例脚本段落可以写成：

```text
{#card-stack}三张功能卡依次飞入并叠放，突出最后一张。把演示文字换成当前产品的实际功能。

{#chart-live-moves/axis-rescale-shock}用坐标轴重新缩放表现规模变化，保留原镜头的主要运动节奏。
```

- `#` 固定卡与变体，`@` 绑定资源或标记，正文描述内容、画面变化和用户取舍。编辑器补全显示卡号和动作摘要。单卡默认采用目录第一变体。后续若调整目录，已入轨的快照仍保存实际构图源码。
- 确定模板直接实例化为 Remotion 构图。需要截图的卡先按工具返回的别名绑定当前工程图片。四个相机模糊变体使用 VAC 的确定性帧采样实现。
- 自由描述的编译通过绘制 Skill 完成。Agent 先提取目标、运动、时序和资源，选卡并按需适配生成源码，保存后使用确定性帧时钟执行。普通段落保留可读脚本，源码随代码轨快照保存。已有代码条的局部再生成沿用选区和修订保护。 [工具与编译规则](../../skills/video-use/vac/tool-contracts.md)

下一步优先把 Agent 的编译决策沉淀为可校验的镜头规格，记录卡号与版本、素材角色、文案、动作对象、关键帧、缓动和保留的原生代码。相同规格可重编译，改一个镜头只更新关联源码。回读时，已映射的动作生成可读脚本，复杂的 Remotion 表达式保留为源码片段和说明。首版用卡号映射与 Agent 适配验证这条链路，通用源码回译单独开发。

### 调研时的后续建议

1. **先做一个贯通样例。** 用 2 张卡、1 套风格、1 张纹理和 1 个音效证明「查找 → 导入 → 参数化构图 → 代码轨 → 预览 → MP4 → 保存重开」。确认资源 ID、摘要和路径在重开后有效。工程修改范围及工具权限以现有 Skill run 为边界。
2. **再扩充首批目录和用户入口。** 到 8 张卡、2 套风格、8 项媒体。覆盖空工程纯绘制、导入用户截图与旁白、指定镜头重做三种入口。用既有 Go project/service/skill/MCP 与 WebUI 套件验证目录检索、同 ID 版本固定、重复导入幂等、切项目/旧修订拒绝和范围外素材保留。用既有 timeline/exporter 和可见桌面入口检查实际像素、声音、导出文件及 AVP 重开。 [统一验证入口](../../scripts/TESTING.md)
3. **单独验收真实 Agent 质量。** 给内置与外部 Agent 同一份含截图、旁白和目标的素材简报，核对卖点是否入镜、配方是否匹配、字幕和重音是否对齐、修改一镜后其他片段是否保留，并实际观看短样和成片。模型桩与自动技术检查分别记录。后续口播型流程可加入语义选卡和更精细的字级锚点。
