# AI 画面修改开发交接

状态：2026-10-29 用户再次确认仅保留接口，等待用户具备可用图像编辑模型后再重新授权实施。当前不接模型、不实现生成或编辑作业、不新增执行入口；本文仅保留为后续设计参考，不是当前实施任务。应用 0.3.2 的接口仍返回 HTTP 501，不代表已支持图像生成、局部修补或视频逐帧重绘。

## 1. 现有接口与源码

`POST /api/projects/{id}/sequences/{sequence}/frame-modifications` 位于 [timeline.go](../../control-plane/internal/api/timeline.go)。当前先检查项目序列可访问，再返回 `not_implemented`，消息“画面修改能力尚未启用”。本轮保持此行为，不创建任务、不调用服务商、不替换素材。

复用 [工程模型](../../control-plane/internal/project)、[序列服务](../../control-plane/internal/service/sequence_preview.go)、[绘制服务](../../control-plane/internal/service/project_draw.go)、[统一帧合成器](../../workers/node/timeline-cli/src/sequence.mjs) 和 [前端序列契约](../../webui/src/timelineContracts.ts)。绘制源码/图层编辑已实现，它与 AI 改写已有素材像素是不同功能，不能互相当作实现证据。

## 2. 后续启动条件与首版建议边界（当前不实施）

启动条件：用户提供可用的图像编辑模型及其接口能力、凭证配置方式、原图/遮罩约束和调用预算，并明确要求恢复实施。普通文本LLM或仅有图片理解能力的模型不满足该条件。下文全部为待确认设计，不应由其他Agent自动开始开发。

建议首版只支持用户选定的单帧或静态图片修改：导出当前帧、明确编辑意图、调用配置的图像编辑服务、展示候选与原图对比，由用户接受后作为新资源入库。视频连续帧重绘、时间一致性和音视频再同步单独立项，不默认随首版承诺。

用户原件只读。保留源素材 SHA256、序列内容版本、帧索引、采样时间、原始尺寸和实际提交图像尺寸；输出必须携带生成来源和参数摘要，不能把一次低清预览当作无损原图。所有图像/遮罩引用来自当前工程可见资源，不允许模型提供任意磁盘路径。

## 3. 契约草案（以下字段目前尚未接线）

未来请求至少包括 session、expected_revision、content_version、resource_id、source_sha256、帧定位、prompt、可选 mask_resource_id、provider_profile_id/revision、accept_external、idempotency_key。时间采用明确帧率下的整数帧和有理时间，不使用格式化秒字符串做身份。

建议异步返回 202 与 modification_id/task_id，另提供查询、取消、候选预览和接受/拒绝接口；这些附属路由当前不存在，实施前须固化合同。接受请求再次提交 CAS/内容指纹，避免在旧预览上覆盖新剪辑。作业参数、模型/配置版本与来源摘要固定到该次请求，不读取之后改变的当前预设。

状态流：`awaiting_authorization → queued → preparing_frame → generating → validating → awaiting_review → accepted / rejected`；执行阶段支持 `cancelling → cancelled` 和 `failed`。请求取消或客户端断开不必然代表提供方已停止计费，要区分已提交、提供方确认取消和本机停止等待。异常重试不能重复计费；没有幂等保证的服务商不得静默重发。

## 4. 与编辑、权限和交付的关系

- 编辑请求按现有项目/序列会话、可见集与外发许可校验，展示将发送的帧、遮罩、服务商、尺寸和预算。诊断不触发真实生成。
- 使用明确配置的图像编辑适配器；文本解说/视觉识别接口不等于图像编辑接口。支持哪些提供方、格式及限制尚待确定，不编造现成端点。
- 返回内容先校验实际 MIME、像素尺寸、字节上限、解码与 SHA256，拒绝 HTML/路径/远端 URL 冒充图片。下载网络边界沿用现有提供方拒绝重定向、超时和凭证隔离要求。
- 候选产物与原件并存，用户确认后执行一条可撤销/重做的序列命令，不能直接改磁盘原图或偷偷替换所有同源实例。
- 修改之后旧预览/质检与交付应失效；共享序列渲染器、工程保存/重开与重链接必须识别新资源。Reject/cancel 不改变主序列，历史产物依旧可追溯。

## 5. 实施切片与验收

1. 明确首版单帧/图片边界和提供方，固化请求/响应/错误码、异步状态和 UI 授权页；501 只在对应实现上线后移除。
2. 实现只读抽帧、原件/遮罩检查和候选存储，不连接真实服务商；用本机夹具证明取消、幂等、CAS 与指纹。
3. 实现独立图像编辑适配器、预算与显式外发授权；真实调用需用户许可，记录费用/超时/重试边界。
4. 接通原图/候选对比、接受/拒绝、撤销/重做、保存重开及共享导出；保持当前灰阶界面和设置布局。

沿用现有 API/service/project、Worker 与编辑器浏览器测试。必须覆盖：越工程/失效会话/陈旧修订、原文件被改、缺遮罩、取消和重复提交、非法图像/超大图片/无透明通道、服务商超时与重定向、外发未授权零请求、接受后旧预览失效、拒绝后序列不变、同图多实例隔离、工程往返与导出同版。人工确认修改区域、保留区域、文字/人物身份和清晰度；有可解码 PNG 不等于质量通过。
