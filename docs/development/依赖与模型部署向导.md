## 1. 目标与边界

帮助首次安装和迁移后的用户完成依赖定位、缺项说明、明确授权的安装及模型目录设置。复用设置页的“状态监控”和统一诊断，保留现有预设、声音、模型、自定义路径和工程数据。先做 Windows x64；其他平台明确显示支持范围。

用户必须能分别选择“使用已安装版本”“选择已有本地目录”“查看人工安装说明”；具备安装器支持后才显示“下载并安装”。离线使用和已有环境不依赖在线账号。首次扫描不下载、不运行安装脚本、不请求模型推理或云端服务、不修改全局 PATH。

## 3. 状态流与接口设计要求（待实现）

单个部署项使用状态机：`unscanned → checking → available / missing / incompatible`；用户选择方案后进入 `awaiting_confirmation → downloading → verifying → installing → rechecking → ready`。已有目录可跳过下载和安装。任意执行阶段可进入 `cancelling → cancelled` 或 `failed`；需要管理员权限时单独进入 `awaiting_elevation`。取消后不自动续装，不将失败显示成 ready。

后续在 `/api/system/deployment` 名空间设计：只读清单、创建授权作业、查询作业、取消作业和配置应用。此处是建议名空间，当前没有这些路由；实施 Agent 应先补齐 OpenAPI/机器清单和 TypeScript 契约，再写实现。所有变更请求绑定 item/version、目标目录、包 SHA256、配置修订和幂等键；前端只能选受支持的包或本地目录，不能上传任意 shell 命令。

作业进度包含真实阶段和已下载字节，不能伪造百分比。受控服务端按支持清单解析 URL、大小、SHA256/签名和许可证；不接受任意重定向后的可执行文件。先验证再安装，临时文件与最终目录隔离，阶段原子提交。失败和取消只清理作业自己创建的文件，不删除用户原有依赖和模型。应用路径不得通过未校验的链接/重解析点逃逸目标目录。

模型部署优先支持用户已有 faster-whisper 目录，验证必要文件、兼容模型配置和磁盘空间。在线模型下载的来源、版本、许可与文件清单须显式确定；未确定来源的模型只提供人工安装说明。不要把云端 API 模型当成本地可下载包。凭证使用现有环境变量引用和集中外发许可，设置成功与真实联网测试分开显示。

## 4. 实施切片

1. 扫描/定位：复用统一诊断，显示每种工作流所需依赖；实现已有目录选择和单项复检，先不开放下载。

4. 本地模型：目录验证、依赖检查、项目预设版本绑定；真实模型/声音验收独立取得用户许可。
