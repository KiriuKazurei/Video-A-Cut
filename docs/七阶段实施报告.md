## 5. 联通审查中发现并修复的缺陷

1. **ingest 任务输入不符合 MCP 输出 schema**：`get_task_input` 对 ingest 任务返回 `edl: null`，真实 ingester 进程报 “validating tool output … /properties/edl: type null want object”。修复：ingest 输入始终带空对象 `edl`，并新增真实 MCP 传输回归测试。
2. **`mtime_ns` 精度丢失（偶发）**：纳秒 mtime 大于 2^53，MCP 输出路径经 float64 往返后被舍入，导致 Worker 误判“登记后录像已变化”（是否触发取决于具体 mtime 值，此前通过的端到端属于碰巧可精确表示）。修复：MCP 中 `source.mtime_ns` 改为十进制字符串，Python 侧转回整数写入 snapshot；回归测试使用不可被 float64 精确表示的 mtime。
3. **探测时长包含起始偏移，尾段越界**：Matroska 的 `DURATION` 标签与容器时长是绝对结束时间戳（含首 PTS 偏移、音频尾部），而源时间以主视频首帧为原点。合成录屏的视频实际 17.0 s，探测却报 18.521 s，尾段计划 166 帧、实际只能产出 120 帧而失败。修复：流时长减去起始时间，`duration_us` 取主视频流跨度；新增探测断言、尾段准备测试，端到端选择改为包含尾段。

缺陷 2 和 3 都是在浏览器联通审查中走完“选择尾段 → 生成短片”时暴露的，此前端到端只选了前三段，所以没有发现。
