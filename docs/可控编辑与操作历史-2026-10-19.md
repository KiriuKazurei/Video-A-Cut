## 执行边界

用户选择应用级受控工具沙盒，继续使用本机 Python/Node/FFmpeg。Go 绑定项目、可见集、素材摘要、Skill 快照、预设版本、预算和人工确认；Agent 只提交工具意图，不提供可执行命令、任意路径、过滤器或安装脚本。

- 工具名及参数结构受白名单限制，路径由 Go 从已登记素材和项目运行目录解析，文件读取与发布前复核权限、摘要及版本。
- 子进程仅继承基础运行环境和本次所需 Provider 凭证变量；不继承其他密钥、人工会话密钥、PYTHONPATH、NODE_OPTIONS 等加载覆盖。
- 取帧、媒体探测和共享渲染限制 FFmpeg/ffprobe 协议及探测格式；媒体内隐藏的网络播放列表不能代替 Provider 外发授权。
- 模型/转录/TTS 的外发仍需现有精确预设及人工许可。取消终止所属进程树，迟到结果不得覆盖新版本。
- 本方案是应用权限边界，不是 AppContainer/容器，也不抵御同用户进程、操作系统管理员直接读取进程内存或篡改数据库。外部 Agent 在 VAC 之外拥有的工具不由 VAC 管理。选定原件仅作为参考，不能执行上游任意 shell 或动画代码。

## 人工专属操作日志

0021 的 `vac_agent_journal` 保存连续编号、时间、主体、动作、脱敏请求内容、结果摘要和前项摘要链。MCP 工具尝试先写入请求记录，再交给 SDK；原生工具在执行事务中先登记，完成或失败再追加记录。日志不可用时，新的工具请求停止执行。异常退出可能留下仅有请求的记录，不伪造完成记录，也不自动重复付费调用。

数据库触发器禁止 UPDATE/DELETE；没有日志修改或删除 API。人工可以分页查看、核验摘要链和追加注释，原记录保持不变。日志没有登记为可下载产物，不进入项目镜像或 Agent 上下文。MCP 已移除 `skill_runs.steps`，当前新增 MCP 工具为 10 个；Agent 通过当前 run 和幂等工具回放恢复状态，不能读取审计日志或历史步骤。

人工入口使用独立的 `VAC_HUMAN_ACCESS_TOKEN`（至少 32 字符），不复用 MCP Bearer 凭证。未配置时关闭受保护入口。前端以 `POST /api/human-session` 提交该凭证，获得一小时 HttpOnly / SameSite=Strict 会话；也可发送 `X-VAC-Human-Token`。密钥不进入 localStorage、项目、Skill、日志或子进程。撤销/轮换主凭证会使旧会话失效；`DELETE /api/human-session` 退出会话。

该人工作用凭证应由宿主配置为随机值，仅交给人工 UI；不是模型 API Key，也不加入 MCP Agent 的配置。页面接入前应完成会话解锁，不能把 403 当作可绕过的兼容回退。

受保护范围包括新项目与 Skill run 的读取/写入、步骤/修订/检查点/历史媒体、Skill 管理写入，以及新日志和原 `/api/audit`。原生 Skill 说明仍可按原只读入口获取；MCP 已有身份验证保持独立。前端共享 request 已支持内存凭证、凭据请求和既有错误结构；同源播放器可携带会话 cookie。跨源桌面入口支持人工作用请求头；媒体播放宜使用既有同源 WebUI 地址。

工作台返回的可用视频另带一小时、只读、精确路径绑定的 `preview_url`，供无法添加自定义头的原生 video 播放器使用。它只允许指定视频的 GET/HEAD，不能读取日志、其它 run 或写入；每次仍校验文件/项目权限和摘要，退出人工会话或轮换凭证立即失效。它不进入 MCP、SSE、数据库或日志，前端不可持久化或交给 Agent；界面优先使用该 URL。

## 成片浏览与局部修改

`GET /api/skill-runs/{id}/workbench` 返回 run、当前计划、成片/源素材双时间轴、可用预览、历史标记和操作游标。媒体通过 Go 受控 Range 接口读取，不交给浏览器本机绝对路径。新 SDK 的 `skillPreviewSource` 可接既有播放器。

`POST /api/skill-runs/{id}/edits` 请求示例：

```json
{
  "expected_version": 12,
  "plan_version": 3,
  "artifact_id": "art_当前成片.mp4",
  "artifact_sha256": "当前成片摘要",
  "prompt": "这一段太拖沓，缩短前半段并保留结尾动作",
  "segment_index": 1,
  "idempotency_key": "本次修改的唯一请求键"
}
```

三种选择方式互斥：`segment_index` 从 0 开始；`at_seconds` 是成片播放时间点；或 `timeline_start/timeline_end` 选择完整片段区间。时间点落在溶解重叠区时会选中两个参与片段。区间必须对齐返回的片段边界，不会静默扩大范围；需要更细范围时先通过人工计划接口拆段。

Go 校验当前成片 ID/摘要、计划版本和 run CAS，持久化 `run.edit_request`。其中包含原计划、人工提示词、选择窗口，每个窗口同时携带 `timeline_start/end` 与 `source_start/end`。成片时间按共享渲染器 30 fps 舍入及溶解重叠计算，不把成片时间直接当作源素材时间。

两种 Agent 都读取这一上下文；内置模型提示已包含定向修改规则，外部 Agent 从 `skill_runs.get` 获取。Agent 返回完整 `scripts.propose`，Go 只允许选择范围内的片段变化；片段数量、全局正文/字幕及未选片段必须保持。未选片段的声音配置由 Go 保留，选中片段不能从 Agent 获得声音授权。新计划清除原定稿与检查结论，停在人工确认；确认后才渲染新成片。

提示词修改通过 edit request 表达；人工也可 `PUT /api/skill-runs/{id}/plan` 直接保存脚本与选段。新增/拆分段落时，正文空行段落数必须与片段数一致。人工计划保存后需重新定稿；声音设置使用独立 voice 接口重新确认。`createSkillEdit` 会把前端当前显示的成片、摘要及版本绑定进请求，历史预览不能直接授权新修改。

旧成片保留在历史节点中，修改期间仍可浏览，界面应标记“历史预览”；它不自动成为新版本正式交付。修改后的新 MP4/Premiere 包使用新修订，未经确认的计划不能替代正式成片。

## 备份节点、撤销与重做

`vac_edit_checkpoints` 是不可覆盖的编辑快照图，包含计划、摘要、帧、产物引用、检查记录与待修改上下文；`vac_edit_cursors` 记录当前节点及重做栈。计划/声音/定稿/抽帧/摘要/交付等编辑内容变化时自动建立节点，纯计数/进度变化不额外制造节点。升级前的现有 run 在初始化时补建当前基线节点，不编造此前操作历史。

- `POST .../undo` 回到父节点，`POST .../redo` 前往重做栈顶；都只接受 `expected_version`，仅人工会话可调用。
- 撤销后进行新编辑，当前重做栈清空；旧分支节点及文件继续保留在历史中，不覆盖、不自动删除。
- 恢复会增加 run 和计划修订号，不重用旧修订；清除定稿与成片检查，恢复后的正式交付需要重新确认。
- 权限、可见集、Provider 许可、归属、累计调用次数/时长及外部请求不会被撤销。已撤销的授权不会因恢复历史而生效。
- 恢复不会重新授权历史外发配音；声音外发许可清除，需在声音接口再次人工确认。待执行的编辑请求不自动恢复运行。
- 撤销/重做不重新调用模型、转录或 TTS。已发生的网络调用和费用不可撤销。
- 历史视频可通过原节点的受控预览接口浏览，重新校验当前素材权限及文件摘要。它保持原始身份，不伪装成恢复后的新修订交付。

每次人工发起局部修改、定稿或明确恢复执行会建立新的有界工具预算窗口，累计 steps/elapsed 保持增长；撤销/重做不重置它们。源帧总预算仍受 run 限制。重启或修改不自动重放历史步骤。
