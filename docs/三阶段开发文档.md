## 目标与边界

Go 控制面继续是唯一状态所有者。Agent 只通过受限 MCP 工具读取可见资产和提交任务结果；人类在 WebUI/REST 治理资产。Worker 根据任务类型执行识别、排序、旁白、字幕、混音等动作，文件交付仍由现有 CLI 与受控交付接口完成。MCP 不推送 WebUI 状态，也不暴露资产可见性、锁定、审批或删除。

本阶段先完成项目开发文档 §14 的第一批 `list_assets`、`get_asset`、`submit_result`，随后补齐完整任务循环。这里的“三阶段”是工程交付次序；项目产品路线中的 P2 实时剪辑软件遥控仍是未来增强项。

## 已搭建骨架

- `control-plane/internal/mcpserver` 使用官方 Go MCP SDK 1.8.0，提供 `/mcp` Streamable HTTP。固定 2026-07-28 协议、无会话请求模型。MCP endpoint 仅在 `mcp_agents_file` 配置后启用；控制面现有 `http_addr` 仍限本机回环地址。
- 凭证文件按 Agent 声明 `agent_id`、`role` 和 `token_sha256`。服务启动时校验空值、哈希格式及重复身份；每个请求从 `Authorization: Bearer` 取 token，经 SHA-256 核对后注入身份。请求自报的 Agent ID 或 MCP session 不参与身份判定。浏览器携带 `Origin` 的请求拒绝。
- `list_assets` 只调用 `service.ListVisibleAssets(role)`；`get_asset` 从同一可见集合查找，不经由无过滤的 `service.GetAsset`；`submit_result` 将 token 绑定的 Agent ID 传给现有 `service.SubmitResult`，由 service 校验任务租约。MCP 层只做鉴权、参数和协议适配。
- `get_asset` 返回资产元数据与产物引用；`get_asset_edl` 在同一可见性裁决后返回受控的 EDL 正文。
- 现有 WebUI/REST 与 MCP 共用 service/store。MCP 不提供原始文件读取、治理工具、独立状态表或向 WebUI 发送事件的通道。

配置示例（实际文件放在本机受限目录，不提交真实 token）：

在 `control.json` 中加入绝对路径：

```json
{
  "mcp_agents_file": "E:\\AI\\Video Auto Cut\\.run-data\\mcp-agents.json"
}
```

```json
{
  "agents": [
    {"agent_id": "narrator-01", "role": "narrator", "token_sha256": "<64位小写十六进制 SHA-256>"}
  ]
}
```

`token_sha256` 是随机高熵 bearer token 的 SHA-256；明文 token 仅配置在对应 Agent 客户端。每个 Agent 使用独立 token；轮换时替换哈希并重启服务。当前仅面向本机回环通信，远程接入、TLS/OAuth、动态轮换和速率限制属于部署扩展，不因本骨架而视为完成。
