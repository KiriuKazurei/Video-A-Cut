# ASS 字幕模块实现与验收

日期：2026-10-07。实施范围为 R4 首版 ASS 文件及独立交付包，共用派生格式任务已接入；FCPXML 和 ASS 样式 MP4 预设仍为后续工作。协议与样式见 [delivery-variant v1](../contracts/delivery-variant/v1/README.md)。

## 使用入口

启动当前 Go 服务与更新后的 exporter Worker，在「导出 → 交付」选择已完成导出的资产，使用「ASS 样式字幕 → 生成 ASS」。生成后下载 ASS、原 SRT 或完整交付 ZIP；面板显示进度、取消、失败提示和历史记录。没有当前导出版本、有效 ASS Worker 或原 SRT 时，按钮不可用并显示原因。

默认采用微软雅黑 36、白字黑描边、底部居中，以 1280×720 为基准。原始 SRT 文件逐字节保留；ASS 起止时间按百分秒四舍五入，最大量化误差 5 ms。普通文字中的花括号和反斜杠不会执行为 ASS 标签。第一版固定样式，不提供自由编辑参数。断行使用固定 56 单位预算（可见 Unicode 标量计 2、Tab 计 4，组合重音/变体选择符/ZWJ 计 0），保留原有手动换行；每条最多 8 行，超过时明确拒绝，不裁切或截断文字。

## 实现边界

- Go migration `0013_delivery_variants.sql` 保存输入、产物、请求绑定和 Worker 能力；状态仍从 Task 投影。
- 新 REST 创建/列表/详情/取消/文件/ZIP，共 6 条注册路由；MCP 输入分支与 exporter 的 `submit_delivery_variant` 已接入。
- 新 Worker 能力独立注册，30 秒过期；旧 Worker 的 MP4 能力不能领取 ASS。
- 原导出包与人工审批状态不变；复制文件后生成新包。Go 通过原 SRT 独立重建 ASS 对比实际字节，拒绝已重算散列但篡改文字/时间/样式的输出。
- 原子发布、取消清理、相同身份恢复、持久请求复用、当前修订和治理守卫均沿用现有任务规则。
- 文件生成不依赖字体安装；本机渲染验收使用已安装的 `C:/Windows/Fonts/msyh.ttc`，没有外部下载。其他播放器、Premiere 导入及真人字幕观感未验收。

## 验证记录

证据根为 `.run-data/ass-subtitles-2026-10-07/`。最终测试计数和源码/构建/结果散列保存在该目录 `verification.json`，不将静态检查视为真人通过。

真实链路由 Go 临时服务提供 REST、MCP 和当前 WebUI 构建，启动真实 Node Worker 领取任务并转换、提交，再通过 HTTP 下载字幕和 ZIP，独立检查 ZIP 每个已登记文件散列。父包全部文件散列及资产交付映射保持不变。

真实 FFmpeg/libass 在 1280×720 黑底上烧录两条中文字幕，包括长句换行、多行、逗号、花括号与字面反斜杠标签。独立像素检查字幕出现前没有亮字，字幕出现时位于下半屏且在左右/底部安全区域内；`{\an8}` 普通文字没有把字幕移至顶部。输出包括 `real-chain/ass-render.mp4`、`ass-render.png`、ASS、原 SRT、样式、清单、收据、报告与 `acceptance.json`。这证明样本可以渲染，真人审美结果仍为 pending。

浏览器验收脚本为 [verify-ass-live.mjs](../scripts/verify-ass-live.mjs)，连接真实 Go 服务，检查下载入口、实际 ASS 下载、新尝试、取消、修订失效和 375px 无横向溢出。执行结果在 `real-chain/browser/results.json`。

本轮保留所有原有未提交修改，没有提交或推送 Git。测试产物每批前后按根目录 AGENTS.md 统计，上限 500 MiB；计数见 `.run-data/test-storage/` 的 JSON 报告。后续 R1 真实业务/真人验收、R2 长片及规模矩阵、R3 部署收口、R5 FCPXML 仍按原交接方案执行。
