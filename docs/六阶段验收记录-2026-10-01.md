## 2. 新实现中的工程问题

### F6-01 / P2：预设幂等回执及审计与业务保存脱离事务

位置：`control-plane/internal/service/profile_store.go:67`。插入预设修订的事务提交后，另写 PutIdempotency 并忽略返回错误，然后单独写审计。事务内没有复查同一幂等键。

隔离临时 SQLite 库给 idempotency_keys 加失败触发器后，第一次 SaveProcessingProfile 返回 nil，修订可读；重复完全相同的请求与幂等键返回 conflict。即客户端得到成功却没有回执，或在提交后中断时无法安全重试。当前顺序式 happy-path 测试覆盖不到这个窗口。

解决：事务内复查幂等键与指纹，将预设修订、当前指针、幂等回执及业务审计写入同一事务。失败全部回滚；同键同请求返回同一保存结果，同键不同请求冲突。补回执/审计失败注入及并发同键测试；不能只在事务外补错误检查。

### F6-02 / P2：读取预设未验证保存指纹

位置：`control-plane/internal/service/profile_store.go:72`。GetProcessingProfile 直接解析 canonical_json 并返回数据库 sha256，不调用 Validate/Fingerprint，也未核对请求 ID/修订与 JSON 身份。

隔离库把已保存 canonical_json 中的名称改为“已篡改”但保留原 sha256，GetProcessingProfile 返回 nil；重新计算实际指纹与返回的保存指纹不一致。后续绑定启动/Worker 消费若依赖此函数，会接受内容与标称配置来源不一致的版本。

解决：读取时校验 schema、profile_id/revision、结构与服务端规范化指纹，与行字段核对，不一致拒绝。也检查幂等缓存返回的修订身份/内容。补 JSON 篡改、身份错配、无效结构、指纹错误测试。

以上问题当前在未开放的内部功能中，尚未产生真实生产运行，但应在开放预设读取和绑定启动前修复。
