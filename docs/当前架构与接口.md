## 底层框架

Go control-plane/main.go 组装 SQLite、事件、service、队列及 Harness 初始化。HTTP/MCP 是同一 service 的投影，权限、版本、输入快照、预算、发布和审计均由 Go 判定。React/桌面读取 REST 快照；SSE 只发失效信号；Tauri 仍提供原 11 个桌面 IPC。

现有排队任务继续由 MCP Worker 领取。新 Skill 工具首版复用工作台的受控 Python/Node 直接进程执行，HTTP execute/tool 为同步请求，运行状态另行持久化；前端可读 run/SSE，并用 AbortSignal 取消。没有把 Markdown 解析成固定任务程序，也不声称请求断开后仍在后台继续。模型调用与工具步骤均先登记，取消终止所属进程树，重启把未完成执行停到人工决策。

## 项目与数据

0018 全局可见集、0019 工作台和原 workflow JSON 保留。新增 0020 的 vac_projects、vac_skills、vac_skill_runs、vac_skill_snapshots、vac_skill_steps、vac_skill_requests、vac_skill_revisions。新项目使用 scope v2，绑定项目、人工确认、素材内容 SHA、Skill 快照和精确计划版本；不复用旧全局确认。

项目在 delivery root/projects 下，媒体导入只读允许的 ingest root 后生成托管副本并登记资产。SQLite 为事实来源；project.json、内容大意 JSON/Markdown 是镜像；产物通过 ID 和摘要受控下载。legacy 是兼容迁移视图，不伪造项目确认或搬动旧业务数据。

新项目 Skill 计划保存在 run 及其不可覆盖历史中；旧脚本继续使用 scripts/script_workbenches。两者共用语法、人工门与媒体/交付能力，避免直接改写旧全局脚本语义。前端新入口读取 SkillRun.plan，不能把 run_id 当作旧 script_id，也不假设两者自动双写。

## 功能模块

| 模块 | 实现与边界 |
|---|---|
| Skill 注册 | 三个原生包、固定版本/内容摘要、启停、项目默认/禁用覆盖、本地文本包导入及依赖检查 |
| 外部 Agent | 桌面本机 MCP 免独立凭证；自动连接会话绑定 run owner，服务端固定 narrator 角色并执行人工项目授权。日志记录上报名称/来源及实际 peer，人工权限不对 MCP 开放；内部 Worker Bearer 路径保留 |
| 内置 Agent | 预设 narration 推理；读取图像时走 vision Provider；工具结果回传循环，人工门暂停；凭证仍是 token_env |
| 轻量流程 | 可选预设 transcription 能力、词级转录、目标编排、定稿、共享 FFmpeg 和切点检查；Premiere 可选 |
| 画面流程 | 无 ASR 前置；连续变化三抽一与静止覆盖、预算停卡、证据绑定大意、脚本编排、MP4/Premiere |
| 媒体与交付 | 复用 timeline-cli/script-workbench 渲染；字幕最后烧录、边界音频淡化、TTS/EQ/偏移、同版 MP4/ZIP、摘要与失效 |
| 旧自动链 | TaskInput.script 携带精确定稿；Python 消费原文/片段/声音/开关，Node export 同一渲染器；回执校验精确 script 身份 |
| 审计与恢复 | CAS、幂等请求、运行/模型/工具步骤、计划历史、租约、活跃预算、取消与重启暂停 |
