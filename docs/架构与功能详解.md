# VAC 架构与功能详解

更新：2026-10-29。以当前 `codex/integrate-remote-20261029` 整合实现为准（应用版本0.3.2，统一绘制实现）。本文供人工和 Agent 理解实现与变更影响，不把旧阶段提案写成已有功能。产品定位和沿革见[项目文档](项目文档.md)，未完成事项见[计划文档](计划文档.md)，请求/响应及机器索引见[接口文档](接口文档.md)。

0.3.1仅统一应用、桌面包和MCP标识；AVP格式为3、AVS保持2，draw Skill包仍为0.3.0、video-use adapter仍为0.1.0-vac.7，依赖版本不随应用号批量替换。

### 图片资源、实例与渲染依赖

DrawImageLayer 将“原件”和“实例”分开：resource_id 指向当前工程资源，id 标识画面中的具体使用。多个实例可共享一张原图，各自保存 x/y、width/height、dx/dy、动画帧区间、fit、opacity 和 mode。构图指纹包括原图 SHA 和全部实例参数。改文件备注/名称不改变像素指纹，重新关联原件后保存构图才更新依赖。

Go 只从当前项目资源解析图片路径，校验类型、可用性和实际 SHA；私有路径仅传给固定 Node Worker。Worker 再校验指纹，使用现有 FFmpeg 将支持的图片转为本地 PNG（保留 alpha，最长边各不超过 8192），GIF/APNG 取静态首帧。图片只放到渲染器拥有的临时目录和同源服务内，浏览器不能据此遍历磁盘或请求外部资源。旧构图最多64个图片实例；统一文档最多128个总节点、32份图片原件；原件保持不变。

旧构图适配的自动图层由HyperFrames的同一GSAP时间轴、或Remotion的useCurrentFrame按帧驱动；统一文档的公共图层、变换和关键帧由§18的共享帧时钟驱动；Source 模式传入图片及参数，供源码决定构图和动画。HyperFrames 自动动画在源脚本之后同步注册，确保被引擎捕获，不能等 DOMContentLoaded 后才追加。UI 使用既有四区布局：左侧图片目录/实例，拖入预览区创建实例，右侧按当前选择显示图片参数；构图属性可返回，长参数区独立滚动。没有把源码在 VAC WebView 中执行。

### 2026-10-25 代码绘制执行层

DrawComposition 保存稳定 ID、引擎、源码、整数帧规格、有理 fps、自身 revision 及内容版本。源码留在 AVP，运行缓存位于工作区专属目录；保存、改名和重开保留代码。文档打开校验源码指纹；源码或规格变化使用新缓存，名称变化只递增修订。

project_draw.go 管理当前工程/会话、双重 CAS、幂等、检查、渲染、媒体哈希复核和入轨事务。结果沿用资源索引、真实流、轨组、来源、撤销历史、隔离及共享序列合成器。skill_draw.go只暴露已声明的八个绘制工具；执行命令和输出路径始终由 Go/Node 创建。

Node 固定使用 HyperFrames 0.8.193、Remotion 4.0.538、React 19.2.0 和 GSAP 3.13.0。Remotion 编译 TSX 后注册受控 Composition；HyperFrames 使用完整内联 HTML 与暂停 GSAP 时间轴。源码在独立 Chromium 进程运行，不进入 VAC WebView；模块/API 静态检查、文档 CSP sandbox 和同源请求拦截共同限制环境。这是应用边界，不宣称 OS 沙箱。FFprobe 复核实际宽高、帧数、fps、时长和 SHA256；取消复用进程树终止，Stage 只清理其自建目录。

Windows使用已有chrome-headless-shell或显式配置的Chrome；可见UI验证只使用本地Chrome，不使用Edge。依赖缺失明确失败，不下载浏览器或模型、不云回退。旧单引擎执行路径继续兼容；统一文档使用原生HF、React和公共图层同帧合成，绘制源无需先出MP4即可入轨，详见§18。外部音视频、字幕和配音通过现有编辑时间线组合。

## 1. 状态所有权和调用边界

| 对象 | 权威位置 | 其他形式及约束 |
|---|---|---|
| 已保存工程 | `.avp` 正式文件 | Go 中工作副本可比正式文件新；dirty 表示尚未保存，不能用 SQLite 缓存替代保存 |
| 正在编辑的工程 | Go ProjectWorkspace / SQLite 当前工程投影 | 前端草稿定期 flush；切换和保存前必须收齐编辑器草稿 |
| 全局配置 | SQLite/本地配置/运行环境 | 服务商、预设、凭据引用、Skill 设置不随工程覆盖或写入 AVP |
| 运行和任务 | Go service + SQLite | REST/MCP/Worker/前端不各自建立状态机；Task 状态与运行状态分别归属 |
| 媒体内容 | 原始文件或已登记输出 | SHA/size/源窗口参与内容身份；ID 和真实路径不是同一个概念 |
| 可交付结果 | Go 登记的当前修订、文件清单和摘要 | Worker 产出文件后仍需 Go 独立校验；进程退出 0 不直接发布 |
| 前端状态 | REST 快照 + 页面草稿 | SSE 只令查询失效，不能把事件负载当作完整业务对象 |

Go 的 `main.go` 负责组装配置、SQLite、迁移、事件、service、队列及 HTTP/MCP。handler 处理传输、解码和错误映射，规则放在 service，事务与持久化放在 store，媒体校验和 Skill 类型有独立包。MCP 不持有另一份项目事实。

可见窗口操作直接采用人工身份；无解锁 Cookie/Token、窗口会话倒计时、隐藏撤权或媒体票据。MCP 采用 Agent 身份及工具名单，Worker 采用内部 Bearer、角色、租约及执行 scope。客户端名称是审计元数据，不是赋予人工权限的凭据。应用身份不会扩展 Windows 操作系统权限。

## 3. AVP 工作副本、保存和切换

### 3.1 文档组织

`.avp` 是 UTF-8 JSON，`format="avp"`，当前写入 `schema_version=2`。读取兼容 1/2；版本 1 的原始 EDL 放入 legacy_sequences，没有正式序列时补建空主序列，保留资源、脚本和输出。打开仅升级 Go 工作副本，手动保存/另存为才写新版文件。保存工程身份、resources、完整 scripts、sequences、settings、workspace、允许的 runtime 投影及 file_references。稳定 ID 关联资源、脚本、运行和时间线；完整文件结构以 Go `AvpDocument` 为准，不能丢弃 runtime 或输出引用。

资源 source 记录 relative_path、original_path、SHA-256、size_bytes、modified_ns。先尝试相对工程位置解析，再回到原始位置；素材丢失不删除编辑关系。保存不会把原始媒体嵌入文件。导入 `.avs` 后工程保存自己的脚本副本，原文件独立。

`runtime` 是版本化白名单投影，不是任意数据库 dump。恢复前校验允许表、字段、关系及快照；替换当前工程记录时保留全局配置、服务商、预设与日志。外部成片引用在 file_references 中保留受控映射，允许清空运行缓存后重开工程并找回仍存在的输出；缺失输出明确显示，不伪造成片。

### 3.2 修改、保存和恢复

普通修改先写工作副本并增加会话 revision/dirty。资源编辑历史和运行计划历史有不同作用域。手动保存会同步所有注册编辑器，再将完整 JSON 写入同目录临时文件，flush/close 后用平台原子替换正式文件。Windows 使用对应替换原语；失败保留原件和 dirty，不将最近项目索引失败误报为正式保存失败。

另存为创建独立 project ID，之后两工程修改互不影响；原始媒体继续引用。文件正式路径、资源显示名、备注及布局变化不等同于媒体内容变化。

Go 每 30 秒为有修改工程更新一份本地恢复副本；前端每 15 秒 flush 尚未提交的界面草稿。恢复副本不是正式文件的静默覆盖。首页列出恢复入口和最近项目，默认最近保留 10 项。重启将未完成执行停止到安全/待恢复状态，不自动重放模型或付费步骤。

### 3.3 打开/关闭与运行排空

```mermaid
flowchart LR
  A[选择目标工程] --> B[先校验目标文件和投影]
  B --> C[处理当前 dirty 和活动任务]
  C --> D[确认停止并等待旧请求及 Worker 退出]
  D --> E[保存或放弃当前修改]
  E --> F[事务恢复目标工程投影]
  F --> G[更新 Session 并重建前端]
```

`expected_session` 和 `X-VAC-Project-Session` 用于拒绝过期工作副本请求，不是人工授权凭证。取消、校验/保存失败或排空失败均留在当前工程。工程切换期间拒绝旧业务请求，取消旧请求上下文，等待 Worker 退出/空闲确认，停止播放器，取消查询并清除工程缓存，再按 Session 重建工作区。

资源列表、直接 ID、脚本素材选择、运行/交付读取、SSE 和 MCP 均核对当前工程。没有打开工程时返回空列表或相应不可用状态，不能从历史全局缓存泄漏其他工程。

## 4. 六类资源和依赖管理

| 类型 | 当前识别格式 | 预览/编辑 |
|---|---|---|
| 视频 | MP4/MKV/MOV/AVI/WebM/M4V/MPEG/MPG/TS | 源视频优先；必要时本地 FFmpeg 代理，逐帧、速度、音量、入出点 |
| 音频 | WAV/MP3/M4A/AAC/FLAC/OGG/Opus/WMA | 源音频或代理，播放/定位/速度/音量 |
| 图片 | PNG/JPEG/WebP/GIF/BMP/TIFF | 图片缩放；无法直接显示时代理，TIFF 路径有实际验证 |
| 字幕 | SRT/ASS/VTT | 文本内容预览；ASS 样式编辑属于交付模块的版本化功能 |
| 文稿 | TXT/Markdown | UTF-8 文本预览和工程备注 |
| 脚本 | `.avs` | 正文预览；双击进入工作台，显式关联及导出 |

左栏只列当前工程已导入资源，搜索/筛选不改变工程内容。中栏只保留预览、操作台、备注；右栏显示文件名、位置、大小、格式、时长、尺寸、帧率、编码和音轨等元信息，并支持宽度调整。

导入原件保持外部磁盘引用。生成结果在运行/交付页管理，不自动灌入资源栏。移除只改变工程引用，不删除原文件；被脚本/运行时间线引用的资源保留 missing/removed 占位和稳定 ID，允许重新定位。

指纹用于判断依赖的实际内容/窗口变化。project_dependencies 按脚本绑定和时间线识别受影响结果；无关资源、显示标题和备注不使成片失效。源文件变化或有效绑定/脚本/时间线变化才影响相关运行和交付。重新定位及撤销定位要同步 EDL，不只改 UI 路径。

## 5. 录屏导入、选段和执行隔离

AVP 原件资源导入与兼容 ingest 是两条接入路径：前者立即建立工程引用；后者用于受控录屏探测、长任务分析、选轨、候选分段和标准化短片准备。不能用旧 `POST /api/recordings` 项目管理流程绕过当前工程入口；兼容路径的既有算法和执行隔离仍用于其合法任务。

ingest 绑定录屏、源修订、策略、Worker 能力和 execution。文件路径从配置 root_id/相对路径解析，拒绝目录、越界、链接/junction、设备/未允许路径及正在变化的输入。Worker 打开时再核对，不只信任登记时的字符串检查。

探测保存真实流、视频/音频起点、time_base、时长、尺寸及音轨。游戏声音轨由用户确认，不默认混合所有录音轨。选段支持边界编辑、手动拆分、相邻合并、移除及选择修订；不跨未选间隙合并，至少一帧，并校验数量/总时长。输出 CFR 补帧长度不能越过原选段的源窗口，显示和往返保留精度。

执行协议 2、ingester `vac-ingester/3`、本地实例注册表 schema 2 的隔离机制包含：

- 每次领取固定新的 execution_id、runtime_instance、generation 和资源键；进度、续租、失败、提交和状态查询都检验原 scope，同 Agent 的旧进程也不能写新执行。
- Windows 内核资源锁负责互斥，owner JSON 只诊断；新执行先处理 replace/reject，再等待旧 owned 进程排空和锁释放。不能按 PID 或进程名误杀其他会话。
- Windows 子进程先挂入 Job Object 再执行，Worker 崩溃时终止所属子孙；取消、租约到期和停止确认分别有有界退出/报告机制，不能靠 TTL 假定媒体进程已经退出。
- 复制按完整块、扫描按完成块、准备按完整短片恢复。半个编码单元重做；核对源标记、块/文件哈希、策略和版本，不用块哈希冒充全文件 SHA。
- sealed 成果只在相同受控输入身份下接管，生成新执行回执，旧目录和 receipt 不修改。提交应答丢失先查询 committed/stop 状态，不重复产生成果或延长失效租约。

## 6. 脚本文件、工作台和特殊语法

`.avs` 保存 format/schema_version、ID、title/body、segments、bindings、TTS/字幕/联网查证设置，并可含来源与修订记录。绑定含资源描述、resource_id、unresolved 和关联段索引。没有绑定直接导入；已有绑定允许映射到当前资源、本地文件或“仅脚本”。仅脚本保留待关联描述与段落位置，可编辑，生成或渲染前解决实际依赖。

正文普通文字表示创作要求，实际旁白在段落中保存，两者不能混为“已生成文稿”。空行分段，普通换行仍属同段。编辑时按旧段内容匹配及位置保留旁白、素材和声音；插入段、改变强制视频后仍检查绑定。草稿可不完整，但定稿前验证语法、澄清项、视频/时间窗和实际旁白。

| 语法 | 意义与约束 |
|---|---|
| `{@视频名称}` | 从当前工程目录精确选择；重名使用插入菜单给出的稳定 ID 名称，不接收任意磁盘路径 |
| `{"字幕文字"}` | 强制字幕，优先于全局自动字幕开关 |
| `{"字幕文字", 字号:24px, 字体:"Microsoft YaHei",}` | 字号/字体可选、顺序不限、允许一个尾逗号；字幕字符串使用 JSON 转义 |
| `{黑屏}` / `{白屏}` | 本段入口和前段出口的对应色淡变，每侧最长 0.175 秒且受短段三分之一限制 |
| `{交叉溶解}` | 与前段重叠，最长约 0.35 秒，受相邻段长三分之一限制并对齐 30 fps；重叠缩短总长 |

每段最多一个视频、字幕和效果块；普通文字花括号用 `\{` / `\}`。不支持嵌套表达式、未知效果或重复参数；语法错误必须显示并阻止不合法操作。字号 1～512px，以 1280×720 为基准，缺省 36px；指定字体必须存在于实际字体目录，不自动下载或静默替换。

正文上限 64 KiB、100 段；当前脚本成片支持 1～20 段，每段 0.1～120 秒。时间窗受运行媒体快照和真实源时长约束。资源页入出点是工程预览标记，不自动裁剪转录或运行媒体目录。显式语法优先于自由生成，冲突要报错或澄清。

工作台保存、生成、否决、定稿、声音回写均有脚本/工作台修订 CAS；迟到生成结果不能盖新稿。同一脚本生成/导出互斥，停止取消请求及所属进程。实际生成复用 Python 内容适配；允许查证时只发送有界文字查询并记录真实 HTTPS 来源，检索失败不标“已核实”。媒体证据不等于完整观看所有视频。

## 10. 时间线、MP4 与文件发布

### 10.1 Go 管理的多序列编辑器

正式模型在 `project/timeline.go`，事务在 `service/project_timeline.go`，HTTP 在 `api/timeline.go`。一个工程包含多个独立 Sequence，每条记录稳定 ID、修订、画布、FPS `{num,den}`、sample_rate、轨道、标记、对照组和撤销历史。默认三视频轨及三音频轨，首个视频决定画布和帧率，此前已有帧位置按原 FPS 换算；未配置时 1080p/30fps/48kHz。UI 以不丢帧时码显示，实际秒数始终用有理帧率计算。

Track 保存 kind、顺序、height、locked/hidden/muted/solo、gain_db 与 group_id。Clip 保存 resource_id、真实 FFprobe 全局 stream_index、source_in/out `{value,scale}`、at/duration 整数帧、speed、link_id、effects 及 origin。视频多音轨逐条入轨，轨道不足自动扩展；源音频保留采样尺度，源视频保留时间基，切分后的实例与链接组获得新 ID。片段操作和素材引用不能使用“第几个匹配名称”定位。

所有命令携带 session、expected_revision、idempotency_key、label、operations。一次导入、多音轨展开、分割或成片入轨是整体事务：克隆工作副本、核对 CAS、执行、检查类型/锁定/源范围和模型、同步绑定脚本文字与元数据，再发布新修订。任一失败不暴露部分编辑。人工和 Agent 共用该引擎，Agent 来源在 origin 与历史中记录；Agent 不可调用人工撤销重做。

| 命令 | 行为 |
|---|---|
| sequence.rename / scope.set | 改名或选择原轨组、单个 Agent 组、全部轨道 |
| track.add/update/remove | 增删、重排、轨高及锁定/隐藏/静音/独奏；锁定阻止内容修改 |
| clip.insert / clip.paste | 覆盖目标区间；插入模式先分割跨点内容、整体移位，同步跟随标记 |
| clip.move / clip.trim / clip.split | 稳定实例定位、移动/边缘修剪/剃刀；默认扩展音画链接选择 |
| clip.update / clip.link / clip.unlink | 恒定变速、音量、淡变、位置/缩放/裁切及字幕参数，链接或分离 |
| clip.delete | 普通移除；mode=ripple 删除所选区间并按轨组移动后续内容，锁定或非所选交叠冲突整体失败 |
| gap.insert | 插入空隙并移动跟随标记；字幕文件插入只整体移动一次 |
| gap.close | 闭合轨道组内的空段，后续片段与未锁定标记按波纹删除同一套规则左移 |

效果范围以片段相对帧 from_frame/to_frame 保存，在轨道上显示淡入淡出/溶解和参数标签。恒定变速由 setpts 与 atempo 链实现，音频保持音调；音量、淡入淡出、位置/缩放/裁切、黑白场淡变、相邻片段交叉溶解和字幕走同一合成器。交叉溶解要求真实源尾部，不能凭空延帧；SRT/ASS/VTT 转成有时码的字幕片段，交叠字幕放入独立字幕轨。ASS 入轨保留正文/时间，统一使用可编辑叠加样式，原 ASS 的任意内联动画和样式不等于原生时间线效果。

### 10.2 标记和 AVS v2 绑定

素材标记保存 source_time，始终指向相同源画面。目录为每个使用实例生成候选，包含 resource_id、sequence_id、clip_id、所属素材/序列和当前帧，移动、修剪或变速重新解析该实例。时间线标记保存自己的 frame，普通片段移动不改变它；波纹插入/删除默认移动，locked 则固定绝对时码。单点是合法一帧锚点，不要求配套出点；入/出点用于范围。备注就是识别名。

每次 `{@识别名}` 保存 occurrence ID、kind、target_id、必要归属和 UTF-16 start/end。允许同类和跨类重名；补全显示类型、所属对象和时码，手写歧义必须选择。Go、工作台、Skill 及 Python 以解析后的 typed references 处理，点引用不会伪装成视频名或零时长片段。改名按绑定 ID 倒序修改对应 token 并重算后续偏移，不替换同名正文、字幕字面量或其他对象。删除、修剪移出范围或丢失实例保留引用并报失效；外部原 AVS 仅显式导出写入。

工作台存在未保存正文时，目录更新仅合并仍绑定同一对象的识别名，保留普通正文和其他重名对象。原 occurrence ID 不变，并按 UTF-16 重算偏移；对象不在目录时保留引用而不重绑。保存时 Go 再规范已绑定的当前名称，前端草稿不是第二个权威解析器。

### 10.3 共用合成、缓存和 Skill 结果

`workers/node/timeline-cli/src/sequence.mjs` 为节目预览与序列 MP4 导出共用的合成器。Go 冻结当前工程/序列、内容哈希和有效轨道资源，Node 校验源 SHA，按真实流 trim、速度与采样映射，叠加视频、混音并应用字幕。scope、隐藏、静音和独奏影响真实输出。FFmpeg 生成 MP4 后复核视频/音频/时长与源指纹，缓存 program.mp4、program.json、sequence.json。手动导出原子复制同一已核验 MP4，避免预览/导出各自解释模型。

内容版本忽略文件路径、保存、名称、备注、标记显示名及轨高/锁定等纯 UI 状态，包含实际素材哈希、剪辑、速度、效果和轨道范围。渲染期间工程或内容改变，旧结果不能作为当前节目；资源缺失/变化阻止预览和导出。波形按源哈希/实际音轨流缓存，缩略图按源哈希/源时间缓存，均不调用服务商。

**轨道分界与音量谱（0.2.2 之后，agent/timeline-audio-viz）。** 时间线按“视频/字幕轨在上、音频轨在下”排列，两组之间插入 6px 分界带（背景色 `--vac-hairline` #3A3A3A，横跨轨头与轨道区，无阴影/渐变）。分界带是独立行，随轨道增删、轨高调整和滚动自动保持位置，仅在上下两组都存在时出现。音频片段内绘制音量谱（TL-14）：Node Worker 用 FFmpeg 流式解码 8 kHz PCM（不下混，保留原声道），按桶取各声道最大峰值与功率均值 RMS，以 dBFS 字节编码并按源哈希/流/版本（loudness-v2）缓存；显示范围 -60～0 dBFS，低于 -60 视作静音、高于 0 钳为满格；计算中的 409 由前端退避重试，错误态每 30 s 重新请求；前端构建 2× 金字塔并按缩放选层，只绘制可视切片，叠加片段与轨道增益，RMS 用 #E6E6E6、峰值用 #9A9A9A、接近 0 dBFS 用红色细线提示。1 小时 AAC 立体声样本实测计算约 2.5 s、RSS 约 90 MB（本机 Linux）。片段内的淡入淡出和局部效果范围不改变音量谱，旧的 `waveform` 接口（TL-11）保留兼容但时间线已不再调用。音量谱底对齐（自底部向上画柱）；削波提示在顶部。

**增益橡皮筋。** 音频片段上叠加 2px 强调色 `#4C8DFF` 增益线：垂直位置为不对称映射（顶 +12 dB、中线 0 dB、底 −24 dB）。可选 `effects.gain_keyframes: [{t,db}]`（t∈[0,1] 相对片段时长）；缺省或空时等同恒定 `gain_db`。选择工具下可上下拖动整条线、双击加点、拖手柄改时间/增益、Alt 点击删点；提交走 `clip.update` 以便撤销。属性面板改「音量 dB」会清空关键帧并写回恒定增益。音量谱只用恒定的片段 `gain_db` + 轨道 `gain_db` 做整体缩放（不跟关键帧包络弯折），以免看起来像增益线在“跟着波形走”；蓝色增益线是独立的手动包络编辑器。导出/预览在 Node 合成器里用 ffmpeg `volume` 表达式跟随关键帧包络，恒定 `gain_db` 路径保持不变。

**编辑页抛光（Premiere 向）。** 监视器区收紧标题/控制条高度，预览固定在上方，仅时间线模块内部滚动（多轨不会把预览顶出视口）。工具栏「吸附/插入」改为按压态按钮（去掉低价值 Checkbox 提示）。原「审查」编辑分区已移除：`#/editing/review` 重定向到时间线，流程阶段「审查」亦跳入时间线节目监视；Skill 任务与编辑历史迁入右侧 Premiere 式折叠条（属性 / Skill / 历史），折叠时只保留模块名竖条。

**视频条起点缩略图。** 视频片段模仿 Premiere：仅在条起点展示一张源入点（`source_in`）缩略图，高度铺满标题下方的片段体、宽度按图像固有宽高比计算（`object-fit: contain`，不裁切拉伸）；短片段用 `max-width:100%` 限制溢出。不再沿片段铺胶片条。仍走 TL-12 `thumbnail?at=`，按源哈希/源时间缓存。

完整 Skill 仍经定稿/渲染/检查流程。成功且哈希通过的 MP4 自动作为工程资源和并行 Agent 视频/音轨组加入发起任务时的 sequence_id，在帧零对齐，默认单独预览该组。组来源保存 run、artifact、SHA、plan_version，通知重放不重复入轨；imported_results 在撤销快照之外持久保存，重开不自动恢复用户已撤销的入轨。人工可从工程全部序列的历史运行显式加入当前序列。完整 MP4 是完整片段，不猜内部切点。

结构化 Agent 命令直接改变真实片段，并在轨道呈紫色和来源文字；不另叠一份猜测剪辑。无扁平计划时 run.finish 携带 sequence_revision/content_version，核验最后编辑的同版合成并登记 MP4。它记录机器完成，人工观感仍独立验收。画面内容生成仅定义 FrameAnchor/请求/结果，默认关闭并返回 501，不创建任务或调用服务商。嵌套序列和远程发布未纳入本轮。

### 10.4 兼容 EDL 与交付包

timeline-cli 读取 EDL，按整数帧排序并规范视频、游戏声、人声、字幕和音乐轨；探测实际媒体并检查源窗口、帧率、音频采样与对齐。主交付包括 edit.xml、timeline.otio、48 kHz 音轨 WAV、SRT、媒体及 manifest。当前目标为 premiere，FCPXML 未接入。

脚本共享渲染器生成 1280×720、30 fps 画面，将强制字幕、黑白淡变/溶解及声音效果渲染进媒体；Premiere XML 引用同哈希画面。它不等于 Premiere 原生可调效果。脚本包还包含 script.json、narration.txt、knowledge-sources.json、script-delivery.json 和 IMPORT.txt；清单以脚本/修订/规格/逐文件大小与哈希关联站内预览和下载。

Node 先在同盘 staging 生成，完整后原子发布到新目录。已有输出永不覆盖，包括悬空链接目标也视为存在。恢复须核对同一完整身份、固定输入、工具/规格和文件摘要；发布后登记结果未知保留文件并查询状态，不将未知传输结果直接当业务失败或重渲染覆盖。各链只保留其明确、有界的重命名/登记重试，不扩展为无证据的通用重试。

文件必须位于受控根下，逐层检查常规文件、重解析点/真实路径、大小写别名、清单、size 和 SHA。Go 独立重探媒体并复核源指纹、版本、当前性、治理和执行身份，不能相信 Worker 自报 passed。用户下载/Range 只读取已登记引用；原导出包、旧修订和历史成片不可变。

## 11. 独立 MP4 预览协议

协议源码为 [contracts.d.ts](../contracts/mp4-preview/v1/contracts.d.ts)、[固定预设](../contracts/mp4-preview/v1/presets/mp4-720p-v1.json)、[独立输入样本](../contracts/mp4-preview/v1/fixtures/input.json)。preview 是绑定成功导出 run/revision/package 的独立任务，不能由通用 create_task 制造孤立任务。

输入冻结 EDL、源视频、最终音轨、SRT/ASS、size/SHA 和 preset 快照。atom 以 `ASCII(UTF8字节数)+":"+UTF8内容` 编码再 SHA-256，小写 hex；固定文件按 UTF-8 路径字节序排列，尝试 preview/task ID 不参与媒体输入身份。精确次序由共享协议和独立 golden 约束，不能为让测试通过直接改 expected hash。

`mp4-720p-v1` 为 H.264/yuv420p、AAC 48 kHz 双声道，最大 1280×720，contain/黑色间隙，不放大小素材，帧率沿项目。小素材输出可低于 720p，这与脚本渲染固定画布不同。

schema 1 使用原 SRT；指定 subtitle_variant_id 后冻结同 run/revision、成功且未失效的 ASS、style/font 身份，进入 schema 2，按扩展协议追加指纹，原 v1 字节规则不变。Worker 需有对应 ASS/字体能力，不读取可变样式草稿代替冻结输入。

创建请求固定 expected_version/revision_id/request_id。相同请求重试返回原绑定，换输入必须冲突；同输入活动任务可复用，但每个请求绑定持久保存。成功后的新请求是新尝试，不能用旧幂等键假装新任务。

输出 final.mp4、render-report.json、preview-receipt.json、preview-manifest.json，manifest 不散列自身。报告必须完整含 source_fingerprint、timeline_frames、audio_alignment、subtitles、media_streams 五项，唯一且通过。Go 独立 ffprobe 核对编码、尺寸、帧率、帧数、时长及实际音频呈现区间；无字幕也要给相应检查结论。

音频区间由 start_pts/duration_ts/time_base 换算，容差 `max(1024/sample_rate,1/fps)+1/sample_rate`，不能用 AAC 裸解码样本数强求相等。过滤图写受控 staging 文件，限 8 MiB；按 FFmpeg 版本选择图文件选项，剩余参数也有 Windows 长度检查。探测 stdout/stderr 和进度残行均有有界采集与停止链。

Worker 取消/失约时停止子进程并等 close；scope 包括 task/runtime_instance/execution/generation。registration_pending 不表示可以覆盖输出。前端自动节目源只取成功、当前、未失效且匹配 asset/run/revision 的预览；同上下文刷新保留有效播放，切换立即卸载旧源。

## 12. ASS 派生与样式编辑协议

ASS 是独立 delivery_variant Task，新建派生包，原导出/审批/预览不被覆盖。正式类型和算法见 [contracts.ts](../contracts/delivery-variant/v1/contracts.ts)、[style.mjs](../contracts/delivery-variant/v1/style.mjs) 及同目录规格/fixture。

`ass-basic-v1` 为固定样式；`ass-basic-v2` 支持全局 style、cue overrides、时间和淡入淡出。草稿 GET/PUT 绑定 revision_id/expected_draft_version 和源 SRT SHA，旧草稿冲突 409；创建 v2 再携 draft_version/style_sha256。spec_sha256 始终标固定协议原始字节，不是用户 style hash。

style 身份使用排序对象键、保留数组顺序、字面 Unicode/HTML、无末尾换行的 canonical JSON；overrides 是数组而非 null，可选缺省字段省略。ass-style.json 写相同字节。outline/shadow 至多两位小数；cue ID 为源 SRT 的 1-based 序号，正文不由样式编辑改变。

v1 输入 atom 顺序：域 `vac.delivery-variant.input.v1`、schema `1`；asset/run/revision/parent_package；edl_sha256/parent_manifest_sha256/format/spec_id/spec_sha256；文件数；按 UTF-8 路径序排列的 kind/path/sha256/size。尝试/task/request ID 不参与输入指纹。v2 在原 atom 后追加 `ass-basic-v2` 和 style_sha256。

冻结来源要求恰好一个已声明 SRT，允许空 SRT，UTF-8 元数据/字幕有 1 MiB 上限。原 SRT 连同 BOM/CRLF 逐字节保留。v1 默认 1280×720、微软雅黑 36、白字黑描边 2/阴影 1、底中、左右 64/下 36、WrapStyle 0。

ASS 时间按毫秒到百分秒 half-up 量化，误差至多 5 ms；折叠时长、控制字符、错误序号/时间及越出冻结视频拒绝。确定性断行预算为 56 单位：可见标量 2、Tab 4、组合重音/变体选择符/ZWJ 0，保留原手动换行，每 cue 最多 8 行，不截断内容。

换行转 `\N`，花括号转义；字面反斜杠后加 U+2060 防止组成 ASS 控制序列，原 SRT 仍供精确文本交换。这个策略有 FFmpeg/libass 工程证据，其他渲染器和复杂文字仍需实际观感验收。

派生包复制冻结父文件，增加 subtitles.ass、ass-style.json、variant-report/receipt/manifest。Go 根据原 SRT 和冻结 style 独立重建 ASS 比对实际字节，并检查 source_fingerprint、subtitle_text、subtitle_timing、ass_style、self_contained、转换器版本、当前修订、治理与租约。重算假报告和哈希不能绕过内容校验。

exporter 心跳声明 delivery_variant_capability protocol 1、匹配 spec SHA，v2 还提供实际字体族/文件摘要；30 秒到期，不以 MP4 能力代替 ASS 能力。字体目录只展示族和哈希，不泄露任意绝对路径，不自动下载/嵌入字体。ZIP 从登记文件流式构建，历史派生可读不代表当前结果。

## 13. 局部编辑、历史节点与操作日志

SkillRun 工作台返回当前 plan、成片与源素材双时间轴、预览和历史游标。修改请求绑定 run expected_version、plan_version、artifact ID/SHA 和 prompt，三选一：segment_index、at_seconds 或对齐完整片段边界的 timeline_start/end。时间点位于溶解区可选择两个片段，不能把成片时间当源时间或静默扩大区间。

Go 持久化 edit_request 的 base_plan 和选择窗口。Agent 只能改变被选片段，保留段数、全局正文/字幕及其他片段/声音；新建议仍需重新定稿、渲染和检查。历史预览明确标历史，不作为新编辑的当前授权对象。

0021 的 vac_edit_checkpoints 保存不可覆盖快照图，vac_edit_cursors 保存游标/重做栈；计划、声音、帧、摘要和交付等内容变化建节点，纯计数不建。undo 回父节点，redo 取栈顶；撤销后新编辑清栈，但旧分支文件不删除。恢复分配新 run/plan 版本，清除旧定稿/检查，不恢复权限、Provider 许可、外部请求或预算，也不重新调用模型/TTS。

vac_agent_journal 为连续序号和前项摘要链，记录主体、操作、脱敏请求与结果。工具先记尝试，再执行并追加结果；日志不可用则停止新的工具动作，异常退出允许仅有请求记录，不伪造完成。数据库触发器禁止改删，人工只能分页查看/核验/追加注释。Agent/MCP 不读取操作日志、步骤历史或检查点；项目日志按当前工程过滤，全局链核验仍由窗口操作。

首次取得工程会话时即从 workspace 恢复资源选择。播放头和缩放以会话及序列为归属：尚无本地修改时直接读取工程保存值，只有显式编辑才建立本地覆盖，不用恢复 effect 与默认零值缓存互相同步。这样媒体装载前首帧界面已显示正确位置，刷新不产生虚假未保存状态。节目载入元数据后定位播放头，忽略无元数据及正在 seek 的时间事件，防止旧媒体生命周期污染位置；工程切换后不复用前一会话的本地位置。

保活页面不等于保活媒体加载：资源页与编辑器源监视器仅在激活时挂载媒体及读取文本，隐藏时暂停并取消自己的代理请求，避免两个页面竞争同一源文件的代理生成锁。请求引用在 React 状态刷新前即可拦住重复错误事件，不通过放宽 Go 锁或重复重试掩盖冲突；备注及脚本草稿仍保留。

### 14.1 设置与跨工作区体验

## 18. 无感统一绘制框架（2026-10-26）

本节记录0.3.1工作副本中基于8974cdc实现的统一绘制架构。默认一个画布、图层集和播放头，HTML/GSAP、React及公共图层在同一帧完成后提交像素。程序版本保持0.3.1，本轮代码未提交或推送；实际自动/原生/人工证据按[测试说明](../scripts/TESTING.md)分别记录。

### 18.1 用户目标与默认行为

只提供一个“绘制”入口、一个画布、一条构图时间轴和一套属性编辑器。普通界面取消HyperFrames/Remotion必选切换，默认“自动协同”。用户表达用途、画面、素材和节奏；Agent拆解场景/图层并选择实现，用户调整的是图层位置、大小、层级、文字、颜色、动画、时间及入出点。引擎名、源文件与强制指定放在高级检查器中，不增加新的确认/授权步骤。

可选的创作用途预设为“界面演示”“数据讲解”“素材包装”，用户不选择也可直接生成。预设影响构图和分工倾向，不等同强制引擎。自动策略优先复用当前场景、项目素材和既有组件；只在有明确收益时组合两个引擎。已经确定的计划随工程保存，重复打开或相同修改不反复切换策略。默认用户得到合成结果及一句创作说明，而不是两份引擎任务或一组技术选项。

### 18.2 从video-use继承的策略与扩展

当前仓库的video-use/upstream/SKILL.md在Animations章节按动画slot选择工具：HTML/CSS/GSAP、界面演示和动态排版倾向HyperFrames；React组件、既有React品牌模板与组件化表达倾向Remotion，允许混合。上游按实际动画需要选工具，并没有要求所有场景默认Remotion。VAC保留这些原则，将选择粒度从已渲片段提升为同一场景中的图层/组件。

| 画面任务 | 默认倾向 | 协同方式 |
|---|---|---|
| HTML界面、CSS布局、DOM/SVG与GSAP动效 | HyperFrames | 输出同画布中的可寻帧图层 |
| 既有React模板、可复用组件和React表达更简单的数据图形 | Remotion | 与HTML图层共享素材、变量、主题和时间映射 |
| 含两类内容的场景 | 自动混合 | 同一帧完成双方绘制后再提交最终像素 |
| 简单静态图片、文字、几何及通用变换 | 公共图层能力 | 避免为简单操作强制启动双引擎 |

Agent负责创作与分工，Go中的确定性规划器负责验证能力、依赖、预算和执行计划，不引入另一个自主决策的后端模型。计划记录节点、选用引擎、理由、能力、依赖、固定运行时及帧计算量。无已验证替代路径的能力显式失败；不静默换引擎。修改只影响对应子图，不能为修一个局部效果重写未选内容。现有三个绘制Skill继续保留为内部专项能力，vac-draw-pipeline成为统一默认入口；video-use按目标主动进入统一管线，避免用户选择技能或引擎。

### 18.3 所有权、文档与编译关系

Go仍是工程、编辑命令、修订、预算、运行和依赖的依据；Node执行编译、帧调度与渲染；Tauri提供窗口集成。统一状态关系为：用户目标 → Agent提出DrawDocument → Go校验并冻结RenderPlan → 双引擎适配器按帧执行 → 共享合成与帧输出。预览、最终导出和编辑时间线使用同一份冻结计划及时间映射。

DrawDocument schema_version=1，包含canvas（尺寸/有理fps/色彩约定）、duration_frames、sources、scene/node定义及实例、asset_bindings、变量/主题、时间锚点和策略记录。所有定义与实例均用稳定ID；同一来源可多次实例化而不共享实例位置。节点类型涵盖source（HTML/React）、image、text、shape、group、mask，保留原始HTML/TSX，不把两种源码强行翻译成一种语言。Graph是有向无环图，复用通过引用表达；循环依赖必须拒绝。

公共节点实例具有from/duration/source_offset、speed（有理数）、transform、opacity、crop/mask、z-order、变量与可编辑参数。通用空间/时间属性由统一模型负责；源码内部动画保留在来源中，明确属性作用域，不让源码和公共关键帧隐式争写同一属性。图片与DNG/ARW沿用ProjectResource及现有显影版本，原件不动；素材路径由Go解析，Agent只引用资源ID和实例ID。后续视频/音频节点使用现有受控媒体/PTS链路，不让两套引擎各自解释音轨时码。

正式保存格式为AVP 3，避免旧版读取后忽略混合图层而覆盖丢失；AVP 1/2只读兼容，旧单引擎构图映射成单节点场景，打开不写原文件，手动保存/另存为才写新格式。内部DrawDocument有独立schema版本。完整源代码、图层、引用和参数保存在AVP，编译产物/帧缓存不作为工程内容依据；清理缓存后仍能恢复。AVS不为本次引擎协作额外升级，继续沿用现有已绑定素材/标记的语法与ID；绘制专用引用类型若另行扩展需独立契约。

### 18.4 单一帧时钟与帧完成协议

统一全局时间使用整数帧和有理帧率。每个实例有明确的全局帧到局部时间映射，区间采用[from, from+duration)，速度和偏移不能通过浮点秒反复累计。子构图默认继承父fps；旧工程不同fps须使用确定的有理映射。音频继续使用采样精度。

VAC的受控FrameAdapter协议：init(snapshot)、update(parameters/revision)、seek(frameRequest)、ready(frameRequest)、dispose。请求携带project/session、document_revision（草稿内容签名）、content_version、request_id、global_frame及局部时间；响应只有匹配同一快照/请求/帧才可提交。拖动预览时合并过时请求并丢弃晚到响应，导出逐帧等待全部活动节点完成，不能用上一帧或空层补成功。

HyperFrames适配器保持其运行时与校验，暂停独立时间线并按请求seek；Remotion适配器使用对应局部帧，暂停独立播放。先完成字体/图片/Canvas等资源准备，再等待该帧所有节点就绪，统一合成、截图或编码。禁止依赖墙上时钟、非固定随机种子及播放回调更新画面；随机种子作为计划输入保存。相同环境、相同快照和帧号必须可前进、后退、随机定位并复现。

混合场景使用Remotion Player作为React帧宿主、受控浏览器作为共享合成宿主、FFmpeg作为最终编码后端，受控HyperFrames节点运行在隔离子文档内，通过框架桥接完成seek/ready，不开放任意外部iframe。完整HyperFrames运行时负责其HTML语义，不能只引入GSAP就视为完整HyperFrames兼容。官方@remotion/gsap可用于兼容的同文档简单动效，但不代替HyperFrames节点。纯HyperFrames/纯Remotion场景保留原生执行优化，框架文档和时钟契约不绑定某一个宿主。

官方HyperFrames FrameAdapter仍是experimental v0；本机CLI 0.8.193没有独立安装@hyperframes/core。因此第一阶段必须先核对该固定版本实际协议、导出和兼容范围。官方文档说明提供实现方向，不构成已安装接口可直接调用的证明。Remotion保持固定4.0.538；如需@remotion/gsap/@remotion/player等依赖，显式锁定兼容版本，不能在运行任务时偷偷安装或升级。

### 18.5 绘制过程中统一预览与透明合成

不能仅隐藏顶部选项而仍要求用户分别渲染两个MP4。新增常驻的受控预览Worker，执行当前源码/图层快照，向VAC返回合成帧与选择范围信息；WebUI/WebView不直接运行Agent源码。参数变化可增量更新，HTML/TSX变化重建受影响节点，画布始终显示所有活动图层的共同结果。点击选择通过稳定节点ID和该帧的命中/几何信息映射回工程模型；首版保证图层级操作，不承诺任意源码内部元素都能自动转换为可视化属性。

预览允许降低分辨率和显示帧率，交互优先于后台精细生成；最终导出按目标尺寸/每一帧完整计算。状态区分编译中、等待资源、正在更新、当前画面和旧缓存，不把过期画面伪装成最新结果。预览与导出共用编译器、帧映射、字体和合成规则；没有实测前不承诺任意4K/复杂场景实时30fps。

内部合成保留RGBA及明确的straight/premultiplied alpha约定、色彩空间、遮罩与混合能力。优先在同一受控浏览器合成完整画面并只做一次最终编码，避免逐图层先压成H.264。必须跨进程时使用无损RGBA帧/PNG序列等中间表示，不能用黑底MP4代替透明前景。独立视频导出支持MP4、WebM alpha和ProRes 4444；桌面使用原生保存对话框，浏览器开发预览提供下载。格式分别缓存并核验哈希、帧数和环境签名；透明像素验证范围见测试说明。

跨子文档的混合模式、滤镜/背景采样等能力必须实测。不能在DOM路径中等价表达的效果只可走已验证的帧合成替代路径；若仍不支持，定位到具体效果/图层，不能静默丢层、把背景烧黑或假定所有CSS特性互通。

### 18.6 与现有编辑器、MCP及运行系统衔接

沿用draw.list/save/check/render/get_frame/import业务入口，新增document/plan契约、draw.capabilities和draw.preview。真实注册、HTTP参数及TypeScript SDK维护于接口文档。旧调用继续支持原生单引擎路径，打开旧构图通过适配层映射为单节点场景。一次场景/图层修改必须带现有工程会话、预期修订及幂等键，整体可撤销；同时编辑冲突不得覆盖人工草稿。

编辑时间线支持绘制源引用：片段绑定draw_document_id及内容版本/快照，通过同一FrameSource协议参与节目预览和最终序列合成，不必先生成一份MP4才能入轨。源图层仍在绘制区完整可编辑，编辑时间线管理的是该画面的片段/范围；两条时间轴不得混作同一模型。冻结与随源更新必须明确，旧历史和交付继续指向原版本，防止源变更悄悄改写已完成运行。现有已渲MP4入轨继续可用。

只修改受影响节点及依赖缓存，缓存键包含源码/参数、依赖图、素材及RAW recipe、字体、引擎/适配器、帧映射、分辨率/色彩/透明设置等。保存/备注改名不使像素失效。Go监管预览与渲染进程树，切换工程或关闭预览时销毁旧上下文；连续预览不能产生一批Remotion Bundle窗口。复用现有Worker职责与MCP工具范围，不引入人工Token、预览授权凭证或重复服务商确认。

### 18.7 默认方案与实施验收

建议默认“自动协同”：例如制作导入图片背景+网站界面动效+React数据卡+动态标题时，资源节点提供原图，HyperFrames处理HTML界面，Remotion复用数据卡组件，统一图层控制标题和布局，用户拖动同一播放头即可看到共同结果。Agent可给出一句“使用界面动效与数据卡组合呈现”的说明，技术分工可在高级信息中展开。相同任务若单引擎更简单，则直接使用单引擎而不影响统一交互。

实施按以下四阶段完成，具体结果见测试说明；不得用历史单引擎通过替代同帧像素证据：

1. 兼容性和同帧样例：使用现有固定样本，建立HTML/GSAP移动物体+React图表+透明前景+导入图片的组合；验证0/中间/末帧以及倒序/随机seek。证明它们在同一请求帧共同生效，无需用户分别导出。
2. 正式模型与运行时：稳定ID图结构、FrameAdapter、帧完成协调、透明/色彩、统一check/render、AVP 1/2兼容与AVP 3往返。先以纯HF、纯Remotion、混合三个场景对照旧输出，不能只测UI按钮隐藏。
3. 绘制界面与Agent策略：常驻预览、图层/属性/命中、默认自动策略、可选用途预设、高级源码与强制指定、局部修改/撤销、过期结果和失败提示。
4. 源构图入轨与收口：共用序列FrameSource、声音/字幕与帧映射、一次最终合成、冻结快照、缓存隔离、取消/退出及文档/Skill/MCP同步。

复用现有Go project/service/MCP、Node draw/sequence与前端绘制/编辑/设置浏览器入口，不为该任务另建平行测试体系。覆盖同帧重复/随机寻帧、异fps/速度/裁切、透明黑白底边缘、字体/原片变化、局部缓存、编译失败、晚到帧、连续快速拖动、项目隔离、MCP与人工并发、缺失引擎和旧AVP。PNG/原始合成帧作为像素依据，预览有损代理不要求与最终H.264逐字节相同。Windows真实Chrome与原生Tauri分别检查；模型创作质量和人工手感不记为工程测试通过。

技术依据（2026-10-26核对）：[video-use动画策略](https://github.com/browser-use/video-use/blob/main/SKILL.md#animations-when-requested)、[HyperFrames帧适配器](https://hyperframes.heygen.com/concepts/frame-adapters)、[HyperFrames帧捕获](https://hyperframes.heygen.com/packages/engine)、[Remotion GSAP桥接](https://www.remotion.dev/docs/gsap)、[Remotion iframe时钟约束](https://www.remotion.dev/docs/iframe)、[Remotion透明输出](https://www.remotion.dev/docs/transparent-videos)。这些资料支持设计可行性方向，混合兼容性和性能仍须按首阶段实测。

### 18.8 实现位置与公开边界

- `control-plane/internal/project/draw_document.go`定义便携模型、DAG验证和确定性计划，`draw_time.go`使用整数有理映射。`contracts/draw-time.mjs`供浏览器和Node共用；组内时间采用父组局部帧，源帧使用其自身有理fps。
- `service/project_draw.go`负责会话、工程及构图双重修订、幂等、正式保存、独立导出和源入轨；`draw_dependencies.go`绑定图片指纹和RAW显影配方。冻结源不会被工作构图/RAW参数更新改写；清除显影缓存后可按冻结配方重建。
- `draw_preview.go`管理常驻Node JSON行协议、资源准备/编译/更新进度SSE、45秒请求时限、空闲退出和工程切换销毁。WebUI合并连续定位，只保留一个在途请求及最新目标，旧像素明确标为旧画面。
- Node `unified-draw.mjs`协调原生HF 0.8.193 `__player.renderSeek(...,{exact:true})`、Remotion 4.0.538及字体/图片就绪；`unified-scene.jsx`处理图层、透明遮罩与几何命中。RGBA PNG既供预览，也供序列FrameSource与最终一次编码。
- `DrawWorkspace.tsx`提供用途预设、目标入口、图层/素材、位置尺寸/旋转/透明度/范围/速度/裁切/关键帧、手势撤销重做。高级区保留源码、引擎覆盖、组件参数、源跟随和输出格式。`workspace.draw_states[composition_id]`保存播放头、选中节点、面板及导出格式。
- 首版仅支持sRGB/straight alpha、矩形/椭圆遮罩及线性位置/透明度关键帧。跨子文档backdrop/filter采样没有替代实现，明确不支持；视频/音频继续由编辑轨处理。AI改画面仍返回未实现。动态图作为图片取首帧。预览不承诺任意4K复杂场景实时30fps。
- 源码内部元素不自动变成外部属性；可视化修改以稳定图层实例为单位。暂不提供任意源码元素选择、CSS全特性互通或隐式文件/网络访问。

绘制撤销分为尚未保存的本地手势历史和Go端已提交场景历史。Agent更新未改动草稿时清除旧本地历史，避免用旧快照覆盖新图层；接着可通过人工history接口整体撤销/重做Agent提交。项目/构图双CAS和幂等重放仍生效，重开会话清空临时历史。React来源按源码哈希单独编译并热替换组件，HTML只更新变化的子文档；不因一个源码变化刷新整个合成宿主。

原生验收：Windows可见Tauri的9项检查通过，包含实际鼠标、原生文件框、当前Agent真实MCP制作/查帧、源入轨/共享终渲、独立导出及AVP3源/播放头保存重开。根Agent已目视检查真实画布与产物，用户人工观感未代签。大图由受控本地HTTP服务提供，帧消息只传短资源地址；HTML隔离子文档的数据URI在浏览器内部生成，避免69MB RAW派生图在DevTools消息内重复传输。MCP可读取最大16MiB帧PNG/JPEG，文本仍限256KiB。
