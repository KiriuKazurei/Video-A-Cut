# VAC 架构与功能详解

更新：2026-10-28。以当前 `agent/vu-skill` 实现为准。本文供人工和 Agent 理解实现与变更影响，不把旧阶段提案写成已有功能。产品定位和沿革见[项目文档](项目文档.md)，未完成事项见[计划文档](计划文档.md)，请求/响应及机器索引见[接口文档](接口文档.md)。

<a id="ownership"></a>
## 1. 状态所有权和调用边界

| 对象 | 权威位置 | 其他形式及约束 |
|---|---|---|
| 已保存工程 | `.avp` 正式文件 | Go 中工作副本可比正式文件新；dirty 表示尚未保存，不能用 SQLite 缓存替代保存 |
| 正在编辑的工程 | Go ProjectWorkspace / SQLite 当前工程投影 | 前端草稿定期 flush；切换和保存前必须收齐编辑器草稿 |
| 全局配置 | SQLite/本地配置/运行环境 | 服务商、预设、凭据引用、Skill 设置不随工程覆盖或写入 AVP |
| 运行和任务 | Go service + SQLite | REST/MCP/Worker/前端不各自建立状态机；Task 状态与运行状态分别归属 |
| 媒体内容 | 原始文件或已登记输出 | SHA/size/源窗口参与内容身份；ID 和真实路径不是同一个概念 |
| 可交付结果 | Go 登记的当前修订、文件清单和摘要 | Worker 产出文件后仍需 Go 独立校验；进程退出 0 不直接发布 |
| 前端状态 | REST 快照 + 页面草稿 | SSE 只令查询失效，不能把事件负载当作完整业务对象 |

Go 的 `main.go` 负责组装配置、SQLite、迁移、事件、service、队列及 HTTP/MCP。handler 处理传输、解码和错误映射，规则放在 service，事务与持久化放在 store，媒体校验和 Skill 类型有独立包。MCP 不持有另一份项目事实。

可见窗口操作直接采用人工身份；无解锁 Cookie/Token、窗口会话倒计时、隐藏撤权或媒体票据。MCP 采用 Agent 身份及工具名单，Worker 采用内部 Bearer、角色、租约及执行 scope。客户端名称是审计元数据，不是赋予人工权限的凭据。应用身份不会扩展 Windows 操作系统权限。

## 3. AVP 工作副本、保存和切换

### 3.1 文档组织

`.avp` 是 UTF-8 JSON，`format="avp"`，当前写入 `schema_version=2`。读取兼容 1/2；版本 1 的原始 EDL 放入 legacy_sequences，没有正式序列时补建空主序列，保留资源、脚本和输出。打开仅升级 Go 工作副本，手动保存/另存为才写新版文件。保存工程身份、resources、完整 scripts、sequences、settings、workspace、允许的 runtime 投影及 file_references。稳定 ID 关联资源、脚本、运行和时间线；完整文件结构以 Go `AvpDocument` 为准，不能丢弃 runtime 或输出引用。

资源 source 记录 relative_path、original_path、SHA-256、size_bytes、modified_ns。先尝试相对工程位置解析，再回到原始位置；素材丢失不删除编辑关系。保存不会把原始媒体嵌入文件。导入 `.avs` 后工程保存自己的脚本副本，原文件独立。

`runtime` 是版本化白名单投影，不是任意数据库 dump。恢复前校验允许表、字段、关系及快照；替换当前工程记录时保留全局配置、服务商、预设与日志。外部成片引用在 file_references 中保留受控映射，允许清空运行缓存后重开工程并找回仍存在的输出；缺失输出明确显示，不伪造成片。

### 3.2 修改、保存和恢复

普通修改先写工作副本并增加会话 revision/dirty。资源编辑历史和运行计划历史有不同作用域。手动保存会同步所有注册编辑器，再将完整 JSON 写入同目录临时文件，flush/close 后用平台原子替换正式文件。Windows 使用对应替换原语；失败保留原件和 dirty，不将最近项目索引失败误报为正式保存失败。

另存为创建独立 project ID，之后两工程修改互不影响；原始媒体继续引用。文件正式路径、资源显示名、备注及布局变化不等同于媒体内容变化。

Go 每 30 秒为有修改工程更新一份本地恢复副本；前端每 15 秒 flush 尚未提交的界面草稿。恢复副本不是正式文件的静默覆盖。首页列出恢复入口和最近项目，默认最近保留 10 项。重启将未完成执行停止到安全/待恢复状态，不自动重放模型或付费步骤。

### 3.3 打开/关闭与运行排空

```mermaid
flowchart LR
  A[选择目标工程] --> B[先校验目标文件和投影]
  B --> C[处理当前 dirty 和活动任务]
  C --> D[确认停止并等待旧请求及 Worker 退出]
  D --> E[保存或放弃当前修改]
  E --> F[事务恢复目标工程投影]
  F --> G[更新 Session 并重建前端]
```

`expected_session` 和 `X-VAC-Project-Session` 用于拒绝过期工作副本请求，不是人工授权凭证。取消、校验/保存失败或排空失败均留在当前工程。工程切换期间拒绝旧业务请求，取消旧请求上下文，等待 Worker 退出/空闲确认，停止播放器，取消查询并清除工程缓存，再按 Session 重建工作区。

资源列表、直接 ID、脚本素材选择、运行/交付读取、SSE 和 MCP 均核对当前工程。没有打开工程时返回空列表或相应不可用状态，不能从历史全局缓存泄漏其他工程。

## 4. 六类资源和依赖管理

| 类型 | 当前识别格式 | 预览/编辑 |
|---|---|---|
| 视频 | MP4/MKV/MOV/AVI/WebM/M4V/MPEG/MPG/TS | 源视频优先；必要时本地 FFmpeg 代理，逐帧、速度、音量、入出点 |
| 音频 | WAV/MP3/M4A/AAC/FLAC/OGG/Opus/WMA | 源音频或代理，播放/定位/速度/音量 |
| 图片 | PNG/JPEG/WebP/GIF/BMP/TIFF | 图片缩放；无法直接显示时代理，TIFF 路径有实际验证 |
| 字幕 | SRT/ASS/VTT | 文本内容预览；ASS 样式编辑属于交付模块的版本化功能 |
| 文稿 | TXT/Markdown | UTF-8 文本预览和工程备注 |
| 脚本 | `.avs` | 正文预览；双击进入工作台，显式关联及导出 |

左栏只列当前工程已导入资源，搜索/筛选不改变工程内容。中栏只保留预览、操作台、备注；右栏显示文件名、位置、大小、格式、时长、尺寸、帧率、编码和音轨等元信息，并支持宽度调整。

导入原件保持外部磁盘引用。生成结果在运行/交付页管理，不自动灌入资源栏。移除只改变工程引用，不删除原文件；被脚本/运行时间线引用的资源保留 missing/removed 占位和稳定 ID，允许重新定位。

指纹用于判断依赖的实际内容/窗口变化。project_dependencies 按脚本绑定和时间线识别受影响结果；无关资源、显示标题和备注不使成片失效。源文件变化或有效绑定/脚本/时间线变化才影响相关运行和交付。重新定位及撤销定位要同步 EDL，不只改 UI 路径。

## 5. 录屏导入、选段和执行隔离

AVP 原件资源导入与兼容 ingest 是两条接入路径：前者立即建立工程引用；后者用于受控录屏探测、长任务分析、选轨、候选分段和标准化短片准备。不能用旧 `POST /api/recordings` 项目管理流程绕过当前工程入口；兼容路径的既有算法和执行隔离仍用于其合法任务。

ingest 绑定录屏、源修订、策略、Worker 能力和 execution。文件路径从配置 root_id/相对路径解析，拒绝目录、越界、链接/junction、设备/未允许路径及正在变化的输入。Worker 打开时再核对，不只信任登记时的字符串检查。

探测保存真实流、视频/音频起点、time_base、时长、尺寸及音轨。游戏声音轨由用户确认，不默认混合所有录音轨。选段支持边界编辑、手动拆分、相邻合并、移除及选择修订；不跨未选间隙合并，至少一帧，并校验数量/总时长。输出 CFR 补帧长度不能越过原选段的源窗口，显示和往返保留精度。

执行协议 2、ingester `vac-ingester/3`、本地实例注册表 schema 2 的隔离机制包含：

- 每次领取固定新的 execution_id、runtime_instance、generation 和资源键；进度、续租、失败、提交和状态查询都检验原 scope，同 Agent 的旧进程也不能写新执行。
- Windows 内核资源锁负责互斥，owner JSON 只诊断；新执行先处理 replace/reject，再等待旧 owned 进程排空和锁释放。不能按 PID 或进程名误杀其他会话。
- Windows 子进程先挂入 Job Object 再执行，Worker 崩溃时终止所属子孙；取消、租约到期和停止确认分别有有界退出/报告机制，不能靠 TTL 假定媒体进程已经退出。
- 复制按完整块、扫描按完成块、准备按完整短片恢复。半个编码单元重做；核对源标记、块/文件哈希、策略和版本，不用块哈希冒充全文件 SHA。
- sealed 成果只在相同受控输入身份下接管，生成新执行回执，旧目录和 receipt 不修改。提交应答丢失先查询 committed/stop 状态，不重复产生成果或延长失效租约。

<a id="scripts"></a>
## 6. 脚本文件、工作台和特殊语法

`.avs` 保存 format/schema_version、ID、title/body、segments、bindings、TTS/字幕/联网查证设置，并可含来源与修订记录。绑定含资源描述、resource_id、unresolved 和关联段索引。没有绑定直接导入；已有绑定允许映射到当前资源、本地文件或“仅脚本”。仅脚本保留待关联描述与段落位置，可编辑，生成或渲染前解决实际依赖。

正文普通文字表示创作要求，实际旁白在段落中保存，两者不能混为“已生成文稿”。空行分段，普通换行仍属同段。编辑时按旧段内容匹配及位置保留旁白、素材和声音；插入段、改变强制视频后仍检查绑定。草稿可不完整，但定稿前验证语法、澄清项、视频/时间窗和实际旁白。

| 语法 | 意义与约束 |
|---|---|
| `{@视频名称}` | 从当前工程目录精确选择；重名使用插入菜单给出的稳定 ID 名称，不接收任意磁盘路径 |
| `{"字幕文字"}` | 强制字幕，优先于全局自动字幕开关 |
| `{"字幕文字", 字号:24px, 字体:"Microsoft YaHei",}` | 字号/字体可选、顺序不限、允许一个尾逗号；字幕字符串使用 JSON 转义 |
| `{黑屏}` / `{白屏}` | 本段入口和前段出口的对应色淡变，每侧最长 0.175 秒且受短段三分之一限制 |
| `{交叉溶解}` | 与前段重叠，最长约 0.35 秒，受相邻段长三分之一限制并对齐 30 fps；重叠缩短总长 |

每段最多一个视频、字幕和效果块；普通文字花括号用 `\{` / `\}`。不支持嵌套表达式、未知效果或重复参数；语法错误必须显示并阻止不合法操作。字号 1～512px，以 1280×720 为基准，缺省 36px；指定字体必须存在于实际字体目录，不自动下载或静默替换。

正文上限 64 KiB、100 段；当前脚本成片支持 1～20 段，每段 0.1～120 秒。时间窗受运行媒体快照和真实源时长约束。资源页入出点是工程预览标记，不自动裁剪转录或运行媒体目录。显式语法优先于自由生成，冲突要报错或澄清。

工作台保存、生成、否决、定稿、声音回写均有脚本/工作台修订 CAS；迟到生成结果不能盖新稿。同一脚本生成/导出互斥，停止取消请求及所属进程。实际生成复用 Python 内容适配；允许查证时只发送有界文字查询并记录真实 HTTPS 来源，检索失败不标“已核实”。媒体证据不等于完整观看所有视频。

## 7. Skill 注册、双 Agent 和运行预算

内置包为 video-use `0.1.0-vac.5`、vac-visual-summary `1.2.1` 和 vac-script-syntax `2.0.1`；多轨版工具包含序列读取/编辑及带类型的引用解析，AVS v2 保存稳定绑定并继续读取 v1。本地说明包导入要求 SKILL.md/skill.json，注册 id、version、runtime、输入/输出、流程/执行方式、tools、permissions、资源和摘要；不执行安装脚本。内置不可卸载，全局禁用不能被项目反向开启。上游 video-use 固定在 commit `43cfc566833548093455c9d4a46bd69913b7e552`，保留原件及 MIT 许可；VAC adapter 单独定义工具边界。

Agent 解释说明，Harness 不把 Markdown 编译为固定任务程序。run 固定工程、flow、execution_mode、Skill 版本/内容摘要、媒体/脚本上下文、预设版本、目标、预算和幂等身份。包升版不改写在途快照。当前工程所有导入资源供 Agent 使用，旧逐项可见确认不再是新流程前置。

| 入口 | 执行与恢复 |
|---|---|
| `external_mcp` | Agent 通过本机 Streamable HTTP 读取 Skill、资源、上下文并 claim/run/tool；自动会话隔离 owner，未提供人工定稿/历史/日志操作 |
| `builtin_api` | Go 调所选 narration/vision Provider，将同一工具结果回传模型；循环运行到结束、人工门、预算或错误 |

设置→Agent 与 Skill 的 McpConnectionPanel 订阅 DesktopRuntime 共享上下文，仅读取 ready 状态的实时 mcp_url。地址和 JSON/Codex TOML 配置通过原生 clipboard_write_text 命令复制，失败显示反馈；session 或地址变化丢弃旧反馈/配置。浏览器预览不推导假地址，不生成 Token。Codex URL 配置依据[官方 MCP 配置说明](https://developers.openai.com/learn/docs-mcp)。

外部 MCP 默认仅直连回环，拒绝浏览器 Origin、不合法 Host、代理转发及连接身份变更。`clientInfo.name/version` 和来源写日志。自动 `Mcp-Session-Id` 由 SDK 管理，闲置 30 分钟和 256 会话上限属于 MCP 连接管理，与已移除的窗口人工会话无关。

run 状态 queued/running/waiting_human/succeeded/failed/cancelled；暂停原因包括 plan_confirmation、frame_budget_exceeded、tool_failed、context_changed、runtime_restarted、agent_clarification。计划/声音改变增加修订、清除旧定稿及检查，需按工具要求重新定稿。失败/取消不发布本步骤半成品。

预算默认 24 步、900 活跃秒、24 源帧，硬顶 64/3600/48，检查成片另有 48 帧上限。模型与工具调用先登记并计步，等待人工不计活跃时长；人工局部修改/定稿/明确恢复建立新的有界窗口，累计消耗不倒退。普通重试和撤销不退费、不重置消耗。VAC 不能精确计量外部 Agent 自带模型费用。

轻量流程要求可用词级转录。转录预设支持本地 `faster_whisper` 和显式配置的 ElevenLabs；本地配置固定模型绝对目录、可选 Python、设备/精度/语言/线程。Go 对必要模型文件流式计算指纹，模型、媒体和冻结预设共同确定缓存；识别后重核模型指纹，变化不发布缓存。Python 只用 local_files_only 读取指定模型，启用离线环境，既有 FFmpeg 输出单声道 16kHz PCM 后直接转 NumPy 样本，避免 PyAV 版本差异。词时标加源窗口偏移并校验，成功通过临时文件原子发布；取消沿既有进程树回收，不自动下载、外发、云回退或设备回退。环境探测只检查文件/指纹和导入依赖，不加载模型或推理。画面流程没有 ASR 前置，通过连续变化默认三抽一及静态覆盖抽帧，摘要每个时间项引用同源帧证据，不允许编造。

### 10.1 Go 管理的多序列编辑器

正式模型在 `project/timeline.go`，事务在 `service/project_timeline.go`，HTTP 在 `api/timeline.go`。一个工程包含多个独立 Sequence，每条记录稳定 ID、修订、画布、FPS `{num,den}`、sample_rate、轨道、标记、对照组和撤销历史。默认三视频轨及三音频轨，首个视频决定画布和帧率，此前已有帧位置按原 FPS 换算；未配置时 1080p/30fps/48kHz。UI 以不丢帧时码显示，实际秒数始终用有理帧率计算。

Track 保存 kind、顺序、height、locked/hidden/muted/solo、gain_db 与 group_id。Clip 保存 resource_id、真实 FFprobe 全局 stream_index、source_in/out `{value,scale}`、at/duration 整数帧、speed、link_id、effects 及 origin。视频多音轨逐条入轨，轨道不足自动扩展；源音频保留采样尺度，源视频保留时间基，切分后的实例与链接组获得新 ID。片段操作和素材引用不能使用“第几个匹配名称”定位。

所有命令携带 session、expected_revision、idempotency_key、label、operations。一次导入、多音轨展开、分割或成片入轨是整体事务：克隆工作副本、核对 CAS、执行、检查类型/锁定/源范围和模型、同步绑定脚本文字与元数据，再发布新修订。任一失败不暴露部分编辑。人工和 Agent 共用该引擎，Agent 来源在 origin 与历史中记录；Agent 不可调用人工撤销重做。

| 命令 | 行为 |
|---|---|
| sequence.rename / scope.set | 改名或选择原轨组、单个 Agent 组、全部轨道 |
| track.add/update/remove | 增删、重排、轨高及锁定/隐藏/静音/独奏；锁定阻止内容修改 |

效果范围以片段相对帧 from_frame/to_frame 保存，在轨道上显示淡入淡出/溶解和参数标签。恒定变速由 setpts 与 atempo 链实现，音频保持音调；音量、淡入淡出、位置/缩放/裁切、黑白场淡变、相邻片段交叉溶解和字幕走同一合成器。交叉溶解要求真实源尾部，不能凭空延帧；SRT/ASS/VTT 转成有时码的字幕片段，交叠字幕放入独立字幕轨。ASS 入轨保留正文/时间，统一使用可编辑叠加样式，原 ASS 的任意内联动画和样式不等于原生时间线效果。

### 10.2 标记和 AVS v2 绑定

素材标记保存 source_time，始终指向相同源画面。目录为每个使用实例生成候选，包含 resource_id、sequence_id、clip_id、所属素材/序列和当前帧，移动、修剪或变速重新解析该实例。时间线标记保存自己的 frame，普通片段移动不改变它；波纹插入/删除默认移动，locked 则固定绝对时码。单点是合法一帧锚点，不要求配套出点；入/出点用于范围。备注就是识别名。

每次 `{@识别名}` 保存 occurrence ID、kind、target_id、必要归属和 UTF-16 start/end。允许同类和跨类重名；补全显示类型、所属对象和时码，手写歧义必须选择。Go、工作台、Skill 及 Python 以解析后的 typed references 处理，点引用不会伪装成视频名或零时长片段。改名按绑定 ID 倒序修改对应 token 并重算后续偏移，不替换同名正文、字幕字面量或其他对象。删除、修剪移出范围或丢失实例保留引用并报失效；外部原 AVS 仅显式导出写入。

工作台存在未保存正文时，目录更新仅合并仍绑定同一对象的识别名，保留普通正文和其他重名对象。原 occurrence ID 不变，并按 UTF-16 重算偏移；对象不在目录时保留引用而不重绑。保存时 Go 再规范已绑定的当前名称，前端草稿不是第二个权威解析器。

## 11. 独立 MP4 预览协议

协议源码为 [contracts.d.ts](../contracts/mp4-preview/v1/contracts.d.ts)、[固定预设](../contracts/mp4-preview/v1/presets/mp4-720p-v1.json)、[独立输入样本](../contracts/mp4-preview/v1/fixtures/input.json)。preview 是绑定成功导出 run/revision/package 的独立任务，不能由通用 create_task 制造孤立任务。

输入冻结 EDL、源视频、最终音轨、SRT/ASS、size/SHA 和 preset 快照。atom 以 `ASCII(UTF8字节数)+":"+UTF8内容` 编码再 SHA-256，小写 hex；固定文件按 UTF-8 路径字节序排列，尝试 preview/task ID 不参与媒体输入身份。精确次序由共享协议和独立 golden 约束，不能为让测试通过直接改 expected hash。

`mp4-720p-v1` 为 H.264/yuv420p、AAC 48 kHz 双声道，最大 1280×720，contain/黑色间隙，不放大小素材，帧率沿项目。小素材输出可低于 720p，这与脚本渲染固定画布不同。

schema 1 使用原 SRT；指定 subtitle_variant_id 后冻结同 run/revision、成功且未失效的 ASS、style/font 身份，进入 schema 2，按扩展协议追加指纹，原 v1 字节规则不变。Worker 需有对应 ASS/字体能力，不读取可变样式草稿代替冻结输入。

创建请求固定 expected_version/revision_id/request_id。相同请求重试返回原绑定，换输入必须冲突；同输入活动任务可复用，但每个请求绑定持久保存。成功后的新请求是新尝试，不能用旧幂等键假装新任务。

输出 final.mp4、render-report.json、preview-receipt.json、preview-manifest.json，manifest 不散列自身。报告必须完整含 source_fingerprint、timeline_frames、audio_alignment、subtitles、media_streams 五项，唯一且通过。Go 独立 ffprobe 核对编码、尺寸、帧率、帧数、时长及实际音频呈现区间；无字幕也要给相应检查结论。

音频区间由 start_pts/duration_ts/time_base 换算，容差 `max(1024/sample_rate,1/fps)+1/sample_rate`，不能用 AAC 裸解码样本数强求相等。过滤图写受控 staging 文件，限 8 MiB；按 FFmpeg 版本选择图文件选项，剩余参数也有 Windows 长度检查。探测 stdout/stderr 和进度残行均有有界采集与停止链。

Worker 取消/失约时停止子进程并等 close；scope 包括 task/runtime_instance/execution/generation。registration_pending 不表示可以覆盖输出。前端自动节目源只取成功、当前、未失效且匹配 asset/run/revision 的预览；同上下文刷新保留有效播放，切换立即卸载旧源。

## 12. ASS 派生与样式编辑协议

ASS 是独立 delivery_variant Task，新建派生包，原导出/审批/预览不被覆盖。正式类型和算法见 [contracts.ts](../contracts/delivery-variant/v1/contracts.ts)、[style.mjs](../contracts/delivery-variant/v1/style.mjs) 及同目录规格/fixture。

`ass-basic-v1` 为固定样式；`ass-basic-v2` 支持全局 style、cue overrides、时间和淡入淡出。草稿 GET/PUT 绑定 revision_id/expected_draft_version 和源 SRT SHA，旧草稿冲突 409；创建 v2 再携 draft_version/style_sha256。spec_sha256 始终标固定协议原始字节，不是用户 style hash。

style 身份使用排序对象键、保留数组顺序、字面 Unicode/HTML、无末尾换行的 canonical JSON；overrides 是数组而非 null，可选缺省字段省略。ass-style.json 写相同字节。outline/shadow 至多两位小数；cue ID 为源 SRT 的 1-based 序号，正文不由样式编辑改变。

v1 输入 atom 顺序：域 `vac.delivery-variant.input.v1`、schema `1`；asset/run/revision/parent_package；edl_sha256/parent_manifest_sha256/format/spec_id/spec_sha256；文件数；按 UTF-8 路径序排列的 kind/path/sha256/size。尝试/task/request ID 不参与输入指纹。v2 在原 atom 后追加 `ass-basic-v2` 和 style_sha256。

冻结来源要求恰好一个已声明 SRT，允许空 SRT，UTF-8 元数据/字幕有 1 MiB 上限。原 SRT 连同 BOM/CRLF 逐字节保留。v1 默认 1280×720、微软雅黑 36、白字黑描边 2/阴影 1、底中、左右 64/下 36、WrapStyle 0。

ASS 时间按毫秒到百分秒 half-up 量化，误差至多 5 ms；折叠时长、控制字符、错误序号/时间及越出冻结视频拒绝。确定性断行预算为 56 单位：可见标量 2、Tab 4、组合重音/变体选择符/ZWJ 0，保留原手动换行，每 cue 最多 8 行，不截断内容。

换行转 `\N`，花括号转义；字面反斜杠后加 U+2060 防止组成 ASS 控制序列，原 SRT 仍供精确文本交换。这个策略有 FFmpeg/libass 工程证据，其他渲染器和复杂文字仍需实际观感验收。

派生包复制冻结父文件，增加 subtitles.ass、ass-style.json、variant-report/receipt/manifest。Go 根据原 SRT 和冻结 style 独立重建 ASS 比对实际字节，并检查 source_fingerprint、subtitle_text、subtitle_timing、ass_style、self_contained、转换器版本、当前修订、治理与租约。重算假报告和哈希不能绕过内容校验。

exporter 心跳声明 delivery_variant_capability protocol 1、匹配 spec SHA，v2 还提供实际字体族/文件摘要；30 秒到期，不以 MP4 能力代替 ASS 能力。字体目录只展示族和哈希，不泄露任意绝对路径，不自动下载/嵌入字体。ZIP 从登记文件流式构建，历史派生可读不代表当前结果。

## 13. 局部编辑、历史节点与操作日志

SkillRun 工作台返回当前 plan、成片与源素材双时间轴、预览和历史游标。修改请求绑定 run expected_version、plan_version、artifact ID/SHA 和 prompt，三选一：segment_index、at_seconds 或对齐完整片段边界的 timeline_start/end。时间点位于溶解区可选择两个片段，不能把成片时间当源时间或静默扩大区间。

Go 持久化 edit_request 的 base_plan 和选择窗口。Agent 只能改变被选片段，保留段数、全局正文/字幕及其他片段/声音；新建议仍需重新定稿、渲染和检查。历史预览明确标历史，不作为新编辑的当前授权对象。

0021 的 vac_edit_checkpoints 保存不可覆盖快照图，vac_edit_cursors 保存游标/重做栈；计划、声音、帧、摘要和交付等内容变化建节点，纯计数不建。undo 回父节点，redo 取栈顶；撤销后新编辑清栈，但旧分支文件不删除。恢复分配新 run/plan 版本，清除旧定稿/检查，不恢复权限、Provider 许可、外部请求或预算，也不重新调用模型/TTS。

vac_agent_journal 为连续序号和前项摘要链，记录主体、操作、脱敏请求与结果。工具先记尝试，再执行并追加结果；日志不可用则停止新的工具动作，异常退出允许仅有请求记录，不伪造完成。数据库触发器禁止改删，人工只能分页查看/核验/追加注释。Agent/MCP 不读取操作日志、步骤历史或检查点；项目日志按当前工程过滤，全局链核验仍由窗口操作。

React Query 使用稳定领域键。GET 快照是对象来源；SSE 事件仅 invalidate 对应域，重连完整刷新，不依赖历史重放。工程切换取消请求/播放器并隔离缓存，旧异步结果不能落到新工程。计划/声音草稿必须记载加载对象 ID 与版本，不能用 refetch 后的新 CAS 携带旧文本覆盖他人修改；执行取消请求独立于长执行 mutation。

编辑菜单按原焦点分派剪切/复制/粘贴和文本撤销；时间线焦点交给同一序列命令，资源/旧运行历史保留各自职责。菜单执行后关闭浮层，不能挡住资源或丢掉原输入框选择。时间线 V/C、Ctrl+K、M、I/O、空格、逐帧和删除键避让输入、补全、菜单、滑块、页签、IME 及可见模态框。原生按钮保留自身空格行为；聚焦片段时空格播放节目。历史 CR03 的场景/解说审批守卫仍用于兼容 WorkflowPanel，不能在统一时间线按 C 时误触发隐藏审批；当前候选的实际回归结果见测试说明。

时间线面板固定在可用工作区内，轨道本身滚动，首次布局和窗口尺寸变化时对准 V1/A1 分界；空轨不把主要音画轨挤到底栏之后。源/节目监视器按可用高度分配空间，窄宽度切换监视器；控件横向溢出只在工具栏内滚动。脚本/Skill/历史面板保留各自滚动和草稿。序列切换仅暂停编辑器播放器并取消旧序列请求，避免移除同 URL 的 src 后无法恢复；工程切换仍由工程 Provider 分离旧媒体和缓存。

首次取得工程会话时即从 workspace 恢复资源选择。播放头和缩放以会话及序列为归属：尚无本地修改时直接读取工程保存值，只有显式编辑才建立本地覆盖，不用恢复 effect 与默认零值缓存互相同步。这样媒体装载前首帧界面已显示正确位置，刷新不产生虚假未保存状态。节目载入元数据后定位播放头，忽略无元数据及正在 seek 的时间事件，防止旧媒体生命周期污染位置；工程切换后不复用前一会话的本地位置。

保活页面不等于保活媒体加载：资源页与编辑器源监视器仅在激活时挂载媒体及读取文本，隐藏时暂停并取消自己的代理请求，避免两个页面竞争同一源文件的代理生成锁。请求引用在 React 状态刷新前即可拦住重复错误事件，不通过放宽 Go 锁或重复重试掩盖冲突；备注及脚本草稿仍保留。

## 16. 桌面生命周期、运行目录和更新

Windows 的资源拖入使用 HTML5 事件，窗口配置 `dragDropEnabled:false`，以免 WebView2 的 Tauri 原生文件拖放处理器拦截前端资源拖动；依据 [Tauri 官方配置](https://v2.tauri.app/reference/config/#windowsconfig)。本机资源导入仍使用已有原生文件框，轨道拖放只接受带当前 project/session 的资源 ID。

Tauri 提供原生能力，业务和媒体仍走 Go REST/SSE/Range，不用 IPC 传帧。启动解析配置和参数，核对资源根/独立业务数据，启动匹配 Go/Worker，监听实际动态端口和状态。runtime.lock、迁移清单、SQLite 一致性和旧会话身份防止共用数据；不能按进程名清空“旧进程”。

原生标题栏与页面背景统一使用 `#1E1E1E`；Windows 通过 DWM 设置标题栏及文字颜色，并保留系统窗口按钮和拖动行为。前端根据当前工程和未保存状态，经 `set_window_title` 同步为 `Video Auto Cut — 工程名 *`；无工程时只显示程序名，浏览器开发预览同步文档标题。菜单右侧不再重复工程名。后台就绪、停止、启动和故障状态统一显示在底部状态栏，Worker 故障的停止操作仍保留；启动/故障恢复页也保留底栏，不再占用顶部单独一行。

官方 single-instance 插件先接收重复启动，再将 `.avp` 路径转入同一打开流程；首次启动参数和文件框统一。`project_open_request` 消费待打开路径。系统文件关联由 Tauri 配置声明，安装后实际关联仍待发行验收。

窗口关闭先 prevent_close 并通知 project-close-requested，前端处理任务/dirty/保存，再 confirm_project_exit 正常排空后台。保存收尾时退出请求排队并去重；取消不退出。托盘可显示/隐藏/退出，隐藏不改变窗口身份。后台故障、重启、更新维护和正常退出有各自状态，ready 只表示相应运行状态，不是作品验收。

默认数据目录、VAC_DESKTOP_CONFIG/VAC_DATA_DIR 及 --desktop-config/--data-dir 的实际路径由配置解析；拒绝不允许的 UNC/重解析边界。只转换合法本机默认路径的 Windows 扩展前缀，不借此放开任意网络路径。停止先发请求、再验证 owned 进程退出和锁释放；退出不是仅改 UI 标志。

更新器流程为检查版本/说明 → 下载并验签 → 用户确认安装 → 有序停止 → 安装替换 → 重启。检查/下载失败及签名拒绝不终止正常业务；安装维护状态禁止冲突重启/退出。版本必须同步 desktop 配置、Cargo/package 及锁文件，使用新版本完整同版包。

更新私钥留在本机受控位置或显式签名环境，工程/前端/日志不保存；Tauri 包签名不是 Windows Authenticode。发布需要安装器、`.sig`、latest.json 配套，只有安装器附件不足以完成应用内更新。公开 Release 状态和当前候选的安装/更新/回退都需要另行实际验证，本文件不以历史本地 0.1.0→0.1.1 记录推定通过。
