## 1. 目的与边界

为已有受控资产选择不可变预设，检查真正执行 Worker 的条件，再启动绑定该版本的七阶段处理流程。Go 管理状态、治理与许可；Worker 通过 MCP 领取任务；WebUI 通过 REST/SSE 拉取快照。

流程：预设保存/历史读取 → 本机工具与鉴权 Worker 能力 → 资产预检 → 原子绑定启动 → 场景及草稿人工停点 → 语音/字幕/混音/导出 → 配置可追溯 ZIP 与验收摘要。

本阶段沿用受控交付包输入。不提供任意原始长录屏的直接导入、自动分段、模型下载或剪辑软件实时遥控。builtin 始终表示模板工程回归；configured 的真实模型内容忠实度、声音与 Premiere 最终体验仍需人工校验。

## 3. 关键行为

预设修订、当前指针、保存回执及业务审计一起提交。读取不仅核对 JSON 哈希，也核对行的 profile_id/revision/schema；revision=0 只是查询当前指针，不能绕过身份核验。

预检返回 expected_asset_version，其算法是资产快照与受控 EDL 哈希的 JSON SHA-256。它是并发标记，不是资产锁、媒体内容完整性签名或人工通过证明。启动在事务内重新计算，旧预检不能绕过锁定、角色变更、EDL 变更或另一活动流程。完整媒体/证据校验继续由固定修订与 Worker/CLI 完成。

预设指纹和去敏 JSON 固定在 run 上；发布 v2 不改变已运行 v1。许可绑定具体版本与指纹，撤销后任务输入、领取与登记阻断；历史记录仍可读取。旧的无绑定流程保持兼容，不伪造预设来源。

能力只能通过鉴权 heartbeat 上报，角色从 token 固定。Python 实际检查本机 FFmpeg、环境变量与 SAPI 声音；Node 检查 Node 与 CLI/适配器路径。缺项或过期阻止新启动，任务输入再核对指纹。能力摘要不是模型健康检查，预检不调用模型、不生成语音；端点可达性与内容质量需要实际任务和人工验收。

两类 Worker 消费 get_task_input 的 processing_profile/profile_sha256。Python 映射采样总预算并选定 SAPI 声音，不自动批准草稿；Node 核对 Premiere 目标。回执中的 profile_sha256 必须与绑定一致。最终 ZIP 包含 processing-profile.json，下载的验收摘要包含 profile_binding。

Windows CLI 发布只针对本次暂存目录的 EPERM/EACCES/EBUSY 做最多 6 次重命名尝试，总等待 1.5 秒；每次先拒绝已存在目标，永久错误仍失败。它不清理或覆盖历史交付。

## 4. 处理预设契约

当前 JSON 示例见 `configs/phase6/profile.builtin.example.json` 与 `profile.configured.example.json`。这是新 Profile 格式，不能直接当作已有 Python Worker 配置文件使用。

| 字段 | 契约 |
|---|---|
| schema_version | 当前为 1；不接受未知版本 |
| profile_id / revision | 64 字符以内的标识及正整数修订；修订发布后不可原地改写 |
| name | 非空可打印名称，最多 100 字符 |
| content_mode | builtin 或 configured；builtin 始终标注工程回归 |
| vision / narration | builtin 时只能是 builtin 且没有外部配置；configured 对应 vision/narration 适配器 |
| endpoint | HTTPS，或明确 loopback 的 HTTP；禁止 URL 用户名密码、查询参数及 fragment |
| model | configured 时必须明确，最多 100 字符 |
| token_env | 凭证环境变量名；不接 token 实际值 |
| sampling.max_frames | 单任务 1–48 帧 |
| sampling.max_bytes | 单任务 1–48 MiB |
| sampling.timeout_seconds | 单任务 1–120 秒 |
| tts_voice | 非空声音名称；结构验证不证明本机安装了该声音 |
| export_target | 本阶段 premiere |

Fingerprint 为验证后的 Go Profile JSON UTF-8 字节 SHA-256。配置变化必须改变指纹；Go 是规范化与计算的唯一入口。客户端不能自行提交指纹当作真实性证明。修订号和名称也包含在当前指纹内；更改规范需升级 schema 并保留旧版本算法。

持久化时预设内容只能由服务端校验和计算后写入。不能接受自动批准旁白、无限预算、明文 token、任意脚本/命令或浏览器提交的生产绝对路径作为预设扩展字段。

外发许可与 endpoint 分开存储。指定地址不等于授权；本地 HTTP 的地址验证也不等于证明该服务已存在。正式适配器需限制重定向/目标地址变化，不能把本地配置经重定向悄悄变为外部服务。

## 5. 对外接口（已实现）

用户已明确授权直接修复并补全，因此此前“等待接口审批”的申请已落地。

| 方法与路径 | 请求/响应 |
|---|---|
| GET /api/processing-profiles | 当前预设列表；limit 1–50，offset 0–100000 |
| POST /api/processing-profiles | {profile, expected_revision, idempotency_key}；新建 expected=0、profile.revision=1；返回保存后的 Profile |
| GET /api/processing-profiles/{id}/revisions/{revision} | 0=当前，正数=固定版；返回 {profile, profile_sha256} |
| POST /api/processing-profiles/{id}/revisions | 同保存请求；路径 ID 必须一致；expected 为当前版，新修订=expected+1 |
| POST/DELETE /api/processing-profiles/{id}/revisions/{revision}/external-consent | 无请求正文；actor 使用现有人类入口；仅适用于非 loopback 服务，绑定服务端读取的具体版本/指纹 |
| POST /api/assets/{id}/prepared-preflight | {profile_id, revision}，revision 必须正数；返回检查项、can_start、expected_asset_version |
| POST /api/assets/{id}/prepared-workflows | {profile_id, revision, expected_asset_version, idempotency_key, revision_id?}；返回 run |
| MCP get_task_input | 增加去敏 processing_profile、profile_sha256，仍限制当前租约持有者 |
| MCP heartbeat | 可选 capability={profile_sha256,tools_ready,credentials_ready,tts_voices}；时间由服务端记录 |
| GET /api/workflows/{run} | 增加 profile_binding={run_id,profile_id,revision,profile_sha256}；无绑定时为 null |

POST /api/assets/{id}/workflow-preflight 保留内联 Profile 诊断兼容性，始终不放行启动。正式操作使用 saved-profile 的 prepared-preflight。REST 沿用同源/loopback、JSON 与现有人类治理规则；MCP 无预设修改、许可或审批工具。

SSE 新增 profile.changed、capability.changed；通知只触发 REST 快照刷新。审查接口在没有场景/解说/证据时返回空数组，前端同时兼容旧空值，避免流程刚启动时崩溃。

## 6. 本地运行

需要已安装 Go、Python、Node、ffmpeg、ffprobe 和所选 SAPI 声音；安装过程不自动下载模型。

```powershell
npm --prefix webui run build
pwsh -NoProfile -File .\scripts\Start-LocalPipeline.ps1
# 配置真实本地服务时，先自行准备符合既有 vision/narration 协议的端点和凭证环境变量
pwsh -NoProfile -File .\scripts\Start-LocalPipeline.ps1 -ProfileFile .\configs\phase6\profile.configured.example.json -Port 8807
```

默认 http://127.0.0.1:8806/。每次创建独立 .run-data/local-pipeline/<id>，启动新控制面与 recognizer/narrator/exporter。输入配置文件必须是 revision=1；它由控制面保存并计算指纹，脚本再生成实际 Worker 配置。MCP token 只在本次进程环境中存在，磁盘保存哈希或变量名。

配置示例的地址只是占位，模型仍由操作者运行。WebUI 保存新版后，当前 Worker 的配置仍固定原版；新版会显示能力不匹配，需要按新版配置部署 Worker。首版启动脚本针对新的本地部署，不热切换正在执行的 Worker、不托管模型。

把受控包放入输出显示的 delivery 目录后，通过“导入交付包”登记，再允许三个角色、选择预设并预检。目录必须相对 delivery_root。Ctrl+C 停止本次进程，日志与数据保留；-RunSeconds 20 可做自动停止检查。已有端口占用会报错，脚本不按通用进程名清理用户软件。
