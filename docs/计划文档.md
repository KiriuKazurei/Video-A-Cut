## 4.1 历史设计：成片两条思路与Agent绘制路线

以下保留最初方案和分阶段落地过程，不作为当前待实现清单。当前双引擎、未渲源码拼合、共享终渲已实现，能力以功能文档和架构§18为准；旧“未接线/HTTP待实施”和人工逐步定稿约束均已被后续实现替代，未完成性能与发行事项仍挂账。

VAC 成片按**两条并列思路**规划，不是主从关系：

| 思路 | 名称 | 要点 | 当前状态 |
|---|---|---|---|
| 一 | 基于已有视频剪辑 | 素材轨 / 脚本与 EDL / FFmpeg 成片 / Premiere·OTIO 精修交接；轻量流程走 video-use 剪辑面，画面流程走 visual summary + 编排 | **现行主线**（已落地与持续打磨） |
| 二 | Agent 直接生成/「绘制」画面 | Agent 主动调用绘制类 Skill，用程序化构图产出视频像素（动效、字幕层、UI 演示、信息图、片头片尾、整段绘制成片等）；可**直出**、**渲后导入编辑**、**未渲拼合预览**，或与剪辑轨**最终一并渲染** | **受控像素生产与渲后编辑已接线；未渲源码拼合及 Gate 后续** |

### video-use 转正（原「附属 overlay」→ 正式策略入口）

和零口径（2026-10-23）：上游 video-use 里原先当作**剪辑附属 overlay** 的 HyperFrames / Remotion / Manim / PIL 绘制能力，现**转正**为：

1. **Agent 可主动调用的 Skill**（内置包 `video-use`，见 [`skills/video-use/`](../skills/video-use/)）
2. **生产视频策略之一**（归思路二；也可在混用场景为思路一主轨提供绘制层）

| 项 | 约定 |
|---|---|
| 命名 | Skill id 仍为 `video-use`（VAC adapter `0.1.0-vac.5`，文案已转正；绘制 tool 未接线）；绘制面在包内以「绘制/构图策略」一等能力描述，不再写成「仅 overlay 附属」 |

### 引擎分工（事实口径，不发明能力）

- **[HyperFrames](https://github.com/heygen-com/hyperframes)**：HTML/CSS + 可寻址动画（如 GSAP）构图；无强制 React/构建步骤；CLI `lint` / `validate` / `render`；适合 Agent 写 HTML、产品 UI 动效、kinetic type、透明 WebM、确定性逐帧捕获。Node.js 22+。

- 选用规则：按构图模型选引擎，不因「偏网页」就默认 Remotion；可与素材轨混用（绘制层 + 剪辑层），混用不改变「两条思路并列」。Phase 1 不执行上述 CLI。

#### 与「少开顶栏分页」的关系（显式例外）

产品偏好仍是：**优先把能力做成现有主界面里的模块**，少开顶栏分页。思路二绘制管线是**明确例外**：构图预览、时间轴、源码/图层、Inspector、Lint/渲染队列与剪辑时间线心智不同，硬塞进「编辑」会挤掉 Premiere 式双监视器工作流。因此新增一个顶栏工作区（id `draw`，标签「绘制」），与现有 `resources` / `editing` / `export` / `tts` / `settings` 并列；**不得**借此再拆一串绘制子顶栏。页内用 Ant Design 分区/侧栏 Tab，不再增加顶栏页。键盘 `6` 打开该页；`1`～`5` 仍是原工作区。

视觉：VAC 灰阶统一暗底、Ant Design 5 实心控件；**禁止** liquid glass / 渐变发光（与现行 webui 规范一致）。

### 风险（立项前必须写清）

- **依赖与运行时**：Node 大版本、Chromium/Puppeteer、本机 GPU/CPU 渲染成本；桌面发行是否捆绑或首次引导安装。
- **渲染成本与预算**：长构图与高帧率会显著占步数与墙钟时间；需单独预算项，不能 silently 占满剪辑预算。
- **人类可编辑性**：渲染后的像素轨可剪时长/位置，但构图参数（字体、关键帧）在 VAC 时间线内默认不可深度回编；要保留构图源文件与版本，否则细调只能重渲。
- **Gate**：落地后另开验收项（引擎版本、样例构图、导入时间线、直出哈希）；当前**不得**记入冲刺完成或 REL 范围。
