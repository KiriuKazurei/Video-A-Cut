## 1. 可直接开始的本地检查

在仓库根目录打开 PowerShell，运行：

```powershell
pwsh -File .\scripts\Start-Phase45Review.ps1
```

默认访问 `http://127.0.0.1:8805/`，选择 `phase5_synthetic`。脚本从最新自动测试成功的数据库创建副本，使用同源已构建 WebUI；前台窗口 Ctrl+C 停止。端口占用可加 `-Port 8806`。它不启动模型 Worker，不对外发送媒体。

这份合成 fixture 用来查看证据图片、草稿表单、七阶段记录、ZIP 下载、宽窄窗布局与验收面板。浏览器编辑/撤销/取消会改变副本状态；没有 Worker 时新任务会等待领取，这是明确状态而不是模型已在运行。需要完整重跑可运行下面工程脚本，然后重新启动预览副本：

```powershell
python .\workers\python\scripts\verify_phase5_workflow.py
```

脚本只用合成画面与本地 mock 内容服务，经真实 HTTP/MCP、Python Worker、Windows 中文 SAPI、FFmpeg、Node 导出跑完整链路并验证导出后修改重跑。mock 验证了真实图片字节/哈希，不代表真实内容识别准确。正常 Windows 用户环境需要有可用中文 SAPI 声音；缺语音引擎或出现 HRESULT 错误应记录失败，不能换成测试音后声称通过。

本轮成功的样包与报告位于 `.run-data/phase5-e2e-*` 的 `report.json`、`delivery.zip`、`delivery/` 和进程日志；最近记录以修复报告中的路径为准。Premiere 导入时优先使用 `delivery/deliveries/phase5_synthetic/<wfexport任务>/edit.xml` 所在原目录；若解压 ZIP 到新位置，按包内 README-RELINK.txt 使用 Link Media 重新链接。该合成包预期 8 秒、30 fps、两个视频片段、分轨音频和独立 SRT；旁白为短中文测试句。

为真实测试使用独立 delivery_root 与数据库，先把所选短片段、EDL 和 manifest 导入为新资产；不要覆盖源录屏或已有生产包。通过现有控制面配置启用 MCP 角色 recognizer/narrator/exporter，凭证按既有 Worker README 配置。视觉 Worker 使用 vision 适配器，解说 Worker 使用 narration 适配器；导出 Worker 使用实际 timeline-cli adapters。内容模式选 configured，模式不匹配（例如默认 builtin Worker）会明确失败。TTS 自动批准保持关闭，通过 WebUI 阅读当前草稿后批准。

## 3. 第四阶段：证据与内容

1. recognize 完成后停在场景审查；核对每张 JPEG 是否来自指定片段，源时间是否正确。查看标签、置信度与模型来源，核对证据引用能打开实际图片。
2. 对照录屏确认标签是否准确。误判记下场景 ID、源时刻、原标签、正确内容及理由；必要时修改标签。顺序编辑按 0 起始的位置移动场景，服务会重新编号全部场景，避免局部 rank 冲突。
3. 确认全部场景，观察 sort/narrate 推进，检查视频与游戏音频同时移动，稳定 scene_id 不因排序变化而变成另一片段。
4. 阅读中文草稿，核对每句是否有对应画面证据、有无编造事件，时间窗是否位于来源片段。需要修改时保存新修订，检查批准失效；只批准屏幕上当前版本。
5. TTS 后试听真实语音；字幕应依据实测语音位置回填。确认人声段音乐压低、语音结束后恢复。不能仅凭波形截图判定音画同步。
6. 下载最终 ZIP，随机挑选场景沿证据索引查到 JPEG，核对图像及哈希与原审查记录一致；检查模型/采样配置来源和批准记录。

## 4. 第五阶段：控制台闭环

1. 查看历史流程与阶段任务，检查当前输入/输出修订、等待原因和失败信息；新流程只能有一个活动实例。
2. 编辑草稿文本或时间，保存新修订。旧修订和旧 ZIP 应保留，当前批准清除；未批准不得开启 TTS。越界时间、无效来源或版本冲突应显示错误。
3. 在已批准但下游未完成时撤销，确认下游任务取消/失效，迟到结果不得登记。重新批准应产生新任务；运行中编辑应明确冲突。
4. 在隔离测试资产上取消流程，观察任务与流程都停止；不要对真实录屏资产为了测试随意取消。失败流程可以重试失败阶段，重试记录保留旧 task_id 与新 task_id。
5. 完成 export 后改稿/改顺序，再确认与批准，观察新一轮导出能运行，旧交付和验收记录仍可查询。
6. 使用事件流“断开/立即重连”，断线期间从另一窗口完成一次操作，重连后 REST 快照应刷新。缩窄到约 375/520/700 像素检查按钮、输入框和图片，操作可用键盘完成。
7. 从选定流程下载对应版本 ZIP，检查不是另一个资产或另一个历史版本。验收面板默认待人工，检查完后才选通过/失败；失败填具体备注。

## 5. Premiere 与最终联合验收

导入本次真实模型链路的新包 edit.xml，并单独导入 subtitles.srt；字幕不会因为 XML 导入而自动出现。核对实际测试片段的时长/帧率、片段顺序/切点、三类音轨、中文旁白/字幕时间、画面动作与原游戏声同步、音乐压低与恢复。

在项目内定位并复查至少一个片段边界、一个语音起止点、一个压低恢复点；对照原录屏和生成包记录时间点。先前“8 秒、60 fps、两段视频、三条音轨通过”是第三阶段的样包记录，不直接套用到本次新的真实模型包。真实包的预期规格应从其 EDL/自动报告读取。

有偏移时记录偏移方向、估计帧数/毫秒、复现位置与包版本；此前允许后期一起校对的轻微偏移列为待修项，不静默消失。没有问题才在最终包版本上填写通过。
