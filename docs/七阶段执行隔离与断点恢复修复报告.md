复验又发现并修复：

- 已导出资产的新录屏导入被通用 exported 冻结规则拦截。仅对受控 ingester 任务开放后续导入，其余任务继续受冻结约束；改音轨、帧率和选段后完整新交付通过。
- 同一有效执行恢复时重复 `begin_execution` 被拒。现支持当前 owner 的合法幂等重放，仍检查租约、治理、资源和 scope；外部实例与撤销执行不放行。
- 同执行中断的 checkpoint 登记：恢复时验证本地 manifest，重发精确原参数并推进序号，不能跳过登记或错报完成。checkpoint 接口没有独立 wire request_id，其幂等依据为 scope/sequence/ref/hash；journal 的本地请求 ID 不冒充协议字段。
- Windows 短暂文件占用：journal 原子替换使用唯一临时文件与有界重试；普通内容阶段发布目录同样重试权限失败，每次先检查租约与已有包，不覆盖历史成果、不重跑内容阶段。永久错误仍可见失败。
- owned 根进程退出后，持有管道的孙进程仍可能存活。Runner 在忘记登记或结束管道读取前排空内核 Job；stdout 写入异常向任务边界传播，避免把写盘失败当成功。
- 进程身份/Job 排空信息不可读取时明确报告清理受阻，关闭 owned Job 仍保证终止约束；已取消后的退出等待使用短暂休眠，避免等待一个已置位的 Event 导致 CPU 空转。
- 版本冲突曾统一显示为资源忙；现在提示重新读取版本。长错误消息在 375 px 卡片越界，已增加断词与最小宽度约束并复验。

## 3. 时限、资源与恢复规则

- MCP 请求超时最多 3 秒；控制轮询间隔 0.5 秒，单次服务端等待有界；在途请求最多 2 个。
- 单操作重试预算 20 秒；退避 0.5/1/2/4/8 秒，带有限抖动；等待可取消。实际预算还受本地授权截止及 15 秒停止余量约束。
- 本地租约依据服务端 `lease_remaining_ms`，扣除 RTT 与安全余量，用单调时钟计算；不靠本机墙钟决定执行权。
- 取消宽限 5 秒，强制退出等待 10 秒；无法确认身份或排空则 `cleanup_blocked`，不能新 begin。ACK 不消耗旧业务租约预算。
- 同一受控资源持有内核锁；锁文件保留，不能通过删除文件解锁。`replace_after_stop` 撤销并排空后交接；`reject_if_busy` 返回 409 且不创建半成品。
- 复制恢复保留旧 part，流式验证并复制完整前缀到新 owned part；坏尾部不被采用。空间预算包含新副本；完整块 ledger 采用 9000 条分片及链摘要，单 manifest ≤1 MiB。
- 扫描以完整块、准备以完整短片续跑；未完成编码单元整体重做。sealed 包有有界文件清单/大小/哈希；只从授权候选恢复，旧目录和 receipt 不改写。
- journal 用临时写入、flush/fsync、原子替换。目录发布暂时拒绝访问最多重试 8 次，总等待 1.4 秒；每次拒绝已有 target、失去租约或永久失败。
