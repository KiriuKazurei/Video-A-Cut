# 全项目统一人工验收计划

更新：2026-10-02。第四至第七阶段非人工工程内容已完成并复验。依据用户决定，人工验收统一集中执行，**正式人工结果仍保持待验**。用户授权尝试 computer use 后，已完成真实 Edge 自动交互；当前没有原生 computer-use 工具，采用隔离 headless Edge + CDP，归为自动工程证据。本计划不新增阶段、不自动批准外部模型传输。

## 开发期间如何推进

- 各阶段分别记录工程完成度与人工验收状态。工程完成可以进入后续开发，人工待验不作为阶段开发的前置阻断。
- 修改后执行相关自动测试、接口/Worker 联调、必要的真实浏览器自动检查；已发现的工程缺陷及时修复，不累积到最终人工验收。
- 维护一份统一待验清单，记录功能、风险、素材、配置、证据和已知限制；旧报告保留，不用自动测试替代人工结论。
- 对未受变更影响且已有通过证据的内容复用历史结果；最终仍用同一候选版本验证贯穿各模块的完整操作链路。

本策略不取消产品内的场景确认、草稿批准等操作，也不启用自动旁白批准。那些停点是工作流功能，需在最终验收中实际操作。

## 何时开始统一验收

主要功能范围已明确并基本实现，能够从约定的输入入口走到最终交付；已知阻断工程缺陷修复，相关自动检查通过；候选版本、实际配置和测试素材可追溯，真实模型服务与凭证由操作者准备。届时再组织一次联合人工验收，不按阶段重复索取确认。

受控媒体包/EDL 与原始录屏入口均已实现，执行隔离/重连/断点恢复缺陷已修复，必验工程证据已补齐，见 [七阶段修复报告](七阶段执行隔离与断点恢复修复报告.md)。已自动覆盖五种动态 UI 状态/四宽度、真实视频播放与 ZIP、阶段故障、最终音画标记同步和改选段完整交付。统一人工验收仍覆盖真实录屏候选合理性、实际模型忠实度、配置/声音一致性和 Premiere 播放，再贯通完整操作；合成通过不等于真实内容已通过。

## 集中执行顺序与覆盖范围

| 顺序 | 操作 | 核对内容 |
|---|---|---|
| 1 | 准备候选版本、素材、模型与声音，启动本地环境 | 配置来源、依赖提示、日志、端口冲突、启动/停止范围；不误连其他服务 |
| 2 | 导入素材并设置资产治理 | 输入可读、媒体/音轨正确、角色可见性与锁定立即生效；新增原始录屏入口按实际范围验证 |
| 3 | 保存/加载预设，检查运行条件并启动 | 固定版本与实际模型/声音一致；缺凭证、缺声音、过期能力、错配配置与外发许可正确阻断 |
| 4 | 识别、检查证据、确认或退回场景并排序 | 真实游戏内容忠实度、取样来源、漏识别/误排序、切点；人工判断与证据一致 |
| 5 | 生成并编辑解说，批准或撤销 | 中文文本忠实度、时间窗、修改版本和审批绑定；撤销停止下游，旧结果不覆盖新版 |
| 6 | 执行语音、字幕、混音及导出 | 实际中文语音、字幕时间、帧率/切点、音画同步、音乐压低和完整分轨 |
| 7 | 预览、试听、下载 ZIP/摘要并导入 Premiere | 来源/版本正确、移动包后可重新链接、XML/SRT 导入正常、可编辑轨道与实际播放一致 |
| 8 | 修改后重跑及异常恢复 | 取消、失败重试、租约回收、Worker 中断、重复请求、发布后未登记恢复；历史包保留、新旧版本不混淆 |
| 9 | 浏览器与本地运行收尾 | 宽窄窗、按钮和键盘操作、事件流断开/重连快照、配置历史、停止后无本次进程遗留 |

第 4/5 阶段专项步骤继续参考 [四五阶段联合人工校验](四五阶段联合人工校验.md)，第 6 阶段契约参考 [六阶段开发文档](六阶段开发文档.md)，第 7 阶段输入与时间映射参照 [七阶段开发文档](七阶段开发文档.md) 第 12 节。1–3 阶段既有人工通过记录保留，最终回归重点放在跨阶段衔接和受后续变化影响的交付行为。

## 结果记录与修复闭环

每项记录候选提交/构建、profile_id/revision/sha256、run/输入与输出修订、素材源时间、实际结果、日志或截图、异常时间点及复验结果。自动检查、人工内容判断、Premiere 播放和运行体验分别保留证据。

发现问题后直接修复，先执行受影响的自动回归，再集中复验对应人工步骤；若涉及时间基准、审批/版本绑定或交付格式，重新走完整交付主路径。所有约定必验项通过且已发现的阻断问题关闭后，才记录正式验收通过；仍未执行或受限的项目明确保留，不批量填写 passed。
